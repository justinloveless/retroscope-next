# UF14 decisions: front-end polish and the one-socket rule

UF14 owns the paths listed in `docs/followups/UF14.md`. Amendments to U31, U32, U33, U35 and UF11 point back here.

## Contracts later units rely on

1. **One socket per tab, always.** `getSocket()` in `screens/app.js` is the only place that calls `createSocket`.
   Every room screen (`poker/index.js`, `retro/index.js`, `team/index.js`) takes the tab's socket as
   `mount(root, boot, {socket})` from the entry, or asks `getSocket()` when it was mounted without one (a guest
   who joins first, a visitor whose boot has no principal). None of them stops the socket on unmount; they
   `leave` their room. The entry starts the socket early on every room route (`ROOM_MODULES`) when the visitor
   has a principal.
   - **Principal change.** `getSocket()` remembers the pid it created the socket with. When `currentMe()` names
     another principal (a guest joined, someone signed in), the old socket is stopped and a new one made, so the
     hello and the outbox carry the right pid. The poker guest form now calls `setMe` with the new principal, as
     the landing page does.
   - `tests/e2e/fake/shell/one-socket.spec.js` walks team → poker → board → team in-app and checks one browser
     WebSocket, one fake connection, one hello, and that the socket is never closed (so no 4409).
2. **`socket.resync()`** (`net/socket.js`) drops the clock samples (`clock.discard()`, new in `core/clock.js`)
   and runs the wake path: a ping when welcomed, an immediate reconnect while waiting (not during a `bye` wait).
   The retro timer calls it on a wall-clock jump instead of dispatching a fake `online` event (amends U35
   decision 4).
3. **`ui/choice.js` replaces native `<select>`.** `createChoice({label, name, options, value, onChange})` is a
   menu button in the kit's `.select` look, with `value`, `update({options, value, disabled})` and `destroy()`.
   Its accessible name is `"<label>: <current option>"`. Every team screen uses it; no `<select>` is created
   anywhere in `web/src` any more. `ui/select.js` (U10) stays, unused, because its unit test
   (`tests/web-unit/core/ui.test.js`) is not UF14's; new code must not render it.
4. **Popovers inside a modal dialog** (`ui/popover.js`) attach to that `<dialog>` instead of `document.body`. A
   modal dialog makes the rest of the document inert, so a menu opened from a dialog (a choice in a form) would
   otherwise be visible but not clickable.
5. **`fake.waitForSubscription(roomKey)`** (`tests/web-fake-server/server.js`): resolves once a live connection
   holds the room. Since the entry's socket says hello before the page joins its room, specs that script a
   room wait for this instead of `waitForConnection()`; a `tx` sent between the two would miss the page.
6. **Root files on the plain fake server.** `server.js` serves `manifest.public` (`/favicon.ico`,
   `/manifest.webmanifest`, `/robots.txt`) with `Cache-Control: public, max-age=86400`, the ETag and 304
   revalidation, and `shell.js` writes the same head links as `Server/Hosting/Shell` (`theme-color`, the
   favicon, the SVG logo, the web manifest), each only when the build ships its file. The demo's own routes for
   the same files are left as they are (`demo/**` is not UF14's) and answer identically.

## Decisions where the spec was silent or did not fit

1. **The WebKit CSP violation in `team/actions.spec.js:159`** was the action-items tab's native `<select>`s. WebKit
   reports `style-src-attr` for every `<select>` it creates (its user-agent shadow tree carries inline styles).
   When the element is created detached, as `updateItem` did on every render, the report targets the
   `document`, so `_team.js`'s filter (which only matched a `SELECT` target) let it through now and then. The
   fix removes the cause: every team `<select>` (action-item filters and assignees, kudos period, invite role
   and expiry, board visibility and template, template column colours) is a `createChoice`, and `_team.js`
   drops its filter, so the harness's CSP check is strict on WebKit again. The audit found no `style`
   attribute or `setAttribute('style', …)` anywhere: `h()` throws on a string style, and every inline style is
   a CSSOM write.
2. **Time zone and locale are pinned per spec, not in `tests/e2e/playwright.config.js`.** That config is U48's
   and not in UF14's paths, and several functional specs compute expected times with the Node process's own
   time zone, which a page pinned to UTC would no longer match. `poker-table/visual.spec.js` uses
   `test.use({timezoneId: 'UTC', locale: 'en-US'})`; the screenshots config pins the same for every shot.
3. **Baselines for both platforms.** The visual baselines were regenerated on macOS arm64 (`-darwin`) and, in
   the official image `mcr.microsoft.com/playwright:v1.64.1-noble@sha256:7852dc5a7d72f5fe458a597d690f6c42fbc8e9e26ddfa95f8e6ef552558d9bbf`
   (linux/arm64), as `-linux`. Fonts differ between operating systems, so one file per platform is the stable
   form; with the time zone pinned, neither depends on the machine any more. The command:

   ```
   docker run --rm --ipc=host -v "$PWD":/work -w /work -e RS_E2E_TARGET=fake <image above> \
     npx playwright test --config tests/e2e/playwright.config.js tests/e2e/fake/poker-table/visual.spec.js \
     --project chromium --update-snapshots
   ```

   In 56 runs in that image one shot differed by 28 pixels (a seat's name label one pixel over), so the
   screenshots allow 40 differing pixels; the glyph change in item 4 alone moved far more. A CI job that runs
   the visual spec should run it in the same image, since a bare runner's fonts are not the image's.
4. **The left Jira panel** stores `{open, width}` under `localStorage['rs.panels'].left`, next to the Round
   panel's `right` (U32 contract 2), replacing U33's top-level `jira` flag. It uses `createResizable` (240–480 px,
   arrow keys by 16 px) with the grip on its right edge, and `submit.js` reuses `history.js`'s
   `readPanels`/`writePanel` instead of its own copy.
5. **Strip glyphs** come from `room.extras['jira.meta'][ticketKey].issueType`. A round without a key, or whose
   metadata has not arrived, shows the neutral glyph labelled "Issue".
6. **The jira-drawer chunk needed no trimming.** Since UF11's measurement (lazy chunks net of what their
   importer loaded, shared chunks reported once), `jira-drawer` measures about 6.0 KB against its 22.5 KB budget.
   Even counted with the editor (6.8 KB) and the shared markup chunk (5.9 KB) it loads, it is about 18.7 KB, so
   the headroom is well over 1 KB. The budget is unchanged.
7. **Retro settings never send a known refusal.** Before sending, the dialog checks what `RetroDecider` would
   refuse and shows the reason instead: not a facilitator, an archived board (both re-checked at Save, because
   either can change while the dialog is open), values out of range (now including control characters in the
   vote emoji), and fields someone else changed since the dialog read them. For the last, the dialog shows the
   fresh values of those fields, keeps the facilitator's other edits and sends nothing, as it already did when
   the change raced the save. A `board_archived` nack gets its own sentence.
8. **`CSS.escape`** is used for every id interpolated into a selector: `focus.js` (two places) and `board.js`
   (the pending-spinner lookup).

## Owner review of the wave 5 cross-unit edits

- `retro/board.js` (78edcec) exposes the board's socket on the feature `ctx` so the team link joins on it. With
  the one-socket rule that socket is always the tab's own; the comment stays accurate.
- `retro/index.js` no longer creates or stops a socket of its own. Until the welcome arrives, `me()` falls back to
  the boot `/api/me` body converted to `welcome.me`'s shape (`{pid, kind, name, avatar}`), so role checks such as
  `isFacilitator` work on the first paint from a boot snapshot. Boots in the old `{pid, kind, name}` shape still
  work.
- `poker/index.js`: the U31 module-level socket (`socketFor`) is gone (contract 1). `submit.js` places its chips
  through `ctx.slots.center`, which U32 added, instead of reaching from the left slot to its parent (U33
  decision 5 asked for that slot).
- `team/index.js`: `ctx.navigate` is `screens/app.js`'s `navigate` (U30's follow-up); the hidden-link click is
  gone.
- `retro.css`: the styles U36 set through the CSSOM because it owned no stylesheet (the celebration card, its
  confetti layer, the kudos drawer's type row) moved into `retro.css`. Only what differs per confetti piece
  (position, colour, shape) is still set in script. U36's follow-up rules were added: done cards
  (`.retro-card-done`), the action-item row, the Jira key badge and the kudos summary.
