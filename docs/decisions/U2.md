# U2 decisions: ids, protocol, room contract, ports, authz contract

U2 owns the shared contract. Later units that need a change here ask U2 (DESIGN §k.1), and the change lands in
`Core/{Ids,Protocol,Room}` and `Core/Authz/{Capability,ResourceFacts,Policy}.cs`. `Core/Authz/PolicyRules.cs`
is a deny-all stub that now belongs to U9.

## Conventions later units must follow

1. **Wire types live in `Core/Protocol` and are registered in `WireJsonContext`.** Each concrete payload has
   exactly one kind in `Catalog.Entries`; a test fails when a `Command`, `WireEvent` or `Unsequenced` type is
   missing from the catalog, and `WireWriter` throws on one. To add a kind, add the record, its
   `[JsonSerializable]` line and its catalog entry, then run
   `dotnet test tests/Retroscope.Core.Tests --filter Category=Protocol` twice: the first run regenerates
   `web/src/net/protocol.gen.js` and `docs/protocol.md` and fails, the second passes. Commit both files.
2. **Required means "no default value".** `WireJsonContext` uses `RespectRequiredConstructorParameters` and
   `RespectNullableAnnotations`, so a record parameter without a default must be present, and a non-nullable
   one must not be null. A parameter that must be present but may be null (`ticketKey|null`, `columnId|null`,
   `cardId|null`, `userId|null`) has no default and `[property: JsonIgnore(Condition = Never)]`, so it is
   written as `null` instead of being dropped. Unknown members, numbers in strings and case-mismatched names
   are refused.
3. **Domain events are not wire events.** Deciders return their own event types (`TEvent` of
   `IRoomDomain`), which the store persists and `Apply` folds. Projections turn them into `WireEvent`s per
   viewer, which is where vote secrecy happens. `PokerCommand`, `RetroCommand` and `TeamCommand` are open
   so domain-internal commands (timers, presence, actor posts) can derive from them in `Core/Poker` etc.
   without entering the catalog.
4. **Ids are typed everywhere**, including `IAccessView` (`RoleIn(TeamId, …)`, `HasCurrentGrant(BoardId, …)`)
   where §c.1 shows `Guid`. Every id type carries `[JsonConverter(typeof(GuidIdConverter<T>))]`, so any
   `JsonSerializerContext` (the Server's HTTP contexts included) writes ids as bare UUID strings and as
   dictionary keys without registering anything.

## Decisions where the spec was silent or did not fit

1. **No generated C# files.** §a describes a generated two-phase parser (`switch (k)`) and
   `IdConverters.g.cs`. A generator would need its own project or a check-in-and-diff step for C#, and buys
   nothing over data: `WireParser` looks the kind up in `Catalog` (a `FrozenDictionary` holding each kind's
   `JsonTypeInfo`), which is the same single source of truth and is AOT-safe. Id converters are one generic
   `GuidIdConverter<T>` closed per id type through a static abstract `IGuidId<T>.From`, which is still "one
   converter per id type" and needs no reflection. `protocol.gen.js` and `docs/protocol.md` are the generated
   artefacts, checked by the CI diff.
2. **Server frames are parsed too.** `WireParser.ParseServer` exists for C# clients (`Retroscope.Sim`, the
   soak tool, integration tests). It uses the same envelope reader; `snap.d` is typed by the room kind of
   `r` and `snap.o` likewise.
3. **`snap` has an `o` member** for the per-viewer overlay (R11: one shared public document per seq plus a
   small overlay). §c.3 shows only `d`. `PokerOverlay` carries the viewer's own votes and `heldByThisTab`;
   `RetroOverlay` carries `mine` cards, comments and votes. Team rooms have no overlay.
4. **Whole-entity update events.** `poker.round.updated`, `retro.column.updated`, `retro.config` and
   `team.action.updated` carry the whole round, column, configuration or item instead of only the changed
   fields. With `WhenWritingNull`, "absent" and "cleared to null" are indistinguishable in a partial update
   (`parentKey:null` in §c.4 would vanish), and the payloads are a few hundred bytes.
5. **`retro.config.update` patch uses `maxVotes: 0` for "unlimited"** for the same reason: a null in a patch
   means "not changing". `RetroConfig.maxVotes` (state, not patch) is omitted when unlimited.
6. **`Decision.Reject` gains `JsonElement? Data`** for the nack's `d` (`stale` carries `{current:…}`,
   `spotlight_held` carries `{holder}`). The shape of `current` is per command and owned by the domain units,
   so it travels as an opaque `JsonElement` (`JsonSerializer.SerializeToElement(value, WireJsonContext…)`
   is AOT-safe). `NackFrame.D` is the same element.
7. **`CommandContext.Viewer` is nullable**: internal transitions (timers, presence, actor posts) have no
   caller. **`IRoomDomain.Timers` returns `TimerRequest<TCommand>(Key, DueAt, Command)`**: the actor needs to
   know what to decide when a timer fires, and the key lets it replace an armed timer.
8. **`Policy.Can` takes a `Principal?`** (null = unauthenticated HTTP caller) with an overload taking
   `Viewer`, because HTTP handlers have no `ClientId`/`ConnectionId`. `ResourceFacts` carries only facts about
   the resource; roles and grants are resolved through `IAccessView` at decide time (R12). The `Capability`
   list is a first cut from §c.4/§c.11; U9 may ask for additions.
9. **Room codes are case-insensitive and never rewritten.** Imported codes include 13-character lower-case
   board codes (`Math.random().toString(36).substring(2,15)`) that can be valid Crockford strings, so
   `RoomCode.TryParse` only checks the shared grammar `[A-Za-z0-9-]{3,64}` and does not map Crockford aliases
   (`O→0`, `I/L→1`). `LookupKey` is the upper-cased code, matching the `upper(code)` indexes in §b. New codes
   are 10 characters from the Crockford alphabet, one random byte per character (256 is a multiple of 32, so
   there is no bias).
10. **Epochs are a typed `Epoch(ulong)`** written as 16 lower-case hex digits, so the browser never sees a
    64-bit number it cannot represent.
11. **Kick codes** beyond §c.3's `access_revoked`: `deleted` (session or board deleted), `not_found` and
    `forbidden` (a `sub` that cannot be served; there is no `q` to nack), `too_many_rooms` (over the 10
    subscriptions per connection limit, §c.7).
12. **Parse errors carry `Room` and `Q` for commands** so the transport can nack `invalid` instead of closing
    the socket when only `k` or `d` is wrong (version skew, a bad payload). `FrameError.TooLarge` maps to 4413
    and the other envelope errors to 4400. Messages name members and kinds, never payload values (S33).
    `CmdFrame.DataHash` is FNV-1a of the raw `d` bytes, for the actor's `(cid, q) → hash` dedupe (§c.7).
13. **`NaturalCompare` follows ICU, not plain ordinal.** §a says "ordinal, digit runs numeric", but the
    original sorted sprints with `localeCompare(…, {numeric:true})`, so the golden bucket vectors (U47) will
    hold ICU's order. Without ICU (InvariantGlobalization) the comparer reproduces it for ASCII: digit runs by
    value with leading zeros ignored, case-insensitive letters, spaces and punctuation (in ICU's order) before
    digits before letters, then lower case before upper case. Non-ASCII letters compare by upper-case code
    point, an approximation (ICU sorts `é` next to `e`). The test table was produced with Node 20's ICU.
14. **`UuidV5` uses SHA-1**, which RFC 9562 fixes for version 5; CA5350 is suppressed at that one call with the
    reason. Reference values come from Python's `uuid.uuid5` (the RFC's DNS example is one of them).

## Verification

- `dotnet test tests/Retroscope.Core.Tests --filter "Category=Protocol|Category=Text"`: 340 tests pass.
  Every catalog kind round-trips through its frame with all members and with only required members, and again
  after its members are shuffled at every depth; snapshots and overlays round-trip in `snap` frames.
- `./build.sh test` is green.
- `./build.sh aot-smoke` passes with zero warnings. The server does not call the protocol yet, so the trimmer
  drops it from that publish. A throwaway AOT console app (not committed) that writes and parses `cmd` and `tx`
  frames, refuses a command missing a required member and runs `NaturalCompare` also published with zero
  warnings and behaved the same as under JIT.
