# UX12 decisions: the rich description editor, phase 6 (the editor UI)

UX10 built the server path (the edit view, `AdfWrite`, `descriptionAdf`) and UX11 the editor's core (pinned
ProseMirror, the `readHTML` rewrite, the schema, ADF conversion, tokens and clipboard). This unit is phase 6, the
first release people see: "Edit description" opens the ProseMirror editor in the issue drawer and the centre issue
view. It also closes the prerequisites the earlier units left open: the client schema's cross-check against
`AdfSchema` (UX11 follow-up 1) and tokens in the web fake (UX10's open item).

The owner's decisions for this phase (2026-10-23): ProseMirror; prefetch the editor chunk when the drawer or the
centre view opens for a user who can edit (`JiraEditIssues`), never for viewers; mention search and image upload
come in later phases (the real-Jira gates G1 to G3 they depend on passed, UX10 decision 5); the emoji picker
is out.

UX12 changes `web/src/rich/` (`commands.js`, `toolbar.js`, `views.js` and `palette.json` are new; `rich-editor.js`
and `schema.js` changed), `web/src/poker/issue-drawer.js`, `web/styles/rich-editor.css`, `web/build.mjs`,
`web/budgets.json`, `web/assets/icons.svg` with `tools/make-sprite.mjs`, one Core record
(`AdfOpaquePart.Label`) and the endpoint that used to compute it, the web fake's Jira, its fixtures and golden,
Core and web unit tests, the fake e2e specs, the real-stack Jira spec, `tools/quick.mjs` and DESIGN §f and §g.

## Prerequisites

1. **The client schema is checked against `AdfSchema`, field for field** (`AdfSchemaWebMirrorTests`, Core,
   `Category=Adf`). UX11 decision 5 chose a cross-check over a generated file, because `adf-schema.json` carries
   data the C# table does not model; this follows it. The test reads `web/src/rich/adf-schema.json` with
   `JsonDocument` and asserts:
   - the nodes are exactly the editable ones plus `rsOpaque` and `rsOpaqueInline`, and the marks the server's plus
     `rsMark`, with the same block flag;
   - each node's and mark's attributes by name (refused ones absent), required flag, type, range, enum values and
     check (colour, status colour, link href, card URL with its schemes, timestamp);
   - for plain and patterned strings, behaviour rather than spelling: over a corpus at every length bound and with
     every ASCII character, the web rule (pattern, code-point length, no control character) accepts exactly what
     `AdfSchema.ValidString` writes;
   - each node's children against its context, less preserve-only types, plus a token where `OpaqueChildren` holds,
     with `Min` and `Max`; the inline flag and node marks; `contextMarks` against `ParagraphMarks` and
     `HeadingMarks`; `codeCombinesWith` against `CodeTextMarks`; the text marks; the stash name and the ref
     pattern against a real `IslandId`.

   Checked with teeth: a widened mention-id pattern and a list item without `rsOpaque` each failed it, naming the
   field. CI's clean-tree step is not needed for a check; a drift fails the test itself.
2. **The web fake serves the real projection** (`tests/web-fake-server/edit-views.gen.json`).
   - RS-12 (the e2e fixture) and DEMO-123 (the demo) gain a paragraph with an unknown attribute (`dataSource`), an
     `inlineExtension` and an `annotation` mark, and an `extension` block. Their markup and islands gain the matching
     read view, which `WebFakeAdfTests` still holds to the server's rendering.
   - `WebFakeAdfTests.The_fake_serves_the_projected_edit_views` writes the golden from `AdfEditProjection` in the
     `protocol.gen.js` style: it regenerates the file and fails when it was stale, so CI's clean-tree step catches a
     projection change. The golden holds the projected ADF, the opaque parts with label and preview, the mark
     tokens, the media table, the limits and every original as the bytes the fixture holds. The test also requires
     that both issues carry exactly an extension, an inline extension, an annotation and one stash, so the fake
     always exercises all four token forms.
   - The label was computed in the endpoint; it moved to Core (`AdfOpaquePart.Label`), so the golden and the server
     cannot name a part differently.
   - The fake serves the golden as the edit view of an issue whose ADF it was generated from (it restores the
     golden's tokens and compares, so a test's own fixture never gets it by accident). On save it restores tokens the
     way `AdfWrite` does: the i-th use of an opaque ref takes the i-th original (one too many is
     `opaque_duplicated`), a mark ref the i-th or the last, a stash fills the members the client did not set, and a
     ref it does not hold answers `stale`. It splices the originals in as text, so `issue.adfText` is the saved
     description and a spec can check the bytes. The next edit view after a save serves the save's own tokenised
     ADF.
   - After a rich save the fake rebuilds the read view from ADF. Its reader now writes tables, panels, layouts,
     expands, task and decision lists, media, statuses, dates, mentions and colour marks in the server's Doc shapes,
     with the server's island rule; a fake self test requires that it reproduces both fixtures' read views exactly.
3. **The palette is the server's** (`web/src/rich/palette.json`). It maps each Jira palette hex to the design token
   `jira.css` themes, as `AdfColor` does, and lists the classic text-colour (20) and highlight (7) pickers in Jira's
   order (adf-inventory §5). `AdfColorWebMirrorTests` compares both maps with `AdfColor`'s, entry for entry. The
   editor and the fake's reader both use it.

## The editor

4. **Opening.** "Edit description" (drawer and centre view, `canEdit` only) loads `GET …/description` and the chunk
   together, then mounts `createRichEditor`. The button reads "Opening the editor…" meanwhile. An edit view with
   `editable: false` falls back to the markup editor with islands (kept until phase 12); a description that has no
   markup form either says it can only be edited in Jira. An edit view the strict reader refuses (`AdfError`) says the
   same in other words instead of opening a broken editor.
5. **Everything is edited in place.** The schema's content expressions already allow text in tables, panels, lists,
   layouts, expands and task and decision items; the node views (`views.js`) draw them with the read view's
   `jira.css` classes (`panel panel-*`, `tasks`/`task`, `decisions`/`decision`, `layout`/`layout-col`, `media`,
   `status-*`, `date-lozenge`, `jira-user`, `smart-card`), so editing looks like reading. Colours, widths, spans and
   column flex go through the CSSOM; palette hexes become `var(--jc-<token>)`, so they follow the theme like the read
   view. An expand's title is an input and its collapse is view state only: the node view tells ProseMirror to ignore the
   class change on its own element, which ProseMirror would otherwise undo by redrawing the expand open. Panels are
   `isolating`, like expands and cells, so Backspace at the start of one never merges it into the block before. A task's box toggles its state. Media
   come through the attachment proxy by the view's media table.
6. **Tokens are read-only and named.** `rsOpaque` is a dashed block with the part's label and "Kept as it is", plus
   its read-only preview when that says more than the label; `rsOpaqueInline` is a dashed chip; `rsMark` is a dotted
   underline. All are `contenteditable=false`. The token guard (UX11) still refuses copies.
7. **The toolbar** (`toolbar.js`) follows Jira's: text styles (a kit menu showing each style at its size), bold,
   italic, "More formatting" (underline, strikethrough, code, clear formatting), text colour and highlight
   (palette popovers with a "Default"/"No highlight" swatch), bullet, numbered and action-item lists with outdent
   and indent, link, insert (quote, code block, divider), undo and redo. It is built from `createButton`,
   `createMenu` and `createPopover`, with no native `<select>`. Buttons keep the editor's selection (no focus on
   press), show `aria-pressed` and disable themselves where the command does not apply. Tools come in groups set
   apart by space, and the toolbar wraps between groups: two rows in the narrow centre card and on an iPhone 13, where tools are
   2 rem wide with 0.25 rem between groups. The arrow keys move between tools. In the centre view the toolbar sticks
   flush to the top of the stage's scroller, and the scroller drops its top fade while the editor is open, so no text
   shows above the stuck toolbar.
8. **Shortcuts as in Jira:** Mod-B/I/U, Mod-Shift-S (strike), Mod-Shift-M (code), Mod-\ (clear), Mod-K and
   Mod-Shift-K (link), Mod-Alt-0…6 (text styles), Mod-Shift-7/8 (lists), Mod-Z, Mod-Shift-Z and Mod-Y, Tab and
   Shift-Tab (cells, list items, tasks, two spaces in code, else paragraph indentation where `contextMarks` allows
   it; past a table's first or last cell Tab stays put, since adding a row is phase 8; elsewhere Tab leaves the
   editor), Enter (splits list items and tasks; an empty task leaves its list or outdents), Shift-Enter (hard break),
   and ArrowUp on the first line of a task or decision, which browsers stop at the item's checkbox or icon, moves to
   the end of the block above. ProseMirror keeps Escape to itself, so Escape in the editor never closes the drawer.
9. **Commands** (`commands.js`) are plain ProseMirror commands shared by the toolbar, the keymap and the tests.
   Tasks follow ADF's shape: a nested task list sits inside the task list after its parent task, and new lists and
   tasks get fresh `localId`s (`crypto.randomUUID`). Links take what someone types: a bare host gets `https://`, an
   address gets `mailto:`, anything that would fail the save's href rule is refused in the popover with a message.
   Only plain text can be renamed from the popover: over text that holds a chip, a token or a line break the "Text to
   display" field is disabled and the link is applied to the text as it is.
10. **The stale-selection race.** A plugin flushes ProseMirror's DOM observer on every keydown, so a key acts where
    the browser's selection is even when `selectionchange` has not been handled yet. `editorPlugins` builds the
    plugin list, and `editor-plugins.test.js` pins the flush first in it and checks that it flushes. The specs still send keys with
    25 ms gaps and wait 80 ms after moving the caret, and focus the editor before setting a selection: ProseMirror
    writes its own selection back into the DOM about 20 ms after a focus, and it reads a caret at the very start of
    the document right after a focus as the browser resetting it.
11. **Saving.** Save compares `canonicalAdf(pmToAdf(doc))` with the loaded view's ADF and, when equal, closes
    without a PATCH. Otherwise it sends `{descriptionAdf, descriptionBase: view.updated}`.
    - `stale` first re-reads the edit view. When its ADF is canonical-equal to the one the draft started from, only
      another field changed (a points submit, the drawer's own edits, someone else's edit in Jira), so the draft moves
      onto the new `updated` and the PATCH is sent once more.
    - A `stale` that remains keeps the draft and shows a banner: the issue changed in Jira after editing started, the changes were
      not saved, the draft is kept. "Reload" asks first ("Discard draft and reload" or "Keep my draft"); only then
      does it load Jira's version.
    - `invalid` shows the code and the path from `fields.descriptionAdf` and `fields["descriptionAdf.at"]`, and
      keeps the draft.
    - Any other error is a toast and keeps the draft.
    - Cancel with changes asks ("Discard" or "Keep editing"); without changes it closes at once.
12. **Prefetch.** When the drawer or the centre view opens an issue for a user with `canEdit`, `loadRichEditor()`
    runs on an idle callback (2 s timeout; a 300 ms timer where `requestIdleCallback` is missing, as in Safari),
    once per page, and is retried after a failure. Viewers never request the chunk, and quick sessions never load
    the drawer at all; specs check both by the requests the fake server saw.
13. **The stylesheet is linked on the poker route** (`ROUTE_STYLES`), not on demand: 1,911 B brotli, and it lets the
    editor paint styled on its first frame. It holds `.rich-*` and ProseMirror's classes, plus two kinds of rule
    outside them: the "Text styles" menu, which the kit mounts outside the editor (`.menu[aria-label="Text styles"]`),
    and the centre view's scroller while the editor is open (`.nt-issue:has(.rich-toolbar)`).
14. **Icons.** The sprite gains 19 Lucide icons from the already pinned `lucide-static` 1.49.0 (bold, italic,
    underline, strikethrough, code, list, list-todo, list-indent-increase and -decrease, baseline, highlighter,
    text-quote, square-code, minus, unlink, redo-2, type, remove-formatting, puzzle). The tarball came from the npm
    registry with `npm pack`, whose integrity check passed; `make-sprite.mjs` refuses any other version.

15. **Unsaved drafts are kept.** When the view moves to another issue or closes with a dirty editor (the drawer's
    Close button, a link to another issue, or someone else's navigation in the centre view: a spotlight move, the next
    round, an unlinked round), the draft is kept in memory with the edit view it started from, and a toast says so.
    The issue's header then shows "Unsaved changes", and "Edit description" reopens the draft with a banner saying it
    is back. Saving goes through the same `descriptionBase` check, so a draft never overwrites a description that
    changed meanwhile. Cancel's "Discard", a save and "Discard draft and reload" drop it. Drafts live for the page
    only and are never stored, like every Jira text.
16. **Jira's autoformat** (`input-rules.js`): `#`…`######`, `>`, `-` or `*`, `1.` and three backticks start their
    blocks as before; `[] ` starts an action item and `---` alone on a line is a divider; `**bold**`, `__bold__`,
    `*italic*`, `_italic_`, `~~strike~~` and `` `code` `` take their mark when the closing character is typed, after a
    space or at the start of a line, so `snake_case` stays as typed. Backspace right after one undoes it.

## Deviations and limits

- **Tables are edited, not restructured.** Text in cells is edited in place; adding or removing rows and columns,
  merging, header toggles, cell colour, the number column and column resizing are phase 8. The editor draws no number
  column.
- **Insert is quote, code block and divider.** Panels, expands, layouts, tables, status, date and the slash menu are
  phase 7; mentions phase 9; images phase 11. Existing ones are edited in place.
- **No subscript, superscript or alignment controls yet.** Existing `subsup` marks and alignment are kept.
- **The toolbar wraps instead of collapsing into "…".** Jira hides overflowing tools; here the groups wrap to a
  second row, which keeps every tool one tap away on a phone.
- **Drafts are kept for the rich editor only.** The markup fallback (`editable: false`) still discards its draft when
  the view moves on, as before; phase 12 removes it.
- **Autoformat covers blocks and the common marks.** Links (`[text](url)`), headings by `h1.` and Jira's wiki
  shorthands are not converted.
- The real-device pass (iOS Safari, Android Chrome) the design asks for before each user-visible phase is still
  owed (open items).
