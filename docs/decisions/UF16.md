# UF16 decisions: realtime and polish follow-ups

Spec: `docs/followups/UF16.md`. Amendments to U45 and U48 point back here.

## Decisions where the spec was silent or did not fit

1. **Where the 08/57 classification lives.** `SqlRoomStore.CommitAsync` now lets a `PostgresException` of SQLSTATE
   class 08 (connection exception) or 57 (operator intervention: `57P01` admin shutdown, `57P02` crash shutdown,
   `57P03` cannot connect now, `57014` query cancelled) propagate unclassified. The actor already treats anything that
   is neither `CommitRejectedException` nor `FencingLostException` as an unknown outcome: it poisons the room, every
   subscriber gets `bye` (1012) and the next message reloads. Nothing new was needed in `RoomActor`. The store is
   where Postgres errors are classified, so the fix sits there and not in `Leader.CommitFencedAsync`. `Leader` (U12)
   still rethrows any `PostgresException` from `COMMIT` as is, and its comment ("rolled back for certain") does not
   hold for these two classes. The store's filter covers both the batch and the `COMMIT`.
2. **The "store fake" for item 1** is the test's `SqlCounterStore` against real Postgres. Its plan can end with
   `do $$ begin raise exception … using errcode = '<state>'; end $$`, so each class reaches the store as a genuine
   `PostgresException` from Npgsql. An in-memory fake would have bypassed the code being fixed.
3. **Card order (item 2).** The bug was on the server. The client already broke ties by id (`byCreated` in
   `retro/model.js`), but `RetroProjection` sorted cards and comments by `CreatedAt` ticks. The wire carries only
   milliseconds, so two posts in the same millisecond could reach a snapshot in tick order while the client sorted
   them by id. The projection now orders by the wire millisecond, then by id. `RetroSort` compares milliseconds too,
   as the client's `sortItems` does. Guid order and the lower-case string order of the ids agree, so both sides tie
   the same way. The golden case is `tests/golden/transcripts/retro-same-millisecond-alice.json` (two cards and two
   comments, each pair in one millisecond, with the earlier tick on the higher id). Before the fix, the C# convergence
   check failed on it.
4. **Timer regressions (item 3).** `ActorTimers.cs` was not changed. Both new tests
   (`RetroPersistenceTests.A_timer_whose_first_fire_lands_early_…` and `…started_before_a_restart_…`) pass with U45's
   fix and fail with the `ActorTimers.cs` of 941c734. They run the real retro binding and store under `EarlyTimers`, a
   test `TimeProvider` (in `ActorHarness.cs`) whose timers fire a thousandth of their delay early. That is how a timer
   on the monotonic clock fires against a wall clock that runs slow. `ActorHarness.Runtime` now takes any
   `TimeProvider`, and `RetroScope.NewRegistry` takes an optional one (U22's test harness, a one-parameter change).
   The tests settle the actor after the command and the load before they advance the clock. Without that, the timer
   could be armed after the advance and never fire early, which is how an early version passed on the old code.
5. **Accessibility (item 6).** The known-issues list in `a11y.spec.js` is gone. The scan fails on any violation.
   - **Colour contrast that was real:** `.btn-green` (`--green` was `#16a34a`, 3.3:1 with white; it is now
     `#15773a`, 5.6:1, and 4.6:1 at the hover mix), `.btn-emerald` (a new `--emerald-strong: #04704f`, 6.1:1;
     `--emerald` stays the accent tint used by the poker strip), inactive tabs (`--muted-foreground` on `--muted`
     is 4.3:1; they now use `--foreground` at 70 %, about 7.5:1), and `.nt-chip-key.is-placeholder` (4.1:1 on the
     current chip's tint, now `--foreground` at 70 %). The real-stack visual baselines and the fake poker-table
     baselines still pass unchanged.
   - **Colour contrast that was not real:** the dark-theme `.btn-primary` findings (contrast 1.2 to 3.1) were caught
     halfway through a `background-color` transition. One case is the spec flipping `data-theme` on the anonymous
     pages. The other is a filter button that just became `btn-primary`. At rest, the dark theme's primary button is
     a light fill with dark ink, well over 4.5:1. The scan now waits two frames and for running `CSSTransition`s
     to finish before it runs axe. It does not wait for other animations, because spinners never finish.
   - **`label-content-name-mismatch`:** axe drops parentheticals before it compares, so "Switch team (Platform)" did
     not contain "Platform". The team switcher is now named `Switch team: <team>`. With no current team it has no
     `aria-label`, so its name is its visible "Teams". The kudos button no longer has an `aria-label`. Its content is
     "Kudos", the count badge and a `.sr-only` " left", so its name is "Kudos 3 left", and that starts with what it
     shows. `tests/e2e/fake/shell/header.spec.js` and `tests/e2e/fake/retro-actions/kudos.spec.js` follow the new
     names.
   - **`aria-prohibited-attr`:** `.retro-presence` is a `role="group"`, which may carry its "N online" label.
6. **The hidden holder (item 5).** The test asserts `bound` (not `bound|mine`) before the page hides, after it shows
   again and 1.5 s later. It records the holder page's `websocket` events from the take onwards and expects none,
   because a reconnected tab is no longer bound. It passes on all four projects without a product change.
7. **Stylesheets outside the listed paths.** UF16 lists `web/src/{core,screens,team,poker,retro}/**` for
   accessibility fixes, but colour contrast lives in `web/styles/{tokens,kit,neotro}.css`. §k gives each stylesheet
   to the unit that owns the matching `web/src` folder (U10 core with tokens/base/kit, U31 poker with neotro). The
   edits are the minimum the contrast fixes need, in one `fix(web)` commit.
8. **DESIGN's `ui/` line** names `choice.js` where it named `select.js`, because UF14 replaced the one with the
   other and UF15 deleted `select.js`. U48's base-URL note is corrected by an amendment in `docs/decisions/U48.md`
   (that file is append-only for this unit).

## Linux baselines for `tests/e2e/real/**` (item 4)

The real-stack specs seed people with `psql` through `docker compose exec`, so the test runner has to stay on the
host, next to the stack. Only the browser runs in the pinned Playwright image
(`mcr.microsoft.com/playwright:v1.64.1-noble@sha256:7852dc5a7d72f5fe458a597d690f6c42fbc8e9e26ddfa95f8e6ef552558d9bbf`),
as a `playwright run-server`. The host's runner connects to it with `exposeNetwork: '<loopback>'`, so the browser
reaches the stack's `localhost` ports through the runner. That needs neither host networking nor the Docker socket
in the container. The runner's platform is `darwin`, so a throwaway config spreads `tests/e2e/playwright.config.js`
and pins `-linux` in `snapshotPathTemplate`:

```
docker run -d --rm --name pw-server --init --ipc=host -p 127.0.0.1:48699:3000 --user pwuser -w /home/pwuser \
  <image above> npx -y playwright@1.64.1 run-server --port 3000 --host 0.0.0.0
# linux.config.mjs: { ...base, testDir: <repo>/tests/e2e,
#   snapshotPathTemplate: '<repo>/tests/e2e/{testFileDir}/{testFileName}-snapshots/{arg}{-projectName}-linux{ext}',
#   use: { ...base.use, connectOptions: { wsEndpoint: 'ws://127.0.0.1:48699/', exposeNetwork: '<loopback>' } } }
RS_E2E_TARGET=compose RS_E2E_BASE_URL=https://localhost:$RS_TEST_HTTPS_PORT npx playwright test \
  --config linux.config.mjs tests/e2e/real/visual.spec.js --project chromium --update-snapshots=missing
```

The 20 `-linux` files were written once, then passed 24 of 24 with `--repeat-each 3` against the same image.

## Endorsement order (verifier's note on item 2)

`RetroProjection` sorts endorsements by `CreatedAt`, then id, unchanged. That is already the wire order:
`EndorsementInfo.CreatedAt` is the `long` the decider sets from `context.Now.ToUnixTimeMilliseconds()`, so it
carries no ticks to disagree with the client's `byCreated`. The same-millisecond golden now runs on a team board
and adds two endorsements in one millisecond, the earlier on the higher id, to pin that.
