# U10 decisions: web core, UI kit and the completed build

## Contracts later units rely on

1. **`manifest.json` shape** (read by U11 `StaticAssets`/`Shell`). U0's `entry` and `routes` (route pattern → JS files for `modulepreload`, each with its static imports) are unchanged. Added:
   - `css`: stylesheets every page links (the kit bundle `kit-<hash>.css`).
   - `routeCss`: route pattern → that route's own stylesheets (for example `neotro-<hash>.css` on poker routes), linked by the shell after `css`.
   - `styles`: every built stylesheet, file name → public URL.
   - `assets`: `web/assets/**` logical name → content-hashed URL under `/assets/static/`.
   - `files`: every served file (public path) → `{size, etag, br, gz}`. `br`/`gz` are the byte sizes of the `.br`/`.gz` siblings, or `null` when there is none. `etag` is a quoted strong ETag of the raw bytes. This is the list `StaticAssets` loads into its `FrozenDictionary`.
2. **Precompression** covers text types only (`.js .css .json .svg .html .txt .map .webmanifest`), and a sibling is written only when it is smaller than the original. PNG, WOFF2 and MP3 are already compressed; a `.br` of them would be larger, and `StaticAssets` would then serve more bytes. §g.7 says "every file"; this is the smallest reading that does not make responses worse.
3. **`csp.json`** is `{scriptHashes: ["sha256-…"], themeScript: "<minified script>"}`. The shell must inline `themeScript` byte for byte (the hash covers exactly that text) and place it **after** the `<script type="application/json" id="boot">` element, because the script reads `theme` from the boot JSON first, then `localStorage['rs.theme']`, then `prefers-color-scheme`. The boot JSON's top-level `theme` field is the user's preference (`light|dark|system`). The script source is `web/src/core/theme-boot.js`; `core/theme.js` applies later changes and must resolve the same way (a test runs both).
4. **`<html data-theme>` always holds the resolved value** (`light` or `dark`), never `system`. `tokens.css` keys the palette on it, with a `prefers-color-scheme` fallback for `:root:not([data-theme])`.
5. **Stylesheets are esbuild entry points, never imported from scripts.** esbuild folds CSS imported from a lazy chunk into the *entry's* CSS bundle, which would put `neotro.css` and `retro.css` on every page and into the `css` budget. So `build.mjs` builds every `web/styles/*.css` except the partials `tokens.css` and `base.css` (which `kit.css` `@import`s) as its own entry, before the JS pass, and fails the build if a script imports a stylesheet. `ROUTE_STYLES` in `build.mjs` maps a route module to its stylesheets (`poker/index.js` → `neotro.css`, `retro/index.js` → `retro.css`, `team/index.js` → `team.css`; a missing file is skipped until its owner adds it). That map is compiled into the bundle as `RS_STYLES`, and the router links a route's stylesheets and waits for them before mounting it on in-app navigation. A unit that adds a stylesheet for another route asks U10 to extend `ROUTE_STYLES`. Budget lines: `css` is `kit.css` (kit + tokens + base); the others print as `css:<name>` without a baseline.
6. **Static assets in JS.** `build.mjs` defines the global `RS_ASSETS` (the `assets` map) for bundled code. `ui/icons.js` uses `RS_ASSETS['icons.svg']` and expects U37's sprite to use Lucide names as symbol ids. CSS `url()` references to `web/assets` files are hashed by esbuild's `file` loader.
7. **Budget names.** `entry` is the entry chunk and its static imports. Every lazily imported module is measured with its static imports, excluding what the entry already loads, and named after its module: the directory for `index.js` (`poker/index.js` → `poker`), otherwise the file name (`screens/landing.js` → `landing`, `poker/jira-browse.js` → `jira-browse`). One alias: `issue-drawer` → `jira-drawer` (§g.7 names that chunk after its contents). Over the `budgets.json` number prints a warning; more than 10 % over fails the build. Chunks with no baseline are printed but not judged.
8. **Banned sinks.** An esbuild `onLoad` plugin rejects `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write` and `document.writeln` anywhere in bundled source, with file and line. It matches text, so the words must not appear in comments or strings under `web/src` either.
9. **`h()` allow-list.** Unknown attributes, inline `on*` attributes and string `style` throw instead of being dropped, so mistakes show up in tests. `href`/`src`/`action`/`poster` accept relative URLs and `http(s)`/`mailto` (links) or `http(s)`/`blob:`/`data:image/{png,jpeg,gif,webp}` (images). Protocol-relative URLs, including the `/\host` form, are refused.
10. **Router params.** `update(params)` receives the path parameters plus `route` (the matched pattern, so `team/index.js` can tell `/teams/:id` from `/teams/:id/settings`) and `query` (`URLSearchParams`, for `?tab=` and `?round=`). A malformed percent-encoding in a parameter makes the route unmatched (carried follow-up).
11. **Store API.** `createHub(read, {schedule})` gives `select(fn, eq, listener)`, `notify()` and `flush()` over any state source, so U28's `RoomStore` can keep its lazily computed view and still batch notifications per frame. `createStore(initial)` is the plain-state version.
12. **`http.js` retry rule.** GET, HEAD, PUT and DELETE are retried on 502/503, at most 3 tries in total. The wait is `Retry-After` (seconds or HTTP date) when present, else 125–250 ms, 250–500 ms. A `Retry-After` above 10 s is not waited for; the error carries `retryAfterMs` instead. POST and PATCH are never retried. Network failures become `ApiError{code:'network', status:0}`; aborts stay `AbortError`.

## Ownership deviation

`web/src/entry.js` belongs to U29, but the carried follow-up for this wave asked U10 to fix its `match()`. The fix lives in `core/router.js` (owned here); `entry.js` only swaps its private copy for `import { match } from './core/router.js'`. U29 replaces the stub with `createRouter()` anyway.

## Check command and Node versions

`node --test tests/web-unit/core` (a bare directory) runs on Node 20 (local) but **not** on Node 22 or 26: both treat the argument as a module path and fail with `MODULE_NOT_FOUND`. This contradicts U0 decision 7. `build.sh` passes explicit file lists, so CI is unaffected. On Node 22+ run `node --test 'tests/web-unit/core/**/*.test.js'`. Verified on 20.19.1, 22.23.3 and 26.5.0.

Test helpers in `tests/web-unit/core/` start with `_` and do not end in `.test.js`, so neither `build.sh` nor the Node glob runs them as tests. `_dom.js` is a minimal DOM for Node, so the core and kit tests need no jsdom dependency (the web workspace may depend on esbuild only, §a).
