# U48 decisions: web fake server and the fake e2e harness

U48 owns `tests/web-fake-server/**`, `tests/e2e/fake/_harness/**` and `tests/e2e/playwright.config.js`.
The API is described in `tests/web-fake-server/README.md`.

## Conventions later units must follow

1. **Fake specs import from the harness.** Every spec under `tests/e2e/fake/` imports `test`/`expect` from
   `_harness/fixtures.js`. That gives each test its own fake server on a free port (`fake` fixture,
   `baseURL`). A test fails on any CSP violation, any exception in a fake script, and any client frame
   the protocol refuses (opt out with `test.use({ allowProtocolViolations: true })`). `teeth.spec.js`
   checks that the fixtures catch these, using `test.fail()`.
2. **The fake runs in the Playwright worker, not as a `webServer`.** Specs script it directly
   (`fake.onCommand`, `fake.tx`, `fake.route`), so there is no control API over HTTP and no shared state
   between tests. Specs run `fullyParallel`.
3. **Projects** are `chromium`, `firefox`, `webkit` and `mobile-webkit` (iPhone 13). `RS_E2E_TARGET=fake`
   runs only `tests/e2e/fake/**`. `compose` runs everything else against `RS_E2E_BASE_URL` (default
   `http://localhost:8080`). U43/U45 own what the compose target needs beyond that. Results and reports go
   to `artifacts/e2e/` (gitignored).
4. **Every frame is checked against `protocol.gen.js`** (carried follow-up "match U2's protocol.gen.js
   exactly"). That covers frame members per `docs/protocol.md`, command and event kinds, the rooms each
   kind belongs to, payload member names, required command members, nack codes with their `retry` flag,
   and kick and bye codes. Frames a script sends are checked before they leave, and an invalid one
   throws. Transcripts are checked when loaded. Client frames are checked on arrival: the fake answers
   `nack invalid` when the envelope is fine, and closes with 4400 otherwise, as U2 decision 12 describes
   for the real server. Nested shapes (`RoundInfo`, snapshots) are not checked, because
   `protocol.gen.js` does not carry them and parsing `docs/protocol.md` would be fragile.
5. **Transcript format.** A transcript is `{frames, expectedViewerState?, expectedNav?}` (§g.4). `frames`
   is one viewer's socket for one room, in order. Server frames are replayed verbatim. Client frames in
   the list (`hello`, `cmd`, …) document what the viewer sent and are not replayed. A `welcome` sets the
   fake's `me`, a `pong` is skipped, and a `bye` closes with 1012. A transcript must open with the `snap`
   (or `replay`) of its room, and every frame must name the same room. U7 and U8 emit
   `tests/golden/transcripts/*.json`. If they need another shape (for example per-frame direction
   markers), `parseTranscript` in `transcripts.js` is the one place to change.
6. **The fake's resume rules match §c.3**: `sub {e,s}` with the current epoch gets a replay from the log
   (empty when current), and anything else gets a snapshot. `lastQ` is the cid's cursor. A `q` at or
   below the cursor is acked `dup`, and `cmd` without a sub gets `nack not_subscribed`. After a transcript
   is replayed, the room's epoch, seq and log follow it, so a resume after the transcript works.

## Decisions where the spec was silent

1. **The shell.** It mirrors U10 decision 3, since U11's `Shell` is not merged. It links the kit and route
   stylesheets, adds `modulepreload` for the entry's imports and the route's chunks, and writes the boot
   JSON with `<` escaped. The theme script from `csp.json` is inlined after `#boot`, followed by
   `<script type="module" src=entry>` and `<div id="app">`. Headers are the §e set. `connect-src` names
   `ws://host` because the fake serves plain HTTP. Only the files listed in `manifest.files` are served,
   uncompressed. Static file negotiation is U11's concern and is not mimicked here.
2. **Boot JSON** is whatever the test sets (`fake.boot`). The default is
   `{build:'fake', theme:'system', me:null, path}`. The exact shape belongs to U11/U25/U29.
3. **The CSRF rule is enforced** on non-GET `/api/` requests (`X-RS: 1`, and a same `Origin` when one is
   present; violations get 403 `csrf`), so front-end code cannot forget the header. The fake does not
   implement the `Sec-Fetch-Site` alternative.
4. **Fake Jira proxy shapes are provisional.** §f fixes the routes and error codes but not the response
   bodies, which belong to U26. The fake answers with a reading of §f: `browse → {buckets:[{id, kind,
   name, state, startDate, issues:[row]}], partial}`, `issues/{key} → {key, updated, fields, description
   (DocNode with island content), islandIds, comments, commentTotal, attachments, links}`. Description
   and comment bodies are rendered with U5's parser, and islands are spliced in from the fixture. A
   description write with an old `descriptionBase` or an unknown island answers 409 `stale`.
   `failNext(problem)` injects the §f error table. When U26 lands, U33 should align the fake (by
   requesting the change from U48's owner) or override routes per spec.
5. **Self-tests do not need `./build.sh web`.** `self.test.js` writes a tiny dist with the shape of the
   manifest, so `./build.sh test` (which does not build the web) can run it. The Playwright harness uses
   the real `web/dist`.
6. **No `ws` package.** The codec in `ws.js` handles RFC 6455 text, continuation, ping/pong and close
   frames, both masked and unmasked, with 7-, 16- and 64-bit lengths. Binary frames close the socket with
   1003, and a message over 64 KiB closes it with 4413. After a protocol error the connection stops
   parsing. Bytes that arrive with the handshake are processed on the next turn, so listeners attached
   after `connect` still see a close sent immediately after accepting.

## Browser observations for later units

- **WebKit reports close code 1012 as 1005.** On a socket the server closes with 1012 (restart), WebKit
  (desktop and mobile) gives `CloseEvent.code === 1005`. Chromium and Firefox give 1012. Codes in the
  4000 range (4409) come through unchanged. U28 must act on the `bye` frame (and treat 1005 like 1012),
  not rely on the close code. `ws.spec.js` pins this.
- **Firefox does not emulate `prefers-color-scheme: dark`** under Playwright 1.64 (`colorScheme: 'dark'`
  leaves `matchMedia` false). The system-theme check skips that one combination. U29's theme specs will
  hit the same limitation.
- Firefox and WebKit browsers were installed locally with `npx playwright install firefox webkit` for
  the pinned Playwright 1.64.1. CI needs `npx playwright install --with-deps` for all four projects.

## Verification

- `node --test tests/web-fake-server/self.test.js`: 33 tests (codec, validation, HTTP, every WS behaviour,
  transcript replay, the Jira fake). They pass on Node 20.19.1 and were run five times in a row without a
  flake.
- `./build.sh fake-e2e "_harness/*.spec.js"`: the shell, WS (transcript, ack/nack/gap, bye, 4409,
  refused client) and HTTP (fixtures, the Jira fake, CSRF) specs, plus the teeth specs, on all four
  projects.

## Amendment (UF4)

**HSTS is deliberately omitted on the fake.** The fake sends §e's security headers except
`Strict-Transport-Security`. It serves plain HTTP on `127.0.0.1`, and browsers ignore HSTS over HTTP anyway. Sending
it would only suggest that the fake checks HTTPS behaviour, and it does not. HSTS on the real server is U11's
(`Hosting/SecurityHeaders.cs`). When UF4 was written, that file did not send the header yet. UF4 reported this as a
follow-up.

## Additions (UF5)

- **`cid_reuse`.** The fake keeps the DESIGN §c.6 LRU of the last 256 `(cid, q) → payload hash` per room
  (the hash is SHA-256 of `[k, d]` as JSON). A command at or below the cid's cursor is acked `dup` when its
  hash matches or is unknown, and nacked `cid_reuse` when it differs. `fake.bye({newEpoch: true})` empties
  the LRU, as a restart does. To script the duplicated-tab case, `fake.seedCommands(room, cid, [{q, k, d}])`
  records commands as if another tab on that cid had them acked; the client's resend of one of those `q`s
  with its own payload then gets `nack cid_reuse`.
- **The teeth specs no longer use `test.fail()`.** The fixtures export their end-of-test checks
  (`expectNoCspViolations(page)`, `expectNoProtocolViolations(fake)`, `expectNoScriptErrors(fake)`) and
  expose what they collect (`page.cspViolations`, `fake.violations`, `fake.scriptErrors`). Each teeth spec
  commits one violation, asserts the specific record (`style-src-attr` for an inline `style` attribute,
  the refused `hello` with its `cid` error, the thrown script error), asserts that the check throws, and
  clears the record. A CSP record's `directive` is now the event's `effectiveDirective`, which is
  `style-src-attr` for that case in all four projects.
- **WebKit close 1005** is documented in `tests/web-fake-server/README.md` for U28.
