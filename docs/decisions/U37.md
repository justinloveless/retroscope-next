## Decisions where the spec was silent

1. **Sprite gutter.** §g.8 scales cards by 0.8, 1.2, 1.4 and 1.6, and at fractional scales the browser can sample a
   pixel from the neighbouring frame. A 2 px transparent gutter prevents that. Frame `i` sits at
   `x = i × 73`, so `neotro.css` (U31) can use `background-position-x: calc(var(--frame) * -73px * var(--scale))`
   with `background-size: calc(655px * var(--scale)) calc(95px * var(--scale))`, or read `cards.json`.
2. **Source frames are committed** under `web/assets/cards/` so `tools/make-sprite.mjs cards` is reproducible, and the
   test checks that the committed sprite matches what the tool produces from them. `build.mjs` (U10) should ship only
   files that CSS/JS reference (esbuild's `url()` handling does this), not copy `web/assets/` wholesale.
3. **`make-sprite.mjs` has no dependencies.** It decodes and encodes PNG with `node:zlib` (8-bit RGBA, non-interlaced,
   the only format the card art uses). The filtered scanlines (and so the pixels) are deterministic, but the deflated
   bytes depend on the zlib build Node bundles: Node 20, 22 and 26 each produce a different `cards.png`. The committed
   file was written with Node 26.5.0 (zlib 1.2.12); rerun the tool only when the frames change, or it rewrites the
   file with no visual change. The test therefore compares the IHDR and the inflated IDAT with what the tool filters,
   not the PNG bytes, and passes on Node 20.19.1, 22.12.0 and 26.5.0. It also builds `icons.svg`
   (`icons <dir>`) from an unpacked `lucide-static` tarball, so no Lucide package enters `package.json`.
4. **Font subset.** fontTools is a one-off authoring tool, not a build dependency, so the WOFF2 is committed. It was
   produced with fontTools 4.67.0 and brotli 1.2.0 (PyPI, in a throwaway venv) from the original's
   `src/fonts/Neotro.ttf` (sha256 `2e4bdf81…27728`, m6x11plus per its name table):

   ```
   pyftsubset Neotro.ttf --unicodes="U+0020-007E,U+00A0-00FF" --flavor=woff2 \
     --name-IDs='*' --name-languages='*' --layout-features='*' --no-hinting --desubroutinize \
     --output-file=web/assets/m6x11plus.woff2
   ```

   Re-running it gives a byte-identical file. The font has 174 code points in that range; it has no grave accent
   (U+0060) and a few Latin-1 gaps, so long text keeps the system font stack (§g.7). The name table is kept because
   it carries the author and the "Free to use with attribution" string.
5. **Deck glyphs** checked by the test: the deck values `1 2 3 5 8 13 21`, `-`, `?`, and the letters used on pills
   and big buttons (`x pts`, `Abstain`, `Lock In`, `Reveal`), plus all printable ASCII except U+0060 and a sample of
   accented Latin-1 letters.
6. **Icon set.** §g.1 lists `icons.svg` (Lucide subset) without naming the icons. The subset is every Lucide icon the
   original imports (103 names), mapped to their current Lucide 1.x names (for example `Edit` → `square-pen`,
   `Loader2` → `loader-circle`, `AlertTriangle` → `triangle-alert`, `Smile` → `face-slightly-smiling`), minus `Github`
   (brand icons were removed from Lucide; the original used it only for a feedback link). The list lives in
   `ICONS` in `tools/make-sprite.mjs`; units that need another icon add it there and rerun the tool. Stroke attributes
   are on each `<symbol>`, because `<use>` inherits from its own ancestors and not from the sprite's root element.
7. **Version pin.** lucide-static 1.49.0 (published 2026-09-29, more than two weeks before this unit; 1.60.0 is the
   newest). Checked against registry.npmjs.org; tarball sha512
   `gSjtl7bR2v26oDInh2Wua1PrF2BRRXl9inhnLWcFfnRqRShmgZvlFRisPHqTfU7kxsuZU8ThNjAFotbInrzKow==`.
8. **Licence checks (§12 row owned by U37).** https://managore.itch.io/m6x11 was checked on 2026-10-20. It lists
   m6x11plus on the same page under the same terms, "free to use with attribution", with the credit "a font by Daniel
   Linssen". Not blocking. The default retro track has no recorded source or licence, so it is not shipped and the
   timer runs with the alarm only until a licensed track is added (with its own section in `THIRD_PARTY.md`,
   which the test then requires).
9. **Card art provenance.** The cards were added to the original repository in commit `100cb90` with no recorded outside
   author. Nothing proves they are the project's own art, so `THIRD_PARTY.md` marks their origin as unconfirmed and
   blocks release until the project owner confirms it.

   **Update (2026-10-22):** the project owner confirmed that the card art is the owner's own work or licensed to the
   owner and may ship. `THIRD_PARTY.md` now records this, and the release gate in `deploy/RUNBOOK.md` section 1 is
   gone.

## Follow-ups for other units

  landing screen).

  development machine), not the Node 20/22 the project targets, so `./build.sh test` can pass where CI fails. Pin or
  check the Node major there.
