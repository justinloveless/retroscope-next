# UX14 decisions: the issue fields as labelled chips and a meta line

The Jira fields block in the poker issue view (`web/src/poker/issue-drawer.js` `fields()`, shared by the centre of
the felt and the drawer) was an eleven-row label and value table. At 1440 px with both side panels open the centre
is about 390 px wide, so the labels took a third of it, every empty field took a full row with a dash, and the
description started near the bottom of the first screen.

UX14 changes `web/src/poker/issue-drawer.js`, `web/src/ui/menu.js` (an `onClose` option), `web/styles/jira.css`,
the web fake's Jira (`jira.js`, the fixture and the demo data) and the fake e2e specs `poker-jira/drawer.spec.js`
and `poker-jira/issue.spec.js`.

## The candidates and the owner's pick

Three throwaway prototypes were built on the same commit, screenshotted at the same widths (the centre at
1440 px with both panels open and with both collapsed, at 1280 px with one panel open, the drawer, and an iPhone 13,
in both themes, on a sparse and a fully populated issue), and scored by three judges for space, interaction and
look:

- **A. Property tiles.** Each field is a tile with a small label above its value, in a grid of 2 to 4 columns by
  container width, with the reporter and dates on one muted line. Visible labels everywhere and the best date
  treatment, but about 2.5 times the height of B, and empty tiles as tall as full ones.
- **B. Header chips and a meta line.** The fields people change while pointing (status, type, priority, assignee,
  points) become a row of edit chips, then a parent and sprint line and a muted record line. It saved the most
  height at every width with no breakpoints, but had no visible labels, wrote `PTS –` for an unestimated issue,
  dropped empty labels and reporter, and showed the sprint as muted text that looked read-only.
- **C. A details sidebar.** At 40rem and wider the fields move into a column beside the description, as in Jira;
  narrower, the editable ones sit two to a row and the rest fold behind "More details". It only works at widths
  the poker view rarely has, and it ranked last with every judge.

**The owner chose B** (2026-10-23), with the judges' additions below.

## What was grafted onto B

1. **Visible labels.** Each chip has a short muted label above it (Status, Type, Priority, Assignee, Points), and
   the lines below have inline labels (Parent, Sprint, Labels, Reporter, Created, Updated). The labels are the
   `<dt>` of a `<dl>`, so screen readers pair them with their values. The chip buttons keep today's accessible
   names (`Change status: To Do`, `Change story points: none` and so on) and their `.jira-field-*` classes.
2. **Empty fields stay and say so in words.** Unassigned, Not estimated, No parent, No labels, and Backlog for no
   sprint, all muted. The reporter is left out only when Jira has none.
3. **Short dates.** The record line shows `Oct 9` within the current year and `Jun 30, 2025` for an earlier one, in
   a `<time datetime>` whose tooltip is the full date and time. A populated issue's record fits on one line at
   390 px; a past-year date with a long reporter name wraps by whole label and value pairs.
4. **Quieter carets.** A chip's chevron shows on hover, on keyboard focus and while its menu is open, and stays
   faint on a touch screen (`hover: none`). Reduced motion drops the fade through the global rule in `base.css`.
   This answers the judges' point that A's hidden carets made editable and read-only fields look alike: an
   editable chip has a border and a fill at rest, and a read-only one (`.is-static`, for members without Jira edit
   rights) has neither and no caret.
5. **Sprint and parent look like what they are.** The sprint is a chip like the others, with a calendar icon,
   because it is editable. The parent is a link chip (a button with the folder icon, the key in mono and the
   summary) that opens the parent issue the way a linked issue opens: in the drawer from the centre view
   (`ctx.openLinked`), in place in the drawer.
6. **An initials avatar** beside the assignee, drawn in CSS from a `data-initials` attribute so the chip's text stays
   the name alone, in the app's avatar colours; Unassigned gets a dashed empty circle.
7. **Labels moved up** beside the parent and sprint, where they describe the issue, so the record line holds only
   who and when.

## Decisions where the brief was silent

1. **One layout that wraps, with one container query.** `.jira-meta` is an inline-size container. The chips sit in
   two groups (the issue's state, then its people), so a narrow view breaks the row between them instead of
   orphaning the Points chip, as happened at 1280 px with one panel open. Below 36rem (the centre between two
   panels, the drawer, a phone) Parent, Sprint and Labels form a two-column grid (CSS subgrid) whose values line up;
   at 36rem and wider (the centre with the panels collapsed) they flow as one wrapping row.
2. **The open state of a menu opened at a point.** `choose()` opens its menu with `openAt`, so the popover never
   saw the button and could not set `aria-expanded` on it. `createMenu` now takes an `onClose` that it passes to its
   popover, and `choose()` sets the button's `aria-expanded` to `true` when it opens and `false` when it closes. The
   caret's open state keys on that attribute. The assignee and points popovers already anchor on the button.
3. **The demo issues** match the two cases the screenshots compare. DEMO-123 is shaped like the owner's original
   screenshot (unassigned, not estimated, in a sprint, with a parent, no labels, created in a past year, reported by
   someone else); DEMO-119 is fully populated (assignee, points, parent, sprint, labels, a different reporter, a
   creation date this year). DEMO-150 gained labels so the drawer's populated case shows them. The web fake now
   honours an issue's `reporter`, falling back to the first user as before, and the fixture's RS-20 has a past-year
   creation date for the e2e date check.
4. **Visual baselines.** The poker-table baselines (`tests/e2e/fake/poker-table/visual.spec.js`) show a table whose
   round has no Jira issue, so they do not include the fields; they passed unchanged on darwin and were not
   regenerated. No other baseline renders the issue view.

## Open

- **Points: the visible text and the accessible name differ.** An unestimated issue's chip reads "Not estimated"
  while its name stays `Change story points: none`, as the brief required. axe reports this as
  `label-content-name-mismatch` (WCAG 2.5.3), which matters to voice-control users. Changing the name to
  `Change story points: Not estimated` would fix it; it needs the owner's agreement because the names were to stay
  as they are. No other field has the mismatch.
- The drawer still shows the issue key twice (in its title and above the summary). That predates this unit.
