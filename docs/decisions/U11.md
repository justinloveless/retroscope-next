# U11 decisions: hosting

U11 owns `src/Retroscope.Server/Hosting/**` (except `SpotLoadCommand.cs`, which is U27's), `Server/Json/HostingJsonContext.cs`
(transferred per U0 decision 3) and its tests in `tests/Retroscope.Integration.Tests/Hosting/**`.

## Contracts later units rely on

| Type | Use |
|---|---|
| `RoutePolicy` + `.RequireRoutePolicy(…)` | Every endpoint declares one. The middleware enforces the caller half (below) |
| `RateLimit.Define(name, rules…)` + `.RequireRateLimit(…)` | Every endpoint declares one; `RateLimit.Unlimited` is an explicit opt-out. Rules: `RateRule.PerIp/PerPrincipal/PerSubject/Global(limit, window)` |
| `RateLimiter.TryAcquire(limit, new RateKeys(ip, principal, subject), out retryAfter)` | Limits inside a handler (per principal per board for unlock, per account for login backoff) |
| `RateLimits.LimitedResult(retryAfter)` / `WriteLimitedAsync` | The 429 problem with `Retry-After` |
| `ICallerResolver` (U16 implements) / `HttpContext.GetCallerAsync()` | Cookie → `Caller(Principal, EmailVerified, AuthSessionId)`, resolved once per request. Without a resolver every request is anonymous |
| `Problem.Result(status, code, fields?)` / `Problem.WriteAsync` | Every error body (`application/problem+json`, stable `code`, optional `fields`) |
| `EmailBudget.TryReserve(recipient, ip, sender?)` | False → drop the mail, still answer 202. `Dropped` feeds `/api/admin/stats` |
| `RoomResolver.ResolveAsync(context, kind, code, ct)` | `Found(room, facts, Granted\|Password)`, `Hidden` or `Limited`; `RoomResolver.Result(resolution)` writes the non-found response |
| `IRoomAccess` | Subscribe check used by the resolver. Default `PolicyRoomAccess`: loads team membership through `IMembershipLookup` when registered, then `Policy.Can(Subscribe)` with the registered `IAccessView` |
| `IBootContributor` / `BootContext` | Adds members to the boot JSON (`boot.Set(name, JsonElement)`, `boot.Theme = …`) for the shell and `/api/boot` |
| `ShutdownCoordinator.Register(phase, step)` / `IsStopping` | SIGTERM steps in order `StopAccepting → DrainActors → CloseSockets → ReleaseLease` |
| `ClientIp.Of / LimitKey / AuditPrefix` | Client address after forwarding; limit key (IPv4, IPv6 /64); audit prefix (/24, /48) |

## Decisions where the spec was silent or did not fit

1. **Pipeline.** `UsePipeline` runs forwarded headers → security headers → error handling → static assets → routing
   → CSRF → rate limits → route policy → WebSockets. §a lists only the first, second, fourth, sixth, seventh and last.
   Errors are caught inside the security headers so problem responses carry them. Routing comes after static files so
   asset requests skip it, and before CSRF so the later steps can read endpoint metadata. Rate limits run before the
   route policy, so unauthenticated floods are counted too.
2. **Missing declarations fail closed.** An endpoint without a `RoutePolicy` or a `RateLimit` gets 403 at runtime,
   not just a red route-inventory test. Only `RouteEndpoint`s are checked: the framework's 405 rejection endpoint
   carries no metadata.
3. **Route policies are split.** The middleware checks only the caller. `Public`: anyone. `Guest`, `BoardAccess`,
   `BoardManage`, `SessionManage`: any principal, guests included (quick boards and sessions may be created by
   guests). `User`, `TeamMember`, `TeamAdmin`, `TeamOwner`: a user. `VerifiedUser`: a user with a verified email
   (403 `email_unverified`). `AppAdmin`: a user with `IsAppAdmin` (403 `forbidden`). A missing caller or a guest
   where a user is required gets 401 `unauthenticated`. Team, board and session checks need the resource, so the
   handler finishes them with `Policy.Can`.
4. **Guest-reachable means all four of `Guest`, `BoardAccess`, `BoardManage`, `SessionManage`.** The route inventory
   requires a per-IP **and** a per-principal rule on each (S7).
5. **CSRF is one global middleware with no exemptions**, not per-route metadata. Every unsafe method on every route
   is covered, so "unsafe methods carry CSRF metadata" (§j) holds by construction. `Origin` is compared ordinally
   with `PUBLIC_URL`'s origin (browsers serialize it in lower case). Two `Origin` headers, `Origin: null` and
   `X-RS` values other than `1` are refused (403 `csrf`).
6. **Rate limiter.** One `RateLimiter` holds every bucket in a single LRU of 100,000 keys. A request takes a token
   from every bucket its rules name, or from none: a request refused by one rule is not charged to the others. An
   evicted key starts again full, so eviction only ever errs towards allowing. The key includes the rule's limit and
   window, so two rules of one limit never share a bucket. `Retry-After` is the wait until every refusing bucket holds
   a token, rounded up to whole seconds. A principal rule is skipped for anonymous callers, whose IP rule still applies.
7. **Email budget** lives in the same limiter as one four-rule limit: recipient (lower-cased, trimmed) 3/h, IP 20/h,
   sending user 20/day, global 200/h.
8. **Room resolver.**
   * Every lookup counts against the 30/min/IP limit, hits, misses and malformed codes alike.
   * A malformed code, a missing room, a deleted board, a room of a deleted team and a room the caller may not
     subscribe to are all `Hidden`. `RoomResolver.HiddenResult()` is one fixed 404 problem (`room_not_found`), and a
     test compares the status, headers and body of the three cases.
   * A password board the caller cannot subscribe to is `Found(…, Password)`: anyone with the code may try the
     password (parity).
   * §d's `access:'signin'` is not produced by the resolver, because "anonymous caller on a team room" would tell
     an anonymous caller that the room exists. If U25 wants a sign-in prompt, it must show it for every `Hidden` result
     an anonymous caller gets, missing rooms included.
   * Lookup is exact code first, then case-insensitive on the `upper(code)` index. Team rooms are addressed by id,
     never by code.
9. **Shell.**
   * `ShellRoute.All` mirrors the frozen `web/src/routes.js`, and a test keeps them equal. `ShellRoute.Match` is a
     line-for-line port of `core/router.js` `match()`, so the server resolves `/api/boot?path=` exactly as the client
     does. A malformed percent-escape leaves the path unmatched, and `*` also matches nothing (`/admin`).
   * The page is fixed per route and rendered at startup. Only the boot JSON is written per request.
   * Order in `<head>`: kit CSS, the route's CSS, the pixel-font preload (poker routes only), `modulepreload` for the
     entry's static imports and the route chunks, `#boot`, the theme script byte for byte, then the entry module.
   * The boot JSON is `{build, theme, …contributed members}`. `build` is the first 12 hex digits of the manifest's
     sha256 and `theme` defaults to `system`. Its encoder escapes `<`, `>` and `&` (`<` becomes `\u003C`), so the element cannot
     be closed from inside.
   * The shell and `/api/boot` are `no-store`.
   * Room snapshots and `me` are contributed by U25 and U16.
10. **Web build location.** `WEB_ROOT`, defaulting to `<binary dir>/wwwroot` (`/app/wwwroot` in the image). Without
    a `manifest.json` the server still starts: no assets, and a shell without scripts (tests, API-only runs). A manifest
    file entry outside `/assets/` or containing `..` fails startup. Only files listed in the manifest are served;
    anything else under `/assets/` is a 404 problem.
11. **Static negotiation.** Encodings are chosen in the order br → gzip → identity. A coding counts as accepted when
    its own q-value, or the `*` q-value, is above 0. `Vary: Accept-Encoding` is sent only when a sibling exists. Each
    representation has its own strong ETag (the manifest's raw ETag with `.br`/`.gz` inside the quotes).
    `If-None-Match` uses weak comparison and `*`. HEAD is answered, other methods get 405. Range requests are not
    supported (no audio ships, U37).
12. **Security headers go on every response**, not only HTML. They are written before the request runs, so an
    endpoint can replace the CSP (U20's blobs use `default-src 'none'; sandbox`). `connect-src` names
    `wss://<PUBLIC_URL authority>`, or `ws://` for an `http` origin in development. Kestrel's `Server` header is off.
13. **Forwarded headers.**
    * With `TRUSTED_PROXY_CIDRS` empty, forwarding is disabled, because ASP.NET Core's middleware trusts **every** peer
      when both of its known lists are empty. Clearing the lists alone would have trusted everyone; a test covers it.
    * The default loopback entries are removed.
    * `X-Forwarded-Proto` is applied too.
    * `CLIENT_IP_HEADER` replaces the header the middleware reads, under the same trusted-peer rule.
14. **Health.** `/healthz` is 200 only when an `ILeaderEpoch` is registered and `IsLeader`, shutdown has not begun,
    and `select 1` answers within 2 s. Until U12 registers the leader, `/healthz` is 503.
15. **Shutdown.** `ShutdownCoordinator` is an `IHostedLifecycleService`. Its `StoppingAsync` runs before any hosted
    service's `StopAsync`. Steps of one phase run concurrently. A failing step is logged and does not stop later
    phases. `HostOptions.ShutdownTimeout` is 7 s, inside compose's 8 s `stop_grace_period`.
16. **Kestrel** (§i.3): `MaxConcurrentConnections=2000`, `MaxRequestBodySize=2 MiB`, `KeepAliveTimeout=2 min`.
    `UseWebSockets` sets `KeepAliveInterval=15 s`, `KeepAliveTimeout=30 s` as the default. The transport (U14) still
    sets them per accept, and owns the 4 KiB receive buffer and the Origin check.
17. **`PUBLIC_URL` is required** and must be a bare http(s) origin; the host fails at startup otherwise.
18. **Default problem codes** for framework errors with no body: 400 `invalid`, 401 `unauthenticated`, 403
    `forbidden`, 404 `not_found`, 405 `method_not_allowed`, 413 `too_large`, 415 `unsupported_media_type`, 429
    `rate_limited`, 503 `unavailable`, other 5xx `internal`. Unhandled exceptions are logged with method and endpoint
    name only, never the body or path, and answered 500 `internal`.

## Not done here

* **Dynamic JSON compression** (§g.7, "over 1 KB with Brotli Fastest"). ASP.NET Core's response compression
  middleware has no minimum-size setting. Compressing authenticated JSON that echoes user input next to secrets (the
  invite list carries decrypted invite URLs) is a BREACH-shaped risk. None of U11's checks covers it. U43 decides it
  with measured payload sizes.
* **Console JSON logs** and the `/invite/[redacted]` request-log rule (§i.3, §e) are left to U43 and U16.

* **U0 / `build.sh` owner (aot-smoke):** the server now requires `PUBLIC_URL` at startup, and `/healthz` needs the
  leader and the database. The native-binary step already passes both URLs and `PUBLIC_URL`, so it passes once U12
  registers `ILeaderEpoch`; until then it gets 503. The chiseled-image step runs with neither, so it must pass
  `PUBLIC_URL`, `DATABASE_URL` and `DATABASE_OWNER_URL` pointing at the throwaway Postgres (for example
  `--network host` or the container's address).
* **U12:** register `ILeaderEpoch`, and a `ShutdownPhase.ReleaseLease` step.

* **U14:** register `StopAccepting` (refuse upgrades while `IsStopping`) and `CloseSockets` steps. Give `/ws` a
  `RoutePolicy.Guest` and a rate limit with per-IP and per-principal rules.

  `ClientIp.AuditPrefix` for audit rows and backoff keys. U17 calls `EmailBudget.TryReserve` before writing each
  outbox row.

* **U25:** shell and `/api/boot` room snapshots go through an `IBootContributor` that calls `RoomResolver` for
  `/poker/:code`, `/teams/:tid/poker/:code` and `/retro/:code`. `by-code` uses `RoomResolver.Result` for every
  non-found outcome.

## Amendment (UF4)

Decision 6 is tightened: `RateLimiter.TryAcquire` first looks at the buckets that already exist, without creating or
reordering any. If one refuses, the call returns at once. It creates no bucket for the other rules and does not move
the refused key up the LRU, so a caller over its per-IP budget cannot fill the table with fresh recipient or principal
keys. A key that does not exist yet counts as full. When every rule allows, the buckets are created or touched and
charged as before. `Retry-After` still covers every refusing bucket.
