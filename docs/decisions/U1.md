# U1 decisions: schema and migrator

## What the migrator does

`Migrator.RunAsync(ownerConnection, appPassword)` runs as `retroscope_owner` in **one transaction**:

1. `pg_advisory_xact_lock(1381123154)` (the lease already serializes migrators in production, §c.9; this
   makes standalone runs from tests and tooling safe too).
2. Creates `retroscope_app` if missing, then always sets `login nosuperuser nocreatedb nocreaterole
   noreplication nobypassrls` and its password, plus the per-role timeouts (`statement_timeout = 5s`,
   `idle_in_transaction_session_timeout = 30s`). The owner's own timeouts are set to 0 explicitly
   (`alter role current_user`), so a server-wide default can never cut off a migration or the import.
3. Checks every applied migration the binary knows against its sha256 and refuses on a mismatch.
4. Applies pending scripts in version order and records them in `schema_migrations`.
5. Re-asserts the grants (below), then commits.

It returns the number of migrations applied. Calling it is U12's job (after the lease is acquired).

## Decisions where the spec was silent

1. **The app role's password comes from `DATABASE_URL`.** Role passwords cannot live in a migration file and
   compose already gives the app both URLs, so the migrator sets the app role's password to the one in
   `DATABASE_URL` on every start. Rotating `DB_APP_PASSWORD` therefore needs only a redeploy.
   `Db.FromConfiguration` requires `DATABASE_URL` to connect as `retroscope_app` and to carry a password.
   It is resolved lazily (on first use of `Db` or `NpgsqlDataSource`), so a host started without database
   settings, such as the chiseled-image `/healthz` check, still starts.
2. **Grants live in `Migrator.cs`, not in `0001_init.sql`, and run on every start.** A later migration that
   adds a table is granted without repeating the grant (tested). The DDL keeps only
   `revoke execute on function rs_fence(bigint) from public`, which belongs to the function definition, so the
   fence is executable by `retroscope_app` and the owner only.
3. **`schema_migrations` is read-only for the app** (`select` only). The spec's "DML on all tables in public"
   would let the app rewrite the migration ledger and defeat the sha guard. Every other public table,
   `system_state` included, gets `select, insert, update, delete`. Identity columns (`email_outbox`,
   `audit_log`) need no sequence grant (tested).
4. **A newer applied migration the binary does not know is tolerated.** Migrations are expand/contract
   compatible with the previous binary (§c.9), so a rollback to that binary must still start. The sha guard
   covers every file the binary carries.
5. **Versions must be 1, 2, 3… with no gaps.** Embedded files are named `NNNN_name.sql`; the name after the
   underscore is stored in `schema_migrations.name`.
6. **`0001_init.sql` is the §b DDL verbatim** apart from the `rs_fence` revoke above and dropping the trailing
   commented-out grants (now in the migrator).
7. **`db/migrations/.gitkeep` stays.** It is U0's file; it is harmless now that `0001_init.sql` exists.

## Tests and the schema snapshot

- `tests/Retroscope.Integration.Tests/Schema/PostgresFixture.cs` starts one pinned `postgres:18-alpine`
  container per run (same digest as `build.sh`) and gives every test its own database
  (`CreateDatabaseAsync`, migrated, or `CreateEmptyDatabaseAsync`). Roles are cluster-wide, so the fixture
  migrates one database at a time. Later units may join the `SharedPostgres` collection to reuse it.
- `tests/schema.snapshot.sql` is `pg_dump --schema-only` of a freshly migrated database, grants included.
  pg_dump 18 brackets its output with `\restrict <random key>` / `\unrestrict` lines; the fixture drops them.
  The "Dumped from/by version 18.6" header is kept on purpose: a Postgres image bump shows up as a snapshot
  diff. Regenerate with `RS_UPDATE_SCHEMA_SNAPSHOT=1 dotnet test tests/Retroscope.Integration.Tests --filter Category=Schema`.

## Local environment note (Rancher Desktop)

Testcontainers starts its Ryuk reaper by bind-mounting the Docker socket. With `DOCKER_HOST` pointing at
`~/.rd/docker.sock` that mount fails (`stat /Users/…/.rd/docker.sock: operation not supported`). Export
`TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock` (the socket path inside the VM) together with
`DOCKER_HOST` before `./build.sh test`. GitHub-hosted runners need neither. The fixture also retries the first
connection for up to 30 s, because Rancher Desktop's port forward can lag behind the container's readiness.

## Follow-ups for other units

- **U12:** call `Migrator.FromEmbeddedScripts().RunAsync(ownerConnection, db.AppPassword)` after acquiring the
  lease; the `Db` singleton carries `OwnerConnectionString` and `AppPassword`.
- **U0 / build.sh owner:** `aot-smoke` passes the owner URL as `DATABASE_URL`. Once U12 runs the migrator at
  startup, `Db.FromConfiguration` will reject that; the smoke run should pass
  `Username=retroscope_app;Password=<any>` in `DATABASE_URL` (the migrator creates the role with that password).
