# U33 decisions: poker Jira UI

U33 owns `web/src/poker/{jira-browse,issue-drawer,submit}.js`, `web/src/ui/glyphs.js`,
`tests/e2e/fake/poker-jira/**`, the `poker-jira-panel` and `poker-jira-drawer` states in
`tests/e2e/screenshots/capture.spec.js` (carried follow-up) and this file.

## Contracts other units rely on

1. **HTTP shapes the screens read (contract for U26).** They follow U48's fake (`tests/web-fake-server/jira.js`),
   which the demo also serves. U26 implements these shapes, or changes the screens and specs with them in the same
   integration commit. Timestamps inside Jira bodies are Jira's ISO strings.

   | Route | What the screens read |
   |---|---|
   | `GET /api/teams/{id}` | `role` and `jira:{configured, siteHost, ticketPrefix, membersCanEdit}` (U30's shape). Only `configured: true` shows any Jira UI |
   | `GET …/jira/browse?status=&points=&scope=&q=` | `{buckets:[{id, kind, name, state, startDate, issues:[row]}], partial}`, buckets in display order (sprints by start date then name, Backlog last; Jira rank inside). `row = {key, summary, issueType, status, statusCategory, priority, points, parentKey, parentSummary, roundState}` |
   | `GET …/jira/issues/{key}` | `{key, updated, editable?, fields:{summary, status, statusCategory, priority, issueType, assignee:{accountId, displayName}?, reporter:{displayName}?, parent:{key, summary}?, labels, points, sprint:{id, name, state}?, created}, description: DocNode, islandIds, comments:[{id, author, created, body: DocNode}], commentTotal, attachments:[{id, filename, mimeType}], links:[{id, type, direction, label?, key, summary}]}`. `editable: false` turns description editing off |
   | `GET …/issues/{key}/comments?startAt=` | `{startAt, total, comments}` |
   | `GET …/issues/{key}/options` | `{issueTypes:[{id, name}], priorities:[{id, name}], linkTypes:[{id, name, inward, outward}], transitions:[{id, name, to}]}` |
   | `GET …/sprints` | `{sprints:[{id, name, state}]}` |
   | `GET …/issues/{key}/assignable?q=` | `{users:[{accountId, displayName}]}` |
   | `PATCH …/issues/{key}` | one of `{summary}`, `{priorityId}`, `{issueTypeId}`, `{assigneeAccountId: string \| null}`, `{description, descriptionBase}`; 409 `stale` refuses a description write |
   | `POST …/issues/{key}/transition` | `{transitionId}` |
   | `PUT …/issues/{key}/points`, `…/sprint` | `{points: number \| null}`, `{sprintId: number \| null}` |
   | `POST …/issues/{key}/comments` | `{body}` (markup) → the new comment in the list shape |
   | `POST …/issues/{key}/links` | `{typeId, direction: 'inward' \| 'outward', targetKey}` → the link; `DELETE …/links/{id}` |
   | `POST …/issues` | `{summary, description?}` or `{summary, cloneFrom}` → `{key}` |
   | `GET …/issues/{key}/attachments/{id}` | image bytes (`<img src>` and the lightbox) |

   Browse query values: `status` is `not-done` (default), `all`, `new`, `indeterminate` or `done` (status categories);
   `points` is `unpointed` (default), `any` or one of `1 2 3 5 8 13 21`; `scope` is `board` (default, board
   sprints + backlog), `open` (any open sprint + backlog) or `all` (closed sprints too); `q` is the search text,
   sent only when not empty. U48's fake ignores `not-done`, `any` and the numbers, so the specs override the browse
   route with a full implementation (`_jira.js`).
2. **Error codes shown.** `jiraMessage` in `submit.js` maps the §f problem codes and the `jira_pending` nack to
   sentences, and shows the first `fields` message of `jira_validation`.
3. **The feature entry.** `jiraFeature` (exported by `submit.js`) is the poker screen's `FEATURES` entry (U31
   contract 4). Quick sessions (`view.teamId` absent) get nothing and send no request; team sessions ask
   `GET /api/teams/{id}` once.

## Decisions where the spec was silent or did not fit

1. **Ownership deviation: `poker/index.js`.** U31 decision 4 asks for "one import and one `FEATURES` entry" as a
   change request or an integrator `fix(integration)` commit. Without it neither the chunks nor the specs exist,
   so the Check cannot run. Commit `fix(integration): mount the Jira feature on the poker page` adds exactly those
   two lines and nothing else. U32 adds its own entry to the same array; the merge is a one-line conflict.
2. **The submit chips ship in the poker chunk, not in jira-drawer.** §g.1/§g.7 put `submit.js` in the drawer
   chunk, but the chips must paint together with the reveal, and the feature entry has to be a static import of
   the poker chunk anyway. `submit.js` is that entry and holds the chips (poker chunk 16.5 KB of 40 KB). The
   browse panel (`jira-browse`, 8.4 KB) and the drawer (`jira-drawer`, 22.3 KB of 22.5 KB) stay lazy. They load
   1.5 s after the team's Jira configuration arrives, or at once on first use.
3. **The lazy chunks import nothing from poker modules.** `build.mjs` measures a lazy chunk with its whole static
   closure minus the entry. If `jira-browse.js` imported `model.js`, esbuild would move `model.js` into a shared
   chunk that both closures count. The feature passes `uuidv7`, `createSheet`, `jiraMessage`, `openIssue`,
   `prefetchIssue` and `addRounds` in through the context object instead.
4. **The editor is a static import of the drawer.** A lazy `import('../markup/editor.js')` lands on the `editor`
   budget line together with `parse`/`render`/`doc` (about 12 KB against 8 KB), which fails the build (U34
   decision 1, U30 follow-up). The drawer imports it statically: editor, markup and the drawer come to 22.3 KB
   brotli, under the 22.5 KB `jira-drawer` budget. The drawer also formats dates with
   `toLocaleString` rather than `core/fmt.js`, which would add its own 0.4 KB chunk. Once UF11 measures chunks net
   of their importer, the editor can become a lazy import.
5. **The submit chips sit under the table.** The U31 slots are toolbar, strip, left and right. None of them is
   next to the results bar, and the chips belong there (original `SubmitPointsToJira`, shown after the reveal).
   The feature puts its section after `.nt-center > .nt-table` on every update. **U31:** a `center` (or `table`)
   slot in `ctx.slots` would remove that DOM lookup.
6. **Panels.** The browse panel fills the left slot on desktop, open by default (parity: `jiraBrowser` default
   true), and the toolbar's "Browse Jira" button toggles it. The choice is stored as `jira` in
   `localStorage['rs.panels']`, merged with whatever else the object holds (U32 may keep its own keys there).
   neotro.css hides the side panels below 768 px, so phones open the panel as a left sheet. **Resizing (240–480
   px, §g.8) is not done here:** the slot's width is U31's CSS. A follow-up can wrap the slot with
   `ui/resizable.js`.
7. **The drawer is a non-modal side sheet** (`role=dialog`, fixed right, z-index 900), not a modal `<dialog>`. A
   modal makes the rest of the document inert. Menus and popovers (`ui/popover.js` appends to `body`) and toasts
   would then sit under it and could not be clicked. The table also stays visible while the spotlight holder
   previews an issue. Escape and the close button close it, and focus returns to where it was. Clone, New ticket
   and the lightbox are ordinary modal dialogs. **The Round panel's inline "Issue" tab (§0.1)** is left to
   whoever builds the right panel's tabs with U32's History. `createIssueDrawer` is a separate component and can
   be hosted there.
8. **Pending preview.** When the spotlight holder (`spotlight.holder === me` and `heldByThisTab`) opens an issue
   that is not already on a non-pending round, the feature sends `poker.round.create {pending: true, forceNew:
   true}` and the drawer shows "Add to rounds", which sends `poker.round.commitPending`. Closing the drawer, or
   previewing another issue, sends `poker.round.discardPending` for an uncommitted preview. That nack is
   swallowed: the server may already have discarded the round (spotlight lost, holder left). Opening a linked
   issue from inside the drawer only shows its details.
9. **Pointing/Pointed is computed from the room**, the way the original's `getJiraBrowseDisabledReason` does
   (pending previews excluded), so a round added a moment ago blocks its row at once. A row's server
   `roundState` is used when the room has nothing to say. §f's 30 s browse cache is shared by every member, so
   the server cannot know this session's rounds without per-session cache keys. Rows with a reason are hidden
   while "Hide pointed and pointing" is on, except while a search text is set (parity).
10. **Filters** are stored in `localStorage['rs.jira.filters:<teamId>']` and collapsed buckets in
    `localStorage['rs.jira.collapsed:<teamId>']`. Every stored value is checked against its allow-list, and an
    unknown value falls back to the default. Search runs on Enter or the Search button only. The filter controls
    are menu buttons, not `<select>` (WebKit reports a CSP violation for every `<select>`, U30/U34).
11. **Add.** "+" sends `poker.round.create` (the server fills a placeholder round, §c.4). "Add all" sends one
    `poker.round.createMany` per 50 unblocked keys, in bucket order. A key typed by hand must match
    `PROJ-123` or a bare number, which the server prefixes with the team's ticket prefix. "New ticket" posts
    `POST issues` and then adds the new key unless "Add to the rounds" is switched off. Clone does the same.
12. **Hover prefetch.** After 600 ms on a browse row, the drawer's `prefetch` fills a tab-wide 60 s cache keyed
    by `team:key`. The prefetch applies nothing. A click within 60 s opens from the cache. Every write empties
    that key and reloads. The "Issue details" toolbar button (the viewed round's issue) opens the drawer, but
    has no hover prefetch. Round chips are U32's strip; prefetching from there needs the drawer through the
    feature context.
13. **Description editing** turns the DocNode back into markup with `toMarkup`, with every island as a bare
    `[[island:id]]` ref, and hands the islands to `createEditor({dialect: 'jira-description', islands})`. If
    `toMarkup` throws (a top-level node without a markup form that the server did not make an island), or
    `editable` is false, there is no Edit button. Save sends `{description, descriptionBase: updated}`. On 409
    `stale` the edit is dropped with a toast, and the drawer reloads the issue. The user's text is not kept:
    §f says the drawer reloads, and the islands it referred to may have changed.
14. **Story points in the drawer** are decimals from 0 to 1000 in steps of 0.5, and blank clears them (F15). The
    submit chips are the integers 1 2 3 5 8 13 21. The suggested chip is the winner, or the nearest chip, the
    higher one on a tie (parity).
15. **Submit state is the room's.** Pending and failed come from `view.submits[roundId]` (`poker.jira.points`).
    Done comes from `round.jira`, which the snapshot also carries. Every viewer sees the same line ("Submitting 8
    pts to RS-12… (Ada)", "Could not submit …: <reason>", "RS-12 has 8 pts in Jira · submitted by Ada"). Chips
    are disabled while a submit is pending, when the round has no key, and for plain members when the team keeps
    Jira edits to admins (`membersCanEdit: false`). The same rule makes the drawer read-only.
16. **Glyphs.** Type, priority and status visuals are 8×8 pixel patterns drawn as one SVG path each, labelled
    with the Jira name. Unknown types get a neutral square. Status badges are coloured by status category.
    Assignees show their display name (Jira avatars are never loaded, §f).
17. **No stylesheet.** U33 owns no CSS, so layout goes through `h()` style objects (CSSOM, allowed by the CSP),
    as U29 did. The rest uses the kit classes (`btn`, `badge`, `input`, `menu-*`, `dialog`). **U10/UF11
    follow-up:** a `jira.css` in `ROUTE_STYLES` for `poker/index.js` would let these rules move into a
    stylesheet. The drawer's prose (tables, panels, islands) uses whatever the kit styles. `.panel-*`, `.island`
    and Jira tables have no dedicated rules yet.

## Verification

- `./build.sh fake-e2e "poker-jira/*.spec.js"` runs 38 specs on chromium, firefox, webkit and mobile-webkit
  (152 runs; the hover-prefetch spec is skipped on mobile-webkit). The final run: 151 passed, 1 skipped, exit 0.
  Two earlier runs, made while the machine's load average was 140 to 180 (other wave-5 units were testing),
  timed out 5 to 7 Firefox tests in `page.goto` or `newPage`. The same 37 Firefox tests then passed alone
  (`--project firefox`), and so did the next full run at a lower load. No assertion failed.
- `RS_PREVIEW_URL=http://localhost:5201 npx playwright test --config tests/e2e/screenshots/playwright.config.js
  capture.spec.js -g jira`, against a demo started on port 5201 with `--quiet-peers`, passes the four
  `poker-jira-panel` and four `poker-jira-drawer` shots (light and dark, desktop and iPhone), with no console
  error. The panel and the drawer work against the demo's Jira data.
- `./build.sh test` is green: 2,892 .NET tests, 337 web-unit tests and the golden vectors.
- Chunk sizes (brotli): `jira-browse` 8.4 KB of 14 KB, `jira-drawer` 22.3 KB of 22.5 KB, `poker` 16.5 KB of 40 KB.
  The `entry` warning (12.6 KB of 12 KB) was already there before this unit (UF11).
