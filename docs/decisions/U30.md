# U30 decisions: team screens

U30 owns `web/src/team/**`, `web/styles/team.css` and `tests/e2e/fake/team/**`.

## HTTP shapes the team screens read (contract for U24, U25, U26)

§d names the routes but not most response bodies. The screens read the shapes below, and the fake specs
serve exactly these. Timestamps are Unix milliseconds and ids are UUID strings, as on the wire. A server unit
that settles on another shape changes the screen and its spec in the same integration commit.

| Route | Shape |
|---|---|
| `GET /api/teams/{id}` | `{id, name, description, role, pointDescriptions, maxEndorsements, jira:{configured, siteHost, projectKey, boardId, ticketPrefix, status, membersCanEdit}, counts:{boards, members}}`; `jira.status` is `ok`, `auth_failed` or `rotate_required` |
| Every list (`?cursor=`) | `{items:[…], nextCursor: string \| null}` |
| `GET …/boards?archived=true\|false` | items `{id, code, title, visibility, archived, archivedAt?, createdAt}` |
| `POST …/boards` | body `{title, visibility, password?, templateId?}` → `{id, code}`; the screen opens `/retro/{code}` |
| `GET …/poker-sessions` | items `{id, code, createdAt, pointed, total, parentKeys:[{key: string \| null, count}]}` |
| `POST …/poker-sessions` | body `{}` → `{id, code}`; the screen opens `/teams/{id}/poker/{code}` |
| `GET …/invites` | items `{id, kind:'email'\|'link', email? (masked), role, url? (links), expiresAt?, createdAt}` |
| `POST …/invites` | `{kind:'email', email, role}` or `{kind:'link', expiresInDays}` → the new invite in the list shape |
| `GET …/action-items?status=open\|done\|all&assignee=<pid>\|unassigned&sort=newest\|oldest` | items are `ActionItemInfo` (protocol.md) plus `boardTitle?` |
| `GET …/action-items/{itemId}/comments` | `{items:[{id, body, anonymous, createdAt, author?:{pid?, name, avatar?, guest}, mine?}]}` (`CommentInfo` without `cardId`) |
| `POST …/action-items/{itemId}/comments` | `{commentId, body}`; any 2xx |
| `GET …/endorsements/leaderboard?period=30d\|90d\|all` | `{entries:[{pid, name, avatar?, total, counts:{typeId: n}}]}`, ranked |
| `GET/POST/PATCH/DELETE …/endorsement-types` | items are `EndorsementTypeInfo`; POST `{name, emoji, description}` and PATCH (changed fields only) answer the type |
| `GET/POST/PUT/DELETE …/templates` | items `{id, name, isDefault, columns:[{title, color: ColumnColor, actionItems}], config:{allowAnonymous, votingEnabled, maxVotes: number \| null, showAuthorNames, stagesEnabled, enforceReadiness, allowSelfVotes, voteEmoji}}`; POST and PUT take the item without `id`; "Make default" is a PUT with `isDefault: true` |
| `GET …/jira` | `{configured, siteHost, projectKey, boardId, ticketPrefix, pointsFieldId?, membersCanEdit, status, lastCheckedAt, emailMasked?, tokenLast4?}` |
| `PUT …/jira` | §d body; answers the `GET …/jira` shape |
| `PATCH /api/teams/{id}` | only the fields that changed: `name`, `description`, `pointDescriptions` (deck keys with text; the whole map), `maxEndorsementsPerBoard` |
| `DELETE /api/teams/{id}`, `DELETE /api/retro/{id}` | JSON bodies `{confirmName}` / `{confirmTitle}` |
| `POST …/jira/meta` | `{keys}` → `{items:[{key, summary, …}]}`, as U48's fake Jira answers |

Board archive and delete use U25's `POST /api/retro/{id}/archive|unarchive` and `DELETE /api/retro/{id}`. Poker
session delete uses `DELETE /api/poker/{id}`.

## Decisions where the spec was silent or did not fit

1. **Topic badges are keyed by parent key only.** §0.1 keeps parent keys in Postgres and resolves summaries live.
   The original's 75 % rule (`getSessionTopicSummary75Percent`) also grouped rounds by parent *summary* when there
   was no key, which the new schema cannot reproduce. `topics.js` ports the rule over `parentKeys`: one entry per
   parent key, plus `key: null` for rounds that have a real ticket but no parent ("various topics"). So `total`
   in the list is all rounds and the parent-key counts sum to the rounds with a real ticket. Ties keep the order
   the server sends (the original's insertion order, i.e. first appearance in round order). The label is the
   summary from `POST …/jira/meta` (batched by 100, only when the team has Jira configured), otherwise the bare
   key. Tone colours hash the key exactly as `parentBadgeClassName` did. `poker.spec.js` replays the 1,202 golden
   cases (`tests/golden/topic-summary.json`) that have no summary-only topic and matches every label and tone.
2. **The HTTP list decides which action items show; the room decides how they look.** The room snapshot holds only
   open items and those closed in the last 30 days, and has no board titles. The tab fetches the filtered page
   over HTTP, then overlays each item's live state from the room view (which includes this tab's optimistic
   assign/done/delete), re-applies the filter client-side, and reloads the page when the room holds a matching item
   the page lacks (a new item). An open item the room no longer holds, or one deleted while the page was loaded
   (`removed` in the model), is hidden.
3. **Notices are revision counters in the model.** `team.boards.changed`, `team.poker.changed` and
   `team.action.comments` bump counters (`boardsRev`, `poker[sessionId]`, `commentsRev[itemId]`); screens select
   them and refetch. `team.poker.changed` patches the session's counts in place and reloads the list only when the
   session is unknown or its round count changed (its topics may have changed too).
4. **Comments refetch only while open.** A `team.action.comments` notice updates the count on the toggle at once
   and refetches only panels that are open (R22). A posted comment refetches the list itself, because the notice
   may arrive before or after the POST answer.
5. **Tabs, settings, the socket and the comments panel are lazy chunks.** With every tab in one chunk the `team`
   chunk measured 28 KB brotli against a 10 KB budget. Now the `team` chunk is the page shell (8.7 KB with today's
   stub entry, which preloads nothing; less once U29's entry carries the socket, http and kit). Each tab
   (`boards`, `poker-list`, `members`, `action-items`, `kudos`), `settings` and `comments` is its own chunk and has
   no baseline. The comments panel imports the shared editor statically, so the editor loads only when a panel
   first opens. A direct `import('../markup/editor.js')` would be measured as the `editor` budget line with
   `parse.js`, `render.js` and `doc.js` in its closure (12.2 KB against 8 KB), although the action-items chunk has
   already loaded those three; see the follow-up for U10/U0 below.
6. **One socket per browser tab, created here until the entry provides one.** U28 expects U29's entry to create the
   socket. Until there is a shared accessor, `team/index.js` creates it lazily (`import('../net/socket.js')`),
   keeps it in module scope across remounts and leaves the room on unmount.
7. **Navigation from code** (after creating a board or session, leaving the team, deleting it) clicks a hidden
   `<a data-nav>`: the router handles it in-app when it is running, and the browser loads the page otherwise.
   Tab and filter changes use `history.replaceState` (as the original did), so they add no history entries.
8. **Roles shown and gated live.** The viewer's role is read from the room's member list (so a demotion hides admin
   actions at once) and falls back to `GET /api/teams/{id}`'s `role` before the snapshot arrives. The server
   still decides every action. Owners change roles, transfer ownership and remove anyone but themselves; admins
   remove plain members; everyone but the owner can leave (§d, U9 `TeamManageAdmins`).
9. **Jira settings are write-only.** The token field is always empty, `type=password`, with `•••• last4` as its
   placeholder; the email shows the masked address as a placeholder. Empty email or token fields are left out of
   the PUT, so the stored values are kept. A changed site (or a first connection) without a token is refused in
   the form before any request, and the server's refusal is shown the same way. The rotate-required and
   auth-failed banners show on the settings card (blocking style) and, for admins only, on the team page with a
   link to `/teams/{id}/settings#jira`. `membersCanEdit` is a switch inside the form, saved with the rest.
10. **Email invites need a verified address.** The button is disabled with a hint when `boot.me.user.emailVerified`
    is false, and the server's `email_unverified` is shown if it refuses anyway. Link invites copy their URL to
    the clipboard when created.
11. **Image uploads in action-item comments** post the raw file to `/api/retro/{sourceBoardId}/images` with `X-RS: 1`
    and map U20's codes (409 `board_quota`, 413 `too_large`, 415 `unsupported_media_type`, 507 `storage_full`) to
    toasts through the editor's `onError`.

## WebKit reports a CSP violation for every native `<select>`

In WebKit (desktop and the iPhone 13 profile, Playwright 1.64.1) a page with `style-src 'self'` gets a
`securitypolicyviolation` event (`style-src-attr`, target the `SELECT`) as soon as any `<select>` renders, even one
created with no attributes at all. The inline style lives in WebKit's own user-agent shadow tree; Chromium and
Firefox report nothing. Every team screen with a filter or a dialog select failed the harness's CSP check on
WebKit because of it. `_team.js` therefore extends the harness `test` with a capturing `window` listener, on
WebKit only, that stops exactly that report (target is a `SELECT` without a `style` attribute of its own,
directive `style-src-attr`) before the harness's `document` listener records it. Every other violation still
fails the test.

## Follow-ups for other units

- **U48 (harness):** filter the WebKit `<select>` report in `_harness/fixtures.js` itself (the same three
  conditions), so U29, U34 and every other screen with a native select do not each need the filter; then `_team.js`
  can drop its copy. U10's `createSelect` renders the same native element.
- **U10 / U0 (`budgets.json`):** the `editor` line counts the editor's whole static closure, including the markup
  parser and renderer that every page showing markup has already loaded (12.2 KB measured against 8 KB, while
  `editor` + `caret` + `undo` alone are about 7 KB). U34 and U33, which will `import()` the editor directly, will
  hit this. Either measure the editor without modules its importers already load, or move the baseline.
- **Integrator (with U29):** U29's branch adds `screens/app.js` with `getSocket()` and `navigate()`, which was not on
  main when this unit ran. On integration, `teamSocket()` in `team/index.js` becomes `getSocket()` followed by
  `start()` (decision 6), and the hidden-link `navigate` can become app.js's `navigate` (decision 7). The
  `/login?return=` link on the signed-out team page uses the query name U29 validates with `safeReturn`.
- **U24, U25, U26:** implement the shapes in the table above, or change them together with the screens.
