# U42 decisions: importer storage and verify

U42 owns `src/Retroscope.Importer/Storage/**`, `src/Retroscope.Importer/Verify/**` and
`tests/Retroscope.Importer.Tests/EndToEnd/**` (`Category=EndToEnd`).

## Public surface

| Type | Use |
|---|---|
| `StorageStage` (stage 500) | Attaches avatars from `archive.storage_cache` and writes `archive.storage_objects` for every Supabase storage object |
| `StorageStage.AvatarBlobId(user)` | `v5(avatar:<user id>)` under namespace `5d0c7a3e-91b4-4f2a-8e6d-3c1b9a7f2e40` (frozen) |
| `StorageStage.AvatarKey(user, avatarUrl)` | The cache entry (`avatars/<user id>.<ext>` or `google/<url>`) an `avatar_url` may use, or null |
| `Verify/*Check` | The §h.5 hard invariants, discovered by reflection like the stages (U38) |

## Checks

| Name | Invariant |
|---|---|
| `counts` | Per source table, `source = imported + skipped + archived + excluded` |
| `one-owner` | Exactly one owner per team that has members |
| `board-consistency` | A card's column, a vote's board and a comment's board agree with the card's board |
| `poker-rounds` | `(session, number)` unique, sort keys dense from 0 per session, no unlocked vote on a revealed round |
| `markup` | Every card, comment and action-item body passes `MarkupLimits.Check`, is canonical, and its `Doc` holds only retro node kinds |
| `jira-config` | Every `team_jira_config` box is sealed with the active key, opens, and holds `{"email","token"}` |
| `password-hashes` | Imported bcrypt hashes equal the source hashes by SHA-256 |
| `display-names` | No `principals.display_name` looks like an email (`DisplayNames.LooksLikeEmail`) |
| `foreign-keys` | One explicit "no target missing" query per foreign key in `public` and `archive`, generated from `pg_constraint` |
| `anonymity` | No blob referenced by an anonymous card or comment, and no action item of an anonymous card, has a `created_by` |
| `sealed-archive` | Every non-null value of a column in an explicit `seal` list is `{"sealed": "…"}` or `{"stripped": true}` in `archive.rows` |

## Decisions where the spec was silent or did not fit

1. **`VerifyContext` gained two init-only properties** (`Keys`, `Run`) in U38's `Map/Common.cs`, and
   `Source/ImportRunner.cs` sets them. The Jira check needs the production keyring, and the hash check needs the source
   snapshot. `IVerifyCheck` had no way to reach either. Inside `run`, `Run` is the `ImportContext`. In the `verify`
   verb, `Run` is null and `Keys` comes from `APP_KEYS`/`ANON_TAG_KEY`, so **`verify` now requires those two variables**
   (the operator has them, §h.1). These are the smallest edits that make the checks possible. The record's positional
   shape is unchanged.
2. **Checks that need the source run differently in `verify`.** `password-hashes` compares each kept user with its
   own `auth.users` row inside `run`, and records the fact `passwordHashes` = `{count, sha256}` (SHA-256 over the sorted
   `id:sha256(hash)` lines). `verify` has no source, so it compares the target with the last successful run's digest.
   `counts` checks the in-memory report inside `run`, and the stored report of the last successful run in `verify`.
   `verify` is meant for the window between `run` and `cutover`. After cutover, users change passwords, and the hash
   check reports that, as intended.
3. **"Compared with the `plan` dry run."** `source` is the snapshot's own `count(*)`, the number `plan` prints for the
   same instant, so the counts identity inside the run is that comparison. A separate rolled-back dry run would read
   the same numbers again.
4. **Which avatar a user gets.** `profiles.avatar_url` decides. The original uploaded `avatars/<user id>.png` and then
   saved its public URL into the profile, but only when the profile form was submitted. An object that the profile does
   not point at was therefore never the user's avatar (an upload whose save was cancelled), and it is recorded as
   `skipped` (`not_profile_avatar`). Only the URL's path is compared (`…/storage/v1/object/public/avatars/<name>`, and
   `<name>` must be the user's own id). The host is ignored, because the bytes come from the staged cache, which U38
   fetched from `IMPORT_STORAGE_URL`. An `avatar_url` that is neither this nor an allow-listed Google URL is skipped as
   `not_allowed`. Bytes missing from the cache are `not_staged`. The SHA-256 and the magic bytes are checked again
   (`cache_corrupt`, `not_image`), because the cache outlives runs. Each skip is counted
   (`storage.avatars.skipped.<reason>`) and listed in `skippedAvatars` with the user and the URL host.
5. **Manifest dispositions.** For every `storage.objects` row: `imported` (an avatar that became a blob, with its sha256
   and `blob_id`), `skipped` (a kept user's own avatar object that was not imported, with its reason as the
   `storage.objects` skip reason), and `manifest_only` for everything else, counted as `archived` in the
   `storage.objects` tally. Google avatars are not storage objects and have no manifest row. Rows with a null bucket or
   name are counted as skipped (`unnamed`).
6. **Avatar blobs** have `attached_at` NULL, as the server's `BlobsRepo.InsertAvatarAsync` writes them (the
   unattached-blob GC only touches board images). `created_by` is the user, and `created_at` is the import time.
7. **One-owner** applies to teams that have members (U39 decision 11). U39 already lists memberless teams as
   `teamsWithoutMembers`, so this check does not list them again.
8. **The FK check covers `public` and `archive`**, and follows MATCH SIMPLE (a key with a null column references
   nothing). It names each constraint, the count, and up to three offending keys. Most foreign keys are immediate, so
   their violations already fail the offending statement. The check matters for the deferrable ones (spotlight,
   current round, focus card, sort keys), which would otherwise surface only as one COMMIT error.
9. **Soft checks** stay with the stages that observe them (counters and findings in the report, printed by
   `WriteSummary`). UF8's `malformed_identity_data` skip reason and `poker.nullAveragePoints`/`pokerNullAveragePoints`
   flow through the same report and need nothing here.

## Spot-load (outside the owned paths)

- **`tests/Retroscope.Importer.Tests/Retroscope.Importer.Tests.csproj`** gained a `ProjectReference` to
  `Retroscope.Server` with `Aliases="server"`. The Check runs "`retroscope spot-load` in-proc against the output DB" in
  the importer tests. Without the alias, the server's public `Program` would collide with the importer's in U0's
  scaffold test. The importer assembly itself still references no server code (that scaffold test passes).
- `retroscope spot-load` is U27's `Hosting/SpotLoadCommand.cs`, which is written in the same wave and was a stub on
  `main`. `EndToEnd/SpotLoadTests.cs` therefore does what §h.5 describes directly. The target database is migrated by
  the server's own `Leader` (its migrator, as in production), and the importer runs into it. A fresh leader then loads
  up to 20 random ids per kind through `PokerStore`, `RetroStore` and `TeamStore` on the app role, and projects each one
  for an anonymous viewer through the wire JSON contexts. **Integrator:** once U27 lands, the test can also call
  `SpotLoadCommand.RunAsync` against the same database.
- The server's migrator sets role-level timeouts on the role that runs it. The test therefore uses its own superuser
  role `spot_owner`, so the container superuser keeps the database-level timeouts that
  `RunTests.A_long_transaction_survives_database_level_timeouts` depends on.

## Tests (`Category=EndToEnd`)

- `RunVerifyTests`: `run` then `verify` green with every discovered stage and check, plus the counts identity, the
  memberless team, and foreign tables only counted. A second run produces the same rows in every public table and the
  three per-run archive tables. Values the run stamps with its own time, link-invite expiry (time + 7 days), the Jira
  and invite boxes, and rotated board password hashes are masked. A dangling deferred reference is named before COMMIT,
  and the run rolls back. Anonymous posts reach no principal in any table.
- `CorruptionTests`: one clean import, then 15 corruptions, each on a `create database … template` copy. Each one is
  caught by the check that owns the invariant and by no other check.
- `StorageTests`: avatars attached and the manifest dispositions. Staging killed after one object resumes without
  fetching it again, and the run attaches both avatars. Without staging, nothing is attached and the run says why.
  Plus a table of `AvatarKey` cases.
- `SpotLoadTests`: every sampled poker session, board and team loads and projects.
