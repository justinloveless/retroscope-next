# U41 decisions: retro mapping and HTML

U41 owns `Importer/Map/{Retro,ActionItems}Map.cs`, `Importer/Html/**` and `tests/Retroscope.Importer.Tests/Retro/**`.

## Public surface (for U42)

| Type | Use |
|---|---|
| `RetroMap` (stage 400) | `retro_boards` (+ config), columns, cards, comments, votes, readiness, `mentions`, board `blobs`, synthetic guest principals |
| `ActionItemsMap` (stage 450) | `team_action_items`; reads the imported boards and cards back from the target |
| `HtmlToMarkup.Convert(html, HtmlContext)` | HTML → canonical markup, the final `Doc`, the base64 images it still references, and the losses to report |
| `HtmlToMarkup.BlobId(board, sha256)` | `v5(blob:<board>:<sha256>)` under namespace `120c1200-15f7-444a-8830-c25291d55aa1` (frozen) |
| `BoardImages` | Collects extracted images and writes them as attached board blobs |

Both stages need U39's users, teams and team members in the target first; they read `teams` and `team_members`
from the target, not from the source.

## Decisions where the spec was silent or did not fit

1. **The vote recount compares rows, not the counter.** §h.5 asks for "card vote recount vs source `votes`", but
   U38's `expected-columns.json` puts `retro_items.votes` in `omit` (never read), and that file is not U41's. The
   recount therefore compares each imported card's votes with the source `retro_votes` rows that point at it, and
   reports every card where they differ (`counters.retroVotes.recountDrift`, `findings.voteRecount`). A drift means
   votes were lost to merges (two accounts of one person voting), missing voters or duplicates. The old counter was
   maintained by a trigger on those same rows, so it adds nothing a reviewer can act on. If the operator wants it,
   U38 can move `votes` from `omit` to `archive`.
2. **Converter output is built as a `Doc`, not as text.** The walker produces Core `Doc` nodes and lets
   `MarkupWriter` do all escaping; the result is then normalised as `Write(Parse(x, Retro))` and validated with
   `MarkupLimits.Check`. Text from the HTML can never become markup syntax, so pasted `*`, `[`, `&lt;div&gt;` and
   `javascript:` text stay literal text.
3. **Edge whitespace moves outside emphasis.** `<b> x </b>` becomes ` **x** `, because emphasis cannot open before or
   close after whitespace in the grammar; without this the bold would be lost to escaping.
4. **Headings and rules are text only but still separate paragraphs.** `HtmlTagPolicy` lists `h1`–`h6` and `hr` as
   text-only (the retro dialect has no headings or rules); they flush the paragraph before and after so a heading
   does not run into the next line. Other text-only tags are transparent.
5. **A tag outside the policy throws.** The histogram has already refused such a run; reaching one in the converter
   is a bug, not a silent text fallback.
6. **Plain-text bodies.** A body with no `<` predates the rich-text editor; its newlines become line breaks (blank
   lines become paragraphs) and entities are still decoded.
7. **Images.**
   * Only base64 PNG, JPEG and WebP by magic bytes (`ImageSniffer`), at most 2 MiB, at most `MarkupLimits.ImagesPerBody`
     per body. Anything else becomes the text `[image removed]` and is counted as `html.<table>.<loss>`.
   * The same image twice on a board is one blob (the id is derived from board and sha256), which also lets an action
     item and its source card share a blob. A blob's `created_by` is NULL as soon as any anonymous body on the board
     uses it, so a shared image cannot name an anonymous author.
   * Every extracted blob is written with `attached_at = import time`; otherwise the unattached-blob GC (S7) would
     delete them after 24 h.
   * An action item whose source board is gone has no board to own an image, so its images are removed.
   * Truncation can cut images off; only blobs the final markup references are written.
   * Non-data `img` sources become an `[image](url)` link for http(s), and the text `[image]` otherwise.
8. **Mentions.** `[[mention:<uuid>:<name>]]` tokens and `span[data-mention-id]` both become mention tokens when the
   uuid is an imported user (following duplicate-email merges, so the token carries the kept id); anything else
   becomes `@name`. `mentions` rows are written only for members of the board's team (none for quick boards). Mention
   names are kept as written, since renderers re-resolve them.
9. **Over-long bodies** keep as much canonical markup as fits and end with a paragraph `…(truncated on import)`. Each
   one is listed in `findings.truncatedBodies`.
10. **Authorship.**
    * "Anonymous" is `author = 'Anonymous'` (the column default, which the old client also wrote for anonymous posts),
      with or without `author_id`. An anonymous post stores only `anon_tag = HMAC(board ‖ poster)`, where the poster is
      the kept user or the synthetic guest of its `session_id`; `author_id` and `legacy_author` stay NULL. When neither
      resolves, the post is anonymous with no tag.
    * A guest principal is created only when a column references it (a named guest post, a vote or a readiness row),
      never for an anonymous post. It is named by the latest non-anonymous `author` it posted under, scrubbed (S27);
      a guest that only voted is `Guest`. Guests are inserted with `on conflict do nothing` because the poker stage
      can derive the same `v5(guest:…)`.
11. **Boards.**
    * A `room_id` that does not match the target's code check (`^[A-Za-z0-9-]{3,64}$`, e.g. a URL fragment that
      auto-created a board) is replaced with the board id and listed in `findings.recodedBoards`.
    * A `team_id` that was not imported makes the board a quick board (`counters.retroBoards.teamMissing`), and then the
      quick-board password rules apply.
    * A private quick board with no password is treated like the SHA-256 case: an unknowable password, listed.
    * The rotated plaintext is sealed with `ArchiveWriter.Protect("public.retro_boards", <board id>, "rotated_password",
      …)` in `findings.rotatedBoardPasswords`, together with the board code and the (mapped) creator.
    * `timer_duration_seconds` of 0 or NULL means "never set" (the source default is 0), so the board gets the target
      default of 15 minutes rather than §h.2's 1 s minimum, which applies to positive values only.
    * `max_votes_per_user` below 1 is unlimited (NULL); above 99 it is 99.
    * `last_activity_at = updated_at`.
12. **Columns.** The sort key is a dense rank from 0 (the domain's first key) over `(position, sort_order,
    created_at)`, with the id as the final tie-break so keys stay unique. Unknown colours (e.g. `bg-teal-100`) become
    `gray`.
13. **Cards on a column of another board** take the column's board (`counters.retroItems.boardFromColumn`), so every
    card's column belongs to its board.
14. **Readiness** rows that are not ready, or are for another stage than the board's, are archived whole; rows whose
    board was not imported are skipped.
15. **Action items** link `source_card_id` (with `source_version = 1`) only when the card was imported. An action item
    whose source card is anonymous gets `created_by = NULL` even when the source names its creator.

## Tests

`dotnet test tests/Retroscope.Importer.Tests --filter Category=RetroMap` runs:

* `HtmlToMarkupTests`: formatting, hostile HTML (scripts, styles, iframes, event attributes, `javascript:`/`data:`/
  protocol-relative links, SVG data URLs), the DocNode invariant on escaped tags, mentions, images and their limits,
  truncation, empty bodies, canonical output, and a deterministic fuzz of 3,000 tag soups;
* `RetroMapTests`: a fake source with every case, imported by the retro stages behind a seed stage that stands in for
  U39 (users, teams, members in the target): visibility per case with the sealed rotated password opened by the test
  key, config inlining, columns, authorship and anonymity (anon tags checked with the run's own `IAnonTagger`), blobs,
  action items, mentions, the DocNode invariant over every imported body, the vote recount, readiness, and
  `source = imported + skipped + archived` for every retro table.

The source fixture drops `idx_retro_columns_action_items_per_board` to model a live database that lacks it (the
column flag was never switched atomically), so the "more than one action-items column" rule has a case.

## Amendments (UF8)

- **Blob creators (decision 7).** A blob already in the target loses its `created_by` only when this stage saw it in an
  anonymous body. `BoardImages` tracks that flag per blob. A body whose author simply did not resolve (a deleted
  account, say) inserts NULL for a new blob, but no longer clears the creator of an existing one.
- **Markdown links in text** (`[label](href)`) go through the same `IsLinkable` checks as `<a href>`: at most 2048
  characters, no control characters or spaces, and `http`, `https` or `mailto`. A token that fails stays literal text.
  `mailto:` tokens are now recognised; before, they stayed escaped text.
- **Guests (decision 10).** A UUID-shaped `session_id` maps through `SyntheticIds.Guest(Guid)`, the poker stage's
  overload, so the guest is one principal across both stages whatever case the browser stored. Other keys hash as
  before.
- **Column colours** use `ColumnPalette.FromTailwind` from `Map/Common.cs`. `RetroText.Color` is gone.
