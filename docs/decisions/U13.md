# U13 decisions: actor runtime

U13 owns `src/Retroscope.Server/Realtime/Actors/**` and its tests in `tests/Retroscope.Integration.Tests/Actors/**`
(§k lists no test path for U13; the Check runs `Category=Actors` in the integration project, so the tests live there).

## Public surface (for U14, U15, U21–U23, U25, U27)

| Type | Use |
|---|---|
| `IRoomBinding<TState, TInput, TEvent>` | What a room kind plugs in (U21–U23): domain, `FromClient(Command)`, `DurabilityOf`, `CanSubscribe`, `IsMember` (snapshot variant), `Snapshot`/`Overlay`/`Project`, and optional `Supersedes`, `WarmUntil`, `IsDeleted`, `OnShutdown`, `TracksPresence` |
| `IRoomStore<TState, TEvent>` / `SqlRoomStore<TState, TEvent>` | Load a room, load a cursor, commit. Stores subclass `SqlRoomStore` and implement `LoadAsync` and `Plan(room, stateBefore, committedEvents)`; the base runs the plan plus `CursorRepo.Upsert` through `Leader.CommitFencedAsync` |
| `ActorsModule.AddRoom(binding, store)` | How a room unit registers its kind (the `IAccessView` comes from the container, U23) |
| `ActorRegistry` | `SubscribeAsync`, `CommandAsync`, `Unsubscribe`, `ConnectionClosed`, `AccessChanged`, `PrincipalUpdated`, `Post<TState,TInput>` (live rooms only), `AskAsync`, `QueryAsync`, `TryPurgeAsync`, `ShutdownAsync` |
| `IRoomPeer` + `OutboundBuffer` | The connection as an actor sees it (U14 implements `IRoomPeer`); `OutboundBuffer` is the 1 MB byte-bounded queue that closes with 4008 |
| `RoomView<TState>` | What a query sees; `SnapFrameAsync(viewer)` is the boot snapshot (U25) |
| `AskResult` | `Accepted(seq)`, `NoOp`, `Rejected(code, detail, data)`, `NotFound`, `Unavailable` |
| `RoomActor<TState, TInput, TEvent>` | Public so the simulation (U15) can run actors without the registry |

## Decisions where the spec was silent or did not fit

1. **The ring stores projected frames, not domain events.** §c.3 says replay sends missed tx frames "re-projected
   for this viewer", but projections read the state after the events (retro: `ForViewer(stateAfter, …)`), and that
   state is gone by the time a client resumes. So each tx is projected once per *audience* (principal + snapshot
   variant) for every subscriber and every principal still inside the presence grace, serialized once, deduplicated
   by content, and the ring keeps those `ev` arrays. A replay is sent only when every missed tx was built for the
   resuming principal's audience; otherwise the client gets a snapshot. That is never wrong, and a client that
   reconnects within the 10 s grace still gets a replay.
2. **Spotlight coalescing** (§c.8) keeps the superseded entry's seq with an empty `ev` instead of removing it, so
   seqs in the ring stay gapless (§c.3 `s == last + 1`). `IRoomBinding.Supersedes` decides what supersedes what.
3. **The external queue uses `BoundedChannelFullMode.Wait`**, not `DropWrite` as §c.7's sketch shows: with
   `DropWrite`, `TryWrite` returns true and drops the item, which would lose the command instead of nacking
   `server_busy`. With `Wait`, `TryWrite` returns false on a full queue and the actor nacks at once (R26).
4. **New subscriptions use the external queue, resumes the internal one.** A `sub`/`hello` entry with an epoch is a
   resume (§c.7's "Subscribe(Resume)"), so a reconnect storm is never refused. A new subscription on a full queue
   returns `PostResult.Busy`; there is no nack for `sub`, so the transport decides (see follow-ups).
5. **Asks and queries complete after the actor rescheduled its timers**, so an HTTP caller (and a test) sees the
   whole effect of its input, timers included.
6. **A timer fires at most once per request.** `ActorTimers` remembers the last request that fired per key and does
   not re-arm an identical one (same due time and payload) even if the domain still returns it. Without this, a
   domain that no-ops a due timer but keeps asking for it would spin.
7. **Commit failure classification** (R2, §c.6): `CommitRejectedException` (the store's wrapper for a
   `PostgresException`, such as a constraint or a deferred FK at `COMMIT`) nacks `internal`; `FencingLostException`
   and every other exception (unknown outcome, connection refused, timeouts) poison the actor: `bye` + 1012 to every
   subscriber, state, presence, timers, cursor cache and ring dropped, reload with a new epoch on the next message.
   A load failure abandons the message the same way (subscribers restart, asks get `Unavailable`).
8. **Kick codes.** A subscription over `ConnectionsPerPrincipal` (6, §c.7) is kicked `forbidden`; a missing or
   deleted room `not_found`; a deleted room's subscribers `deleted`; `AccessChanged` kicks `access_revoked`.
   A subscriber whose snapshot variant changes (joined or left the team) gets a fresh `snap`.
9. **Presence.** First connection → `Joined` + `presence.join`; a reconnect inside the grace cancels the pending leave
   silently (`ClientConnected`); a tab disconnected for the grace → `ClientGone` (no wire event, even after the
   principal left); the principal's grace expiring → `Left` + `presence.leave`. Domain events from `OnPresence` are
   committed in their own transaction (no cursor) and travel in the same tx frame as the presence event.
10. **No `last_activity_at` bump, no `recent_activity` upsert here.** The bump is per room table, so stores add it to
    their plan (U12 decision 4). §c.5's `recent_activity` belongs with the activity repo (U24) or the transport.
11. **Frames are byte arrays shared between peers**, not pooled segments: every peer of an audience gets the same
    `byte[]`, which keeps the "serialized once" property without reference counting.
12. **`Post` only reaches live actors.** A room that is not live loads the posted change from the database when it
    next starts (action items are created in place, roster and settings are read at load), so starting an actor
    just to post to it would only cost a load.
13. **`EventDurability` is reused from `Core/Poker`**, the one place the three durabilities are defined; retro and
    team bindings return `Committed` (the default).

## Follow-ups for other units

- **U14:** implement `IRoomPeer` over `OutboundBuffer` (`Send` → `TryEnqueue`; close the socket with
  `Buffer.Closed`'s code), and `Restart()` as `bye{restart, retryMs}` then close 1012. Route `hello` subs through
  `ActorRegistry.SubscribeAsync(…, e, s)` (resume) and `sub` frames without `e` as new subscriptions; on
  `PostResult.Busy` for a new subscription, retry after a short delay or close 1012. Call `ConnectionClosed` for
  every room on close. `CommandAsync` already nacks `server_busy` itself.
- **U21–U23:** register with `services.AddRoom(sp => binding, sp => store)`; stores subclass `SqlRoomStore`. The
  poker binding maps `PokerCommand` with the implicit `PokerInput` conversion, `DurabilityOf` → `evt.Durability`,
  `Supersedes` → all `SpotlightMoved`, `WarmUntil` → `state.WarmUntil`, `OnShutdown` → `SpotlightSettleDue` when the
  spotlight is dirty (`PokerRuntimeTests.Binding` is a working sketch). The retro binding caches nothing itself:
  `IsMember` picks the variant and the runtime caches both shared snapshots per seq.
- **U25:** the boot snapshot is `ActorRegistry.QueryAsync(room, view => view.SnapFrameAsync(viewer))` with a 400 ms
  token.
- **U27:** retention calls `ActorRegistry.TryPurgeAsync(room, deleteRows)`; it returns false while anyone is
  subscribed or a message is queued, and nothing can load the room until the delete finished.

  domain (vote secrecy on replay, auto-reveal once).

## Amendment (UF7)

1. **Views of a missing room.** `RoomActor.View()` returns `RoomView.NotFound` for a missing, deleted or unloaded room:
   `Found` is false, `CanSubscribe` is false for everyone and `SnapFrameAsync` throws `InvalidOperationException`. A
   found view's delegates capture the state they were built for, never the `_state` field, so a view kept past a
   poison answers from that state instead of throwing `NullReferenceException`.
2. **Access recheck.** A cursor that cannot be loaded while `AccessChanged` re-snaps a subscriber whose variant changed
   restarts that peer only (`Leave` + `Restart`); the room keeps its other subscribers and its state.
3. **Purge refusal.** `TryPurgeAsync` is refused while anything waits on either queue (`_internal.Reader.TryPeek`; the
   single-reader unbounded channel does not support `Count`), not only the external one. A resume or an ask behind the
   purge would otherwise load the room into the next incarnation while the purge deletes its rows. Messages that
   arrive in the instant between that check and the close still go to the next incarnation, as before.
4. **Retiring without retries.** The fixed 100-attempt loop is gone. A retiring actor closes its queues inside
   `ActorRegistry.Retire`, under the registry lock, in the same step that removes it and installs the next incarnation
   with its leftovers. A sender that got `PostResult.Closed` re-reads the key under that lock and therefore always finds
   the next incarnation (or none, and starts one); it never spins on the closed actor. The only wait left is for a key
   being purged: `ActorOptions.IncarnationWait` (5 s). Past it the caller gets a retryable `server_busy`: a command is
   nacked `server_busy` and `CommandAsync` returns `Busy`, `SubscribeAsync` returns `Busy` (the transport decides, as
   for a full queue), `AskAsync` returns `Unavailable` with code `server_busy`, and `QueryAsync` throws
   `RoomUnavailableException`. `GetOrStartAsync` throws `IncarnationTimeoutException` (a `TimeoutException`) then.
5. **Tests.** `PokerRuntimeTests` starts its room in `IAsyncLifetime.InitializeAsync` instead of blocking on `.Result`.
