# U34 decisions: retro board core

U34 owns `web/src/retro/{index,model,board,column,card,comments,composer}.js`, `web/styles/retro.css` and
`tests/e2e/fake/retro-board/**`.

## Contracts later units rely on

1. **`mount(root, boot, app)`.** The route module takes an optional third argument `{socket}`, the tab's one
   socket from `createSocket` (U28 decision 1). **U29:** pass it from `entry.js`. Without it (today's entry stub)
   the module creates, starts and on `unmount()` stops a socket of its own, so the page works either way.
2. **Boot JSON for `/retro/:code`.** `boot.room = {r: 'board:<uuid>', access?, e?, s?, d?, o?}`. With `d` the
   board paints from it before the socket answers (`room.seed`), and the first `hello` carries `{e, s}`; without
   `d` the socket delivers the snapshot. `access` defaults to `granted`. When `boot.room` is missing or names
   another code (in-app navigation), the module asks `GET /api/retro/by-code/{code}` → `{id, access}`:
   `password` shows an unlock form (`POST /api/retro/{id}/unlock {password}`), `signin` links to
   `/login?return=…`, anything else reads "This board does not exist". **U25/U11:** write `boot.room` in this
   shape (the snapshot members as `snap` sends them).
3. **The model (`model.js`)** follows the U28 model contract: `snapshot(d, o)`, `apply(state, {k, d})` and
   `optimistic(state, k, d)` (via `createRetroModel({me, now})`). State is immutable: cards, comments, votes
   and presence are `Map`s by id, `mineCards`/`mineComments`/`myVotes` are `Set`s, `focus` is an id or null.
   `toWire(state)` writes `{d, o}` in the server's canonical order, which is what the goldens compare.
   - `retro.timer` keeps the normalised timer (an idle timer has no `endsAt`) and records the one-shot expiry as
     `state.expiredAt` (the `endsAt` it carried). **U35:** play the alarm when `expiredAt` changes, at most once
     per `endsAt`.
   - `retro.endorsement.added` with `celebrate` sets `state.celebrate` to the endorsement id. **U36:** celebrate
     when it changes.
   - `retro.readiness.ready` is kept as sent; **U35** intersects it with `state.presence`.
   - `retro.members` replaces the roster; `card.added`/`comment.added` are upserts; a `retro.vote` without
     `voters` clears them (U8 decision 15).
   - `intent(state, k, d, {me, now})` is the optimistic effect for `retro.card.add/edit/delete`,
     `retro.vote.set`, `retro.comment.add/delete`, `retro.column.reorder`, `retro.ready.set` and
     `retro.focus.set`. Role and gate helpers (`isFacilitator`, `isMember`, `allowsContent`, `allowsVoting`,
     `mayPostAnonymously`, `votesLeft`) mirror `RetroRoles`/`StageRules` for what the page offers; the server
     stays the authority.
4. **Feature slots for U35 and U36.** `index.js` passes `FEATURES` (an empty array) to `createBoard`. A feature is
   `{board?(ctx, slots) → {update(view), destroy()}, card?(ctx, card) → {el, update(card, view), destroy()}}`.
   `slots` are `toolbar` (header), `top` (above the columns: stage bar, focus banner, timer) and `before` (the
   start of the column row: previous action items). Card extras sit in the card's action row. `ctx` carries
   `room`-backed `view()`, `me()`, `now()` (server clock), `send(k, d, opts)` (with the optimistic intent),
   `command(k, d, opts)` (no intent), `mentions()`, `person(pid)`, `upload`, `drafts` and `draftKey`. U35/U36
   add their import and one `FEATURES` entry to `index.js` (a one-line change request to U34, or the
   integrator's).
5. **Drafts** are `sessionStorage['rs.draft:<boardId>:card:<columnId>']` and `…:comment:<cardId>`, holding
   `{body, anonymous}`. A column or thread with a draft opens its composer on load.

## Decisions where the spec was silent or did not fit

1. **The editor ships inside a lazy `composer` chunk, not as an `editor` chunk.** `build.mjs` measures a lazy
   chunk with its whole static closure minus the entry, so a lazily imported `markup/editor.js` was charged for
   the `parse`/`render`/`doc` chunk that the retro chunk had already loaded: 12.5 KB against the 8 KB `editor`
   budget, which fails the build (> 10 % over). The editor's own bytes were 6.7 KB. `composer.js` (owned here)
   imports the editor statically and is the module loaded with `import()`, so the editor still stays off the
   board's first paint and loads in its own chunk (composer + editor: 7.3 KB brotli on its own, 14.6 KB with the
   shared markup chunk; no baseline, so printed but not judged). The board prefetches it right after the first
   paint, so a click on "Add a card" rarely waits. Card editing loads the same chunk. **U10:** measure lazy chunks
   net of what their importer already loaded; then `card.js` can import `markup/editor.js` directly again and
   the `editor` line in `budgets.json` judges it. **U33:** the jira drawer meets the same measurement.
2. **No `<select>` on the board.** In WebKit (desktop and iPhone) creating any `<select>` element reports a
   `style-src-attr` violation under the production CSP (its user-agent shadow tree carries an inline style;
   reproduced with a bare `document.createElement('select')`). The column sort is a menu button and the column
   colour is a radio group of swatches. **U10:** `ui/select.js` has the same problem on WebKit; **U35/U36**
   should avoid `<select>` too.
3. **Facilitator UI.** Column tools, rename and add column show for `isFacilitator` on a board that is not
   archived. Deleting a card shows for its author while content is allowed, or for a facilitator in the
   action-items column (§c.4). Card and comment deletes and column deletes ask for confirmation; the original
   used `confirm()` for columns only.
4. **Optimistic kinds** are §g.4's list plus `retro.comment.delete`, which costs nothing to show at once.
   Column add, update, delete and `setActionItems`, and board rename, wait one round trip.
5. **Stale handling.** Card edit: a dialog shows the latest and the user's text, with "Keep latest", "Edit
   mine" (the editor reopens with the user's text against the latest version) and "Use mine" (resend against
   the latest version). Column reorder: rebased once by U28's `rebase` (the moved column is put back at the
   index the user chose among the fresh columns). `retro.column.update` stale is toasted ("Someone changed this
   first"); the fresh column is already shown.
6. **A refused post** (`retro.card.add`, `retro.comment.add`) goes back into its composer and draft, after
   anything typed since (separated by a blank line), and the nack is toasted too.
7. **Mention pills re-render** when the roster changes: a body containing `[[mention:` repaints when
   `members` or `presence` change identity, so a rename shows at once. Names come from team members, then from
   presence; the `@` listbox offers team members only (quick boards record no mentions, U8 decision 11).
8. **Image upload errors**: 409 `board_quota`, 413 `too_large`, 415 `unsupported_media_type`, 507
   `storage_full` (and `stage_forbids`, `board_archived`, `rate_limited`, offline) each get a sentence; the
   editor's placeholder goes and the text stays.
9. **Column sort** is per viewer and per page view (in memory), defaulting from `sortChronologically`.
   `sortItems` ports `RetroColumn.tsx:50-64` (`localeCompare` for authors); an anonymous card sorts as
   "Anonymous", a hidden author as the empty string.
10. **Pending spinner and offline banner.** Every 500 ms the board marks elements (`li`/`section` with the
    command's `cardId`, `commentId` or `columnId`) whose outbox entry is older than 1.5 s with
    `.retro-pending`/`aria-busy`, and shows "Reconnecting… your changes are saved and will sync" after 10 s
    offline.
11. **Column reorder by pointer** uses the grip only (`touch-action: none`): 8 px of mouse movement or a 300 ms
    long press on touch starts it; the dragged column fades to 0.5 and the drop target scales to 1.05 with an
    indigo ring. ArrowLeft/ArrowRight on a focused grip move it one place and keep focus on the grip.

## Verification

- `./build.sh fake-e2e "retro-board/*.spec.js"`: 177 passed, 27 skipped (the Node-only golden checks run in the
  chromium project only), on chromium, firefox, webkit and mobile-webkit.
- Goldens: every `tests/golden/transcripts/retro-*.json` folds through `model.js` to its `expectedViewerState`
  (after normalising an idle timer, as the C# model does), and all 2,000 `retro-sort.json` cases sort as the
  original. One transcript is also replayed into the page and its final board checked in the DOM.
- Repeated runs (`--repeat-each 3` twice over all four projects, `--repeat-each 4` on firefox): one failure in
  about 1,100 runs (firefox, "voting follows the stage…", a 1.4 s failure whose report was not kept); 20 targeted
  repeats did not reproduce it.
