# U4 decisions: Retro Markup (C#)

U4 owns `src/Retroscope.Core/Markup/**`, `tests/fixtures/markup/**` and `tests/Retroscope.Core.Tests/Markup/**`.
The precise grammar, the Doc wire shape and the fixture format are in `tests/fixtures/markup/README.md`. That file is
normative for U5 (`web/src/markup/parse.js`) and for anyone who changes the grammar.

## Public surface (for U5, U6, U8, U22, U25, U26, U41)

| Type | Use |
|---|---|
| `MarkupParser.Parse(text, dialect) → Doc` | Total: never throws, malformed syntax is text |
| `MarkupWriter.Write(doc) → string` | Canonical markup; `Parse(Write(d))` equals `d` for any parsed `d` |
| `MarkupLimits.Check(text, field) → MarkupCheck(Doc?, MarkupError?)` | The validation entry point for every stored body; returns the parsed Doc |
| `Mentions.Extract(doc)` | Distinct mentioned user ids in document order (callers filter to team members) |
| `Doc.Descendants()` | Walks every node, e.g. `OfType<DocImage>()` for the `blob:` refs a card attaches |
| `DocJson.Write/Serialize`, `[JsonConverter(typeof(DocJsonConverter))]` on `Doc` | The wire shape; any `JsonSerializerContext` that includes `Doc` uses it. Docs are write-only (reading throws) |

## Decisions where the spec was silent or did not fit

1. **Three dialects.** §g.6 gives one grammar, §f adds `[[island:id]]` "only in Jira descriptions" and needs headings
   and rules to round-trip ("paragraph, heading, lists, codeBlock, blockquote, rule"). So: `Retro` (cards, comments,
   action items) has mentions and board images but no headings, rules or islands. `Jira` (comments, new issues) has
   headings (`#`–`######`) and rules (`---`) but no mentions or images. Our mention tokens carry principal uuids, not
   Atlassian account ids, and `blob:` images are board blobs. `JiraDescription` is `Jira` plus top-level island lines.
   Outside its dialect a token is plain text, never an error.
2. **Jira mentions are not in the markup.** §f lists ADF `mention` as round-trippable, but the markup has no token for
   an Atlassian account. U6 should make a paragraph that holds an ADF mention an island (lossless, read-only), or ask U4
   for a Jira mention token if editing such paragraphs matters.
3. **One closed Doc for markup and ADF.** §a puts `DocNode` in `Core/Markup` and §f says `AdfToDoc` produces "the same
   DocNode tree". U6 cannot edit `Core/Markup`, so the ADF view kinds are defined here already: panel, table/tr/th/td,
   expand, task list, underline, status, attachment image (REST attachment id, §f F20) and island content. The
   constructors are `private protected`, so the set stays closed and every kind is allow-listed by construction (the
   importer's DocNode invariant, §h.5 S28, can switch on it). `MarkupWriter` throws for ADF-only kinds, because they reach
   the editor as islands. Dates, emoji, inline cards and unresolved media flatten to text or links in U6. If U6 needs a
   different shape, that is a change request to U4.
4. **Island ids** are 1–64 characters of `[A-Za-z0-9_-]`, so U6 can choose the exact encoding of
   `sha256(canonical ADF)[0..12]`.
5. **A single newline is a line break.** Shift+Enter inserts a newline in the editor (§g.6, parity), and users expect
   it to show. A blank line starts a new paragraph.
6. **Emphasis is deterministic, not CommonMark.** The delimiter algorithm in the README is a small, explicit
   rule set that the JS port can copy line by line. It differs from CommonMark in edge cases: emphasis never nests
   inside emphasis with the same delimiter (so `**a **b** c**` is bold `a **b` then text), and `***x***` is bold around
   italic. Intraword `_` is literal (`snake_case`), intraword `*` emphasises. No autolinks: a bare URL stays text.
7. **Links** need a non-empty label and an href without spaces, parentheses or angle brackets. A Wikipedia URL with
   parentheses needs `%28`/`%29`, and the writer encodes them. Scheme check is case-insensitive; `javascript:`, `data:`,
   `vbscript:` and protocol-relative hrefs stay text.
8. **Nesting caps.** Quotes and list items nest at most 16 deep and inline emphasis at most 16 deep. Deeper markers
   are text, so hostile input cannot exhaust the stack.
9. **Limits.**
   * Lengths count Unicode code points, matching Postgres `char_length` in the §b checks (8,000 card and action item,
     4,000 comment).
   * Jira text has no limit in the design, so it gets our own cap of 32,000 code points (a guard, not a claim about
     Jira's field limit).
   * "8 images per card" applies to every retro body, comments included.
   * `InvalidCharacter` refuses NUL and other C0 controls except tab, CR and LF, and unpaired surrogates: Postgres
     `text` cannot store NUL, and the others have no rendering.
   * CR and CRLF are accepted and read as LF.
   * Mapping a `MarkupError` to a nack code belongs to the domain units (U8, U26).
10. **Canonical writer.**
    * Blocks are separated by a blank line, except that a list follows a paragraph on the next line, so nested lists
      keep their typed shape.
    * Italic is written `_` (it cannot merge with a neighbouring `**`). It is written `*` where `_` is not a
      delimiter: next to a letter or digit, after another italic's closing `_`, or inside a `_` italic. When neither
      fits, the enclosing italic tries its other delimiter.
    * Text escapes ``\ * _ ~ ` [ ]`` everywhere. A paragraph line that would start a block is escaped at its start,
      and a text `!` before a `[` is escaped.
    * The editor (U34a) and the importer (U41) can therefore rely on `Write(Parse(x))` being stable.
11. **Mention names** are whatever the token says (1–100 characters, no `]`). They are never interpreted as markup,
    and renderers re-resolve them (§g.6). The writer drops `]` and newlines from a name it did not parse.

## Verification

* `dotnet test tests/Retroscope.Core.Tests --filter Category=Markup` runs these tests:
  * the corpus (each case: parse, write, re-parse, mentions);
  * 100,000 deterministic fuzz iterations (seed 20261020, all three dialects): no exceptions, only dialect-allowed
    node kinds, `Parse(Write(doc))` equals `doc`, and writing is a fixed point;
  * limit, dialect, wire-shape and hostile-input timing tests (every 8,000-character pathological body parses and
    writes in under 2 s; the slowest measured about 0.1 s).
* During development the fuzzer also ran 6.4 million further inputs across 16 seeds, with up to 80 pieces each,
  without a failure.
* Inline token lookups and the closer scan are memoised by absolute position. Without that, `**a **a …` took
  over 1 s at card size.
