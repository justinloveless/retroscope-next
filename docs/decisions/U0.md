## Verification spike results (DESIGN §12 rows owned by U0)

Measured with `./build.sh aot-smoke` on macOS arm64 (osx-arm64 AOT) and in the arm64 chiseled image build.

- **Npgsql under Native AOT:** `NpgsqlSlimDataSourceBuilder` with `EnableArrays()` + `EnableJsonTypes()` publishes with zero trim/AOT warnings. `update … from unnest($1::uuid[], $2::int[])`, a jsonb round trip passed as `string` with `NpgsqlDbType.Jsonb`, an `NpgsqlBatch` inside an explicit transaction (a failing statement leaves nothing committed) and auto-prepare (`Max Auto Prepare=50`, statement visible in `pg_prepared_statements`) all work. **Verified.**
- **BCrypt.Net-Next under AOT:** zero warnings; a `$2a$10$` hash of the 6-character password `abc123` verifies, a wrong password does not, new cost-10 hashes start `$2a$10$`. The vendored EksBlowfish fallback is not needed. **Verified.**
- **`System.Net.Mail.SmtpClient` under AOT:** constructing `SmtpClient` (STARTTLS flag, credentials) and `MailMessage` produces no warnings and runs. Sending over STARTTLS is not exercised here; U17 still owns that half of the §12 row.
- **Chiseled image:** the server image is 23.6 MB, runs as uid 1654 and serves `/healthz`; the binary's `healthcheck` subcommand works inside it (no shell or curl needed).
- **PG18 data directory:** the pinned image sets `PGDATA=/var/lib/postgresql/18/docker`, so the volume mount at `/var/lib/postgresql` in §i.1 is the right one. U43 still records it for the deployed stack.
- **Peak RAM of the AOT publish:** about 1.2 GB maximum RSS for `src/Retroscope.Server` on osx-arm64 (scaffold size; it grows with the code). `build.sh` prints it on every `aot-smoke` run, so CI logs carry the linux-x64 number. Either way, the 1 GB VPS could not do this, which is why images are built in CI.

## Decisions where the spec was silent or did not fit

1. **Test platform.** xunit.v3 4.x runs only on Microsoft.Testing.Platform, and the .NET 10 SDK no longer runs MTP projects through VSTest. `global.json` opts into `"test": {"runner": "Microsoft.Testing.Platform"}`, and the test projects drop `Microsoft.NET.Test.Sdk` and `xunit.runner.visualstudio`. The §k check commands still work as written: `dotnet test tests/<Project> --filter "Category=X|Category=Y"` (xunit.v3 accepts VSTest-style filters). A filter that matches no tests exits with code 8.
2. **Where module hooks live.** §k transfers each stub to the unit whose owned paths contain it, so the hooks (`AddServices`/`Map`) sit in files that units already own, not in separate `*Module.cs` files nobody owns. Where a unit owns a folder, the stub is `<Folder>Module.cs` (`Hosting/HostingModule.cs`, `Realtime/Actors/ActorsModule.cs`, `Realtime/Transport/TransportModule.cs`, `Auth/Email/EmailModule.cs`). Where a unit owns named files, the hooks are static methods on that file's class (`Data/Db.cs`, `Data/Leader.cs`, `Realtime/Rooms/{Poker,Retro,Team}Room.cs`, `Jira/JiraClient.cs`, `Endpoints/*Endpoints.cs`). The owner may make the class non-static, as long as the two static hooks keep their signatures. U27's jobs (`Jobs/{Retention,TokenSweep,TeamPurge}Job.cs`) are registered from `AdminEndpoints.AddServices`, and U17's `Jobs/EmailWorker.cs` from `EmailModule.AddServices`, so `Jobs/` needs no module of its own.
3. **JSON contexts.** No unit lists `Server/Json/**`, so each context transfers to the unit that uses it: `Hosting`→U11, `Auth`→U16, `Oidc`→U18, `JiraClient`→U19, `Blob`→U20, `PokerRoom`→U21, `RetroRoom`→U22, `TeamRoom`→U23, `TeamHttp`→U24, `RoomHttp`→U25, `JiraHttp`→U26, `Admin`→U27. HTTP request contexts use `JsonUnmappedMemberHandling.Disallow` (§d). The Jira-client, OIDC and room-store contexts skip unknown members, because they read documents written by Jira, the identity provider or an older/newer binary. Each stub carries one `JsonElement` registration, because the source generator emits nothing for an empty context. The owner replaces it.
4. **Subcommands in the frozen `Program.cs`.** `retroscope healthcheck` (compose healthcheck, §i.1) runs before the host is built and calls `Hosting/Health.ProbeAsync` (U11). `retroscope spot-load` (§h.5) runs after `Build()` and calls `Hosting/SpotLoadCommand.RunAsync(app, args)` (U27). U0 implemented `/healthz` as an unconditional 200 so the chiseled-image check has something to probe. U11 adds the leader and DB conditions. The probe port defaults to 8080 and can be overridden with `HEALTHCHECK_PORT`.
5. **Front-end route table** is `web/src/routes.js` (frozen, U0). Each route names its `module` next to its `import()`, and `build.mjs` fails if the two disagree. `manifest.json` maps each route path to its chunk plus that chunk's static imports, for `modulepreload`. `web/src/entry.js` (U29) is a minimal working stub so the build has an entry point.
6. **npm workspace at the repo root.** `web/package.json` keeps esbuild as its only dependency (§a), but Playwright specs live under `tests/e2e/` and the golden generator under `tests/golden/`, and from there Node cannot resolve packages installed in `web/node_modules`. The repo root therefore has a private `package.json` (workspace `web`, devDependency `@playwright/test`) and the single `package-lock.json`. Packages hoist to `/node_modules`, so every directory resolves them. The Docker web stage installs only the `web` workspace.
7. **Node version.** CI uses Node 22. `build.sh` passes explicit `*.test.js` file lists to `node --test`, so it also works on Node 20. Check commands that pass a directory to `node --test` need Node 22.
8. **AOT smoke harness** is a separate AOT console project, `tests/Retroscope.AotSmoke`, owned by U0. It is not part of the server, so the frozen `Program.cs` carries no test code. `./build.sh aot-smoke` publishes the server and the probe with zero tolerated warnings, runs the probe against a throwaway pinned Postgres container, starts the native server binary (with `DATABASE_URL`/`DATABASE_OWNER_URL` pointing at that container, for later units), and finally builds `deploy/Dockerfile` and checks `/healthz` on the chiseled image.
9. **Dockerfile architecture.** The build stage chooses the RID from `TARGETARCH` (`linux-x64` by default, `linux-arm64` on arm64 builders), so a local arm64 build is native. CI publishes `linux/amd64` only.
10. **`db/migrations/.gitkeep`** exists so that the Dockerfile's `COPY db/` and the server's embedded-resource glob work before U1 adds `0001_init.sql`.
11. **Scaffold tests** (`tests/*/Scaffold/**`, `tests/web-unit/scaffold/**`, owned by U0) guard the parts that later units must not break: the §a dependency rule, the importer never referencing the server, `Program.cs` calling both hooks of every module and chaining every JSON context, and every route loading a module that exports `mount()`. They deliberately do not boot the host, because later units make startup depend on Postgres.
12. **Fakes project.** `tests/Fakes/Retroscope.Fakes.csproj` is one ASP.NET library for both fakes. U19 owns `FakeJira/**` and U18 owns `FakeOidc/**` inside it.
13. **Docker socket.** `build.sh` uses whatever engine `docker` reaches. On this machine (Rancher Desktop without admin access) that means `DOCKER_HOST=unix://$HOME/.rd/docker.sock`. Testcontainers honours the same variable.
14. **`.gitignore`** gains `artifacts/` (AOT publish output and logs from `build.sh`).
