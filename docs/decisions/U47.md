# U47 decisions: golden vectors

## Layout

- `tests/golden/src/*.ts` holds the verbatim spans. Each span sits between `// golden-span <path> <start>-<end> 7f48a79 sha256:<hex>` and `// golden-span-end`. The hash covers the span's lines, each ending in `\n`. Lines outside the markers are glue. There is one: `export { TONES };` in `topic-summary.ts`.
- `make-golden.mjs` bundles each source file with esbuild, runs it on seeded random inputs (mulberry32) and writes `tests/golden/<name>.json` as `{source, seed, cases:[{<input>, expected}]}`, one case per line. `--verify` regenerates in memory and requires a byte-identical match. It also checks every span against its recorded hash.
- The original repository is found through `--orig <dir>` or `RETROSCOPE_ORIG`. Spans are read with `git show 7f48a79:<path>`, so whatever the original checkout currently has does not matter. Without the original, the copies are still checked against their recorded hashes. `./build.sh test` runs `--verify`, and the script picks up `RETROSCOPE_ORIG` from the environment.

## Where the spec did not fit

1. **Scoring span is lines 52-82, not 52-85.** At `7f48a79`, `getWinningVoteFromSelections` ends at line 82. Lines 84-85 are the doc comment and signature of `winningVoteToStoredAveragePoints`.
2. **Spans copied** (function spans only; erased TypeScript types are not needed to run them):
   - `usePokerSession.ts:52-82`
   - `jiraBrowseSprintBuckets.ts:1-61` (the whole file)
   - `RetroColumn.tsx:50-64` (`SortKey` + `sortItems`)
   - for the topic summary: `pokerSessionListStats.ts:3-105` (everything after the import) with its dependency `pokerRoundTicketPlaceholder.ts:6-11` (`isSyntheticRoundTicket`)
3. **Badge tone included.** `parentBadgeTone.ts:4-30` is also copied, and every badge in `topic-summary.json` carries `toneIndex` (0-11), the index into the original's 12 tones of `parentBadgeClassName(sessionTopicBadgeToneForParentClass(toneKey))`. The rewrite has its own CSS, so the index is what has to match, not the Tailwind classes.
4. **Case counts.** `poker-scoring.json` has 10,000 cases. The other three have 2,000 each. With 10,000 cases each, their inputs add up to about 20 MB of checked-in JSON. At 2,000, every branch is still hit hundreds of times (e.g. topic summary: about 300 `null`, 100 `various` and badges of 1, 2 and 3 topics).
5. **Input alphabet for collation.** Sprint names and retro authors are Title Case words, spaces, dots and digit runs without leading zeros. On that alphabet, ICU numeric `localeCompare` and an ordinal compare with numeric digit runs give the same order. That keeps the vectors stable across ICU versions, and `Core/Text/NaturalCompare` (U2, ordinal, F22) can be checked against them. Mixed-case names, lowercase-first names, other punctuation and leading zeros are left out on purpose, because there ICU and ordinal comparison disagree by design. `'backlog'` (lowercase) is never generated as a sprint name for the same reason.
6. **Dates.** Timestamps are ISO-8601 with `Z` or an explicit `±hh:00` offset. Sometimes the same instant is spelled both ways, to exercise ties. Invalid dates are only strings V8 rejects (`not a date`, `TBD`, `2026-13-40T00:00:00.000Z`). V8's legacy parser accepts strings like `Sprint 5` and reads them in local time, which would make the vectors depend on the time zone. Verified identical under `TZ=Pacific/Kiritimati LANG=tr_TR.UTF-8`, and on Node 22.23.3 / ICU 78.3 (pinned `node:22-alpine`) as well as Node 20.19.1 / ICU 76.1.
7. **Inputs are JSON round-tripped** before the original runs, so absent and `null` fields mean exactly what the JSON says. The topic-summary rounds omit `game_state`, which the summary never reads.
