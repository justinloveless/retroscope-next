# UF10 decisions: auth edge cases

The per-item decisions are appended to the owning units' records: U16 (items 4, 5, 8), U17 (items 1, 2, 6) and U18
(items 3, 7). This file records what UF10 found and where it read the follow-up narrowly.

1. **Item 1 reads "skip the claim" as "verify instead".** Skipping the claim alone would leave an account whose owner
   just proved mailbox control unverified. Verifying without clearing the password or revoking sessions is what the
   verify link does for a same-user session, so the magic link does that too.
2. **Item 5 needed no production change.** Every catch in UF10's paths is already filtered so a caller's
   cancellation propagates (see U16's amendment). The item adds tests only. `RecheckAccessAsync`, which the
   follow-up names as the pattern, is in `Realtime/Actors` (UF9's paths) and was not touched.
3. **Item 6 was already done** by U17; UF10 adds the contract test.
4. **Item 8:** the route did not exist. `DELETE /api/me/avatar` was added with it, since §d lists `PUT / DELETE` and
   the account screen calls both.
5. **Test placement.** UF10 owns `tests/…/AuthCore/**` but not `tests/…/Auth/**` (U16's original folder, with
   `AuthHost`). New AuthCore tests reuse `AuthHost` unchanged and live in `AuthCore/`.
