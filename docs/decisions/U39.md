# U39 decisions: identity and teams mapping

U39 owns `Importer/Map/{Users,Teams,Invites,Activity,Templates,Endorsements}Map.cs` and
`tests/Retroscope.Importer.Tests/Identity/**` (`Category=Identity`).

## Stages (discovered by reflection, U38)

| Order | Class (file) | Source → target |
|---|---|---|

| 110 | `ExternalIdentitiesMap` (Users) | `auth.identities` → `external_identities` |
| 200 | `TeamsMap` (Teams) | `teams` → `teams`, `team_jira_config` |

| 230 | `TemplatesMap` (Templates) | `board_templates`, `template_columns` → same |
| 240 | `InvitesMap` (Invites) | `team_invitations` → `team_invites` |

U38's order table stops at storage 500–599 and archive 900. **600–899 is "after the rooms"**. The two stages there
read the ids the earlier stages wrote (`select id from retro_boards|poker_sessions|teams|endorsement_types`), so they do
not depend on how U40/U41 decide which rooms to import.

## Shared helpers other importer units may use

- `TargetRows` (internal, in `UsersMap.cs`): `CopyAsync` (binary COPY of `object?[]` rows with explicit
  `NpgsqlDbType`s), `IdsAsync`, `Length`/`Clip` (characters as Postgres `char_length` counts them, never splitting a
  surrogate pair), `Plain` (one-line text), `ParseObject`.
- `ColumnPalette.FromTailwind` (Templates): the original's `bg-<hue>-100 border-<hue>-300` → palette name. A bare
  palette name is accepted, and anything else, including the original's `teal` preset, is `gray` (§h.2 "unknown →
  gray"). U41 should use it for `retro_columns.color`.
- `TemplatesMap.VoteLimit` / `VoteEmoji`: `max_votes_per_user` (≤ 0 or null → unlimited, capped at 99) and
  `vote_emoji` (1–8 characters, else 👍). `retro_board_config` has the same columns.
- `TeamsMap.JiraAssociatedData(team)` and `InvitesMap.InviteAssociatedData(invite)`.

## Decisions where the spec was silent or did not fit

1. **Jira box without the server.** The importer must not reference `Retroscope.Server` (§h.5, U0 scaffold test), so
   `Credentials.AssociatedData` cannot be called. `TeamsMap.JiraAssociatedData` rebuilds U19's layout byte for byte
   (`"jira:v1:"` ‖ team uuid in RFC 4122 order), and a test pins the bytes. The plaintext is the server's
   `{"email":…,"token":…}` JSON, `key_id` comes from the box, and `token_last4`/`email_masked` use the server's rules.
   A test opens the box with the production keyring.
2. **`team_invites.token_box`** = `Keyring.Seal(InviteBox, UTF-8 token, AAD = invite id's 16 bytes, RFC 4122 order)`.
   The spec says only "AAD = invite id". **U24 must use the same AAD** (`InvitesMap.InviteAssociatedData` documents
   it) when it lists link invites and seals new ones.
3. **Email invites have no role in the source.** `team_invitations` has no role column, and every accepted invitation
   made a member, so "email invites keep their role" means `member`. A target email invite therefore never grants
   admin either.
4. **Which invitations are live.** `status = 'pending' AND is_active AND expires_at > import time`, with SQL
   semantics (`is_active` null is not live). "cutover + 7 days" is `ImportedAt + 7 days`, the cutover reference U38
   gave `ImportContext`. An invitation whose token is empty or reused is skipped, because `token_hash` is unique in
   the target. The source has a unique token, so this only guards against drift.
5. **Accounts with an email the target rejects** (shorter than 3, longer than 254, no local part) fail the run with
   the account id. `PrincipalDirectory` has already resolved them as users, so skipping them would leave dangling
   references everywhere. GoTrue validates emails, so this should never trigger.
6. **Counting nulled hashes.** `nulledPasswordHashes` counts only non-empty values that are not bcrypt. A null hash
   (Google-only accounts) needs no reset and is not counted.
7. **`disabled_at`** is `deleted_at` when set, else the import time when `banned_until` is in the future. Disabled
   users are listed in `disabledUsers`.
8. **Guests** (anonymous `auth.users`) are named from their profile's `full_name` (else `nickname`) through
   `DisplayNames.Scrub`, so an empty name is `Guest`.
9. **What goes to the archive.** Merged losers' `auth.users` rows go to `auth.users` whole (their
   `encrypted_password` and tokens sealed through the `seal` list), and their `profiles` rows go to `public.profiles`.
   Phone-only accounts are skipped, not archived (S29 says "skipped and reported"). Their metadata and sealed phone
   still reach `auth.users#meta` through U38's archive stage. Profiles with no imported account are skipped
   (`no_account`). Templates without a team, and their columns, are archived whole.
10. **Merge collisions** (§h.1 global rule): memberships keep the highest role and the earliest `joined_at`.
    Favorites keep the earliest `created_at`. Recent activity keeps the latest `last_at`. Endorsements are read
    oldest first and keep the oldest per unique key. A merge that turns an endorsement into a self-endorsement skips
    it (`self`).
11. **Owner repair.** Each roster is ordered by `joined_at`, then user id. "Oldest" means earliest joined. Teams with
    no imported member keep no owner and are listed in `teamsWithoutMembers`. **U42's "one owner per team"
    invariant should read "exactly one owner per team that has members".** A memberless team can only come from a
    source team whose members were all deleted, and inventing an owner would hand a team to a stranger.
12. **Jira config acceptance.** No config is created when the team has neither a domain nor a token. With either,
    the host must pass `JiraHostPolicy`, the email must be non-empty and the token at least 4 characters. Otherwise
    the team is listed in `jiraConfigsRejected` with `host`, `email` or `token`. `jira_board_id`: positive digits →
    `board_id`, else an upper-cased valid key → `project_key`, else neither. `jira_ticket_prefix` is trimmed,
    stripped of a trailing `-` and upper-cased, and dropped if it is still not a valid key.
13. **Names.** An empty team, template or endorsement-type name becomes `Untitled team` / `Untitled template` /
    `Endorsement` (`renamedTeams` lists teams). Over-long names are clipped (`truncatedTeamNames`). Descriptions are
    clipped too, and an empty one becomes null.
14. **Point descriptions.** Keys are the deck values `1 2 3 5 8 13 21`. Values must be JSON strings and become one
    line of plain text, at most 100 characters. Empty values and anything that is not an object are dropped.
15. **Seeded endorsement types.** A team with no imported type gets the original's three defaults
    (`seed_default_endorsement_types`, migration 20260311043131) with ids `UuidV5(team id, "endorsement-type:<n>")`,
    so re-runs agree. `max_endorsements_per_user_per_board` is clamped to the target's 0–50. Teams without settings
    keep the default 3.
16. **Template column order.** `template_columns` has `unique (template_id, sort_key)`, so the sort key is the row
    number over `(position, created_at, id)`, not a dense rank. The source's partial unique index already allows at
    most one action-items column per template, so nothing needs resolving there.
17. **Avatars are not set here.** `users.avatar_blob_id` stays null. U42's storage stage (500s) reads
    `archive.storage_cache` and attaches avatars after the users exist.
18. **Golden files.** `Identity/Fixtures/<name>.sql` seeds a fresh fake source (with `session_replication_role =
    replica`, so Supabase triggers do not add rows). `Identity/Golden/<name>.txt` holds every target row the stages
    write, their archive rows (no seal key, so `{"stripped": true}`), and their slice of the report. The import time
    is masked as `<import>`, keyring boxes as `<box>`. Regenerate with `RS_UPDATE_GOLDEN=1 dotnet test
    tests/Retroscope.Importer.Tests --filter Category=Identity` and review the diff. The tests list the stages
    explicitly, plus a stand-in for the room stages that loads the source's boards and poker sessions bare, so
    U40/U41 merging does not change these goldens.

## Amendments (UF8)

- **Unparseable `identity_data` skips the identity.** `UsersMap.IdentityEmail` parses through `TargetRows.ParseObject`.
  A value it refuses (not a JSON object, or jsonb nested deeper than `System.Text.Json`'s 64 levels, which used to
  abort the run) proves nothing: it never verifies an email, and `ExternalIdentitiesMap` skips the row with the new
  skip reason `malformed_identity_data`. A null `identity_data` is not malformed; it has no email.
- **Merge collision rules (decision 10) have explicit asserts** in `IdentityRulesTests`: highest role and earliest join
  for memberships, earliest favorite, latest recent activity, the oldest of two endorsements that collapse to one key
  (`duplicate`), and a self-endorsement created by the merge (`self`).
- **`ColumnPalette` moved to `Map/Common.cs`** and is the one Tailwind → palette mapping for template and board
  columns. It now follows the rule the retro mapping used: a bare palette name, else the first `bg-`/`border-`/`text-`
  class with a shade decides, else gray. Every colour the original wrote maps the same way under both old rules.
