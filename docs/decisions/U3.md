# U3 decisions: security primitives

Everything lives in `src/Retroscope.Core/Security` (namespace `Retroscope.Core.Security`). It is pure: BCL crypto and BCrypt.Net-Next only. There is no IO and no clock. The CSPRNG is used for nonces, run keys and tokens.

## Public surface (for U11, U16, U18, U19, U22, U26, U38 and later units)

| Type | Use |
|---|---|
| `Keyring.Parse(APP_KEYS)` | `Seal`/`TryOpen(purpose, box, aad)` (a `Span<byte>` overload decrypts into a pooled buffer), `TryReseal` (the rotation command), `IsSealedWithActiveKey`, `Mac(purpose, data)` (`email_hmac`), static `TryReadKeyId`/`PlaintextLength` |
| `KeyPurpose` | `OidcCookie`, `JiraCredentials`, `InviteBox`, `AuditEmail`. Each maps to the HKDF info `retroscope/<oidc-cookie\|jira-creds\|invite-box\|audit-email>/v1` |
| `AeadBox` | Raw AES-256-GCM: `nonce(12) ‖ ciphertext ‖ tag(16)` with a random nonce |
| `Sealer` | Importer sealing (§h.3): `Create(pem)`, `Seal(table, pk, field, value)` → base64, `WrappedKey`, `KeyFingerprint`, static `TryOpen(privateKey, …)` for the operator |
| `OpaqueToken` | `New()` → 43-char base64url of 32 CSPRNG bytes; `IsWellFormed` |
| `TokenHash` | `Of(token)` = SHA-256 of the token string's UTF-8 bytes; `Matches` (constant time) |
| `IAnonTagger` / `AnonTagger.Parse(ANON_TAG_KEY)` | `Tag(boardId, principalId)`, `Owns(tag, …)` |
| `Bcrypt` | `Hash` (cost 10, `$2a$`), `Verify`, `DummyVerify`, `IsWellFormed` |
| `IpClassifier` | `Classify(IPAddress)` → `IpRange`, `IsPublic` |
| `JiraHostPolicy` | `FromAllowlist(JIRA_HOST_ALLOWLIST)`, `AtlassianCloudOnly`, `TryNormalize(input, out host)` |
| `ReturnPath` | `TryValidate(PUBLIC_URL, value, out path)` |

## Decisions where the spec was silent or did not fit

1. **Keyring boxes name their key.** `team_invites.token_box` has no `key_id` column, and neither does the OIDC cookie, so the key id is stored inside the box: `0x01 ‖ len ‖ keyId ‖ AeadBox`. The header goes into the GCM associated data ahead of the caller's AAD, so the key id cannot be swapped without detection. `team_jira_config.key_id` stays as the spec has it, and its writer fills it from `Keyring.TryReadKeyId(box)`.
2. **APP_KEYS format.** Ids are 1–32 characters of `[A-Za-z0-9_-]`. Every key must be base64 of exactly 32 bytes, and duplicate ids are refused. Error messages name the entry or its id and never contain key material.
3. **HKDF parameters.** HKDF-SHA256 with an empty salt (RFC 5869 then uses HashLen zero bytes), the info strings from §e, and 32-byte output. All subkeys are derived once at parse time.
4. **`Mac` uses the active key.** `email_hmac` values therefore change after a rotation. Correlating audit rows across a rotation would need the MAC under each `KeyIds` entry. Nothing in the design does that today, so no API was added for it.
5. **Sealer details.** "table ‖ pk ‖ field" is joined with NUL separators, and the separator is refused inside a part. Public keys smaller than RSA-3072 are refused. The fingerprint stored in `import_runs.seal_key_id` is `sha256:<hex>` of the SubjectPublicKeyInfo DER. The base64 string is the value of `{"sealed": …}`; the importer builds that JSON.
6. **Token hashing.** The hash is over the token *string* (UTF-8), not over the decoded bytes. New tokens and imported legacy invite tokens (arbitrary strings) then hash the same way, which matches §h.2 `token_hash = sha256(token)`.
7. **`IAnonTagger` lives here.** Neither U2's `Ports.cs` list nor any other unit names it. It takes `Guid`s because the U2 id types were not merged yet. Callers pass `BoardId.Value`/`PrincipalId.Value`. The message is the board's 16 bytes followed by the principal's 16 bytes, both in RFC 4122 (big-endian) order. U41 (importer) must produce the same layout, and it does if it calls `AnonTagger`.
8. **IP classification.** For IPv6, only `2000::/3` can be public, minus the IANA special-purpose blocks inside it (`2001::/23`, `2001:db8::/32`, `2002::/16`, `3fff::/20`). IPv4-mapped addresses (`::ffff:a.b.c.d`) are classified by the IPv4 address they carry. Every other v4-embedding form (IPv4-compatible `::a.b.c.d`, NAT64 `64:ff9b::/96`, 6to4, Teredo) is refused outright rather than unwrapped. Beyond the spec's list, IPv4 `0/8`, `192.0.0/24`, the documentation nets, `198.18/15`, `192.88.99/24` and `240/4` (which includes broadcast) are also refused. The decimal, octal and hex notations only matter while parsing: .NET's `IPAddress.Parse` already accepts the inet_aton forms (`2130706433`, `0177.0.0.1`, `0x7f.1`), and the table tests assert that each one reaches the classifier as the address it denotes.
9. **Jira host normalization.** An `http://` prefix is accepted and dropped, because the client always uses https:443. Any other scheme is refused. These are refused anywhere in the input: `@` (userinfo), `%`, `\`, `[`/`]`, whitespace, control characters and non-ASCII. A host whose last label is numeric (decimal or `0x` hex) counts as an IP literal even when `IPAddress` would not parse the whole string, because WHATWG URL parsers would. The §f regex is used as written, so only a single label before `.atlassian.net` is allowed. `JIRA_HOST_ALLOWLIST` entries must be multi-label DNS names. They are validated when the policy is constructed, so a bad entry fails at startup.
10. **Return-path validation.** The rule in §e (same origin, path starts with `/` but not `//`) is checked on the raw value, on each percent-decoded form (up to 3 rounds; a value that still decodes further is refused) and on the resolved path. Backslashes and any whitespace are refused as well, including encoded `%20`: app paths never contain spaces, and this is what closes `/%09/evil.com`. The accepted value is returned normalized (`PathAndQuery + Fragment` of the resolved URI, so `/a/../b` becomes `/b`). The maximum length is 2048.
11. **bcrypt wrapper.** `Verify` returns false, never throws, for a malformed hash or a password that cannot be encoded. `Hash` refuses more than 72 UTF-8 bytes. Signup and password change enforce 10–72 bytes anyway. `Verify` applies no length rule (login has no policy, S30). `DummyVerify` uses a fixed cost-10 hash of a discarded random secret. The well-formedness regex uses `[0-9]`, not `\d`, so it matches the Postgres `password_hash` CHECK exactly.
12. **GoTrue fixtures.** The `$2a$10$` fixtures (`abc123`, and a passphrase) were produced with `golang.org/x/crypto/bcrypt` v0.58.0, the package GoTrue hashes with. They are not hashes produced by BCrypt.Net-Next, so the test proves cross-implementation compatibility.
13. **HKDF vectors** are RFC 5869 A.1–A.3, fetched from rfc-editor.org on 2026-10-20.

## Not done here

- The attachment-redirect media host list (`api.media.atlassian.com`, `*.atlassian.net`) is unverified and belongs to U19.
- IP prefix keying (/24, /48, /64) for rate limits and audit belongs to U11 and U16.
