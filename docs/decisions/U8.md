# U8 decisions: retro domain

U8 owns `src/Retroscope.Core/Retro/**`, `tests/Retroscope.Core.Tests/Retro/**` and `tests/golden/transcripts/retro-*.json`.

## Public surface (for U13, U15, U22, U25, U34, U35, U36)

| Type | Use |
|---|---|
| `RetroState` | Mutable board state (columns with `SortKey`, cards with voters, comments, readiness, focus, `TimerValue`, endorsements, members) |
| `RetroInput` | What the actor decides: `Client(RetroCommand)` (implicit conversion from any `RetroCommand`) or an internal input |
| `RetroDecider(IAnonTagger)` | `IRoomDomain<RetroState, RetroInput, RetroEvent>` |
| `RetroEvent` subtypes (`RetroEvents.cs`) | What `RetroStore` persists; each carries what its SQL needs (mentions, image ids, cascaded card and comment ids, the in-place action item) |
| `RetroProjection(IAnonTagger)` | `Snapshot(state, presence, forMembers)`, `Overlay(state, viewer)`, `ForViewer(stateAfter, events, viewer, viewerIsMember)` |
| `StageRules`, `TimerRules`, `RetroRoles`, `RetroConfigPatches` | The rules the decider and projection share |
| `RetroSort` | Port of `sortItems` (`RetroColumn.tsx:50-64`), checked against `tests/golden/retro-sort.json` |

## Decisions where the spec was silent or did not fit

1. **Internal inputs are not `RetroCommand`s.** U2 decision 3 says domain-internal commands may derive from
   `RetroCommand` in `Core/Retro`, but `ProtocolCatalogTests.Every_concrete_payload_type_has_exactly_one_kind` scans the
   whole Core assembly and fails for any concrete `Command` without a catalog kind. The domain's command type is
   therefore `RetroInput`: `Client(RetroCommand)` wraps a wire command, and `TimerDue(EndsAt)`,
   `TeamSettingsChanged(MaxEndorsements)`, `MembersChanged(Members)`, `ArchiveSet(Archived, By)` and
   `AccessSet(Visibility, PasswordSetAt)` are internal. Internal inputs are trusted: whoever posts them (HTTP handler,
   team actor, timer) has authorized them. U7 hits the same test; U2 may want to narrow it to `Core/Protocol`.
2. **Authorization goes through `RetroRoles`, not `Policy.Can`.** `PolicyRules` is U9's deny-all stub until wave 2
   merges, and the in-room rules (facilitator, ownership, anonymous posting) are part of this unit's Check. The decider
   resolves roles through `IAccessView` at decide time (R12). Facilitator: on team boards members only, whatever the
   visibility; on quick boards any signed-in user; guests never. Subscribe access stays with the actor and
   `Policy.Can(Subscribe)`. **U9:** `RetroFacilitate`, `RetroEndorse` and `RetroViewRoster` should delegate to
   `RetroRoles.IsFacilitator`/`IsMember`, so the two cannot drift.
3. **The timer follows the facilitator rule.** §c.4 says "signed-in"; §c.4 "Facilitator" says non-members on team
   boards may add, edit their own, vote and comment, "nothing more". So: signed-in users, members only on team boards.
   Focus and readiness stay open to every participant (§c.4 says so for focus).
4. **An archived board refuses every client command** with `board_archived` (the original passed no handlers to an
   archived board). Unarchiving is an internal input.
5. **Nack codes.** Voting turned off → `forbidden`; the stage forbidding it → `stage_forbids`. With enforced readiness
   both a non-adjacent move and "not everyone present is ready" are `stage_forbids`. Taken ids (card, comment, column,
   endorsement) → `invalid`. Markup: `TooLong`/`TooManyImages` → `too_large`, `Empty`/`InvalidCharacter` → `invalid`.
   Anonymous posting by a guest or on a board that disallows it → `forbidden`. A move the timer cannot make from its
   state → `invalid`; a repeat (pause while paused, resume while running, reset while idle) → no-op.
6. **`stale` payloads** (`d.current`): card edit `{body, version}`; column update the whole `ColumnInfo`; column
   reorder the current id array; rename the title; config the whole `RetroConfig`; stage and ready the current stage
   name; focus the focused card id or `null`; timer the whole `retro.timer` payload.
7. **Stages.** `stage.set` works with stages off too (it only matters when they are on). Enforcement needs both
   `stagesEnabled` and `enforceReadiness`; Reset/Restart (any → thinking) and Reopen (closed → discussing) skip it.
   "Everyone ready" is `presence ⊆ ready`, so absent principals neither block nor count. Focus survives stage changes.
8. **Timer.** `TimerDue` carries the `EndsAt` it was armed for instead of a generation: a restart or pause changes
   `EndsAt`, so a late callback is a no-op. Start is open from any state (restart). Pausing at or after the end
   expires the timer instead. `retro.timer.remainingMs` is sent only while paused: a running timer's remainder is
   `endsAt` minus the client's corrected clock, so snapshots do not depend on when they were built.
9. **Action items created in place** get `ActionItemId = UuidV5(namespace, cardId)`: deterministic (the decider stays
   pure) and unique per card, matching the unique `source_card_id`.
10. **Images.** The decider cannot see the `blobs` table, so it lists the `blob:` ids a body references. **U22:** the
    attach `update` must be scoped `where board_id = $board and purpose = 'board_image'`, and refuse the command when
    fewer rows match than ids were listed (a foreign or missing blob).
11. **Mentions** are kept only for current team members; quick boards record none.
12. **Column sort keys** are `max + 1` on add (deletes leave gaps), dense `0..n-1` after a reorder.
13. **Duplicate endorsement** (same giver, recipient and type under a new id) is a no-op, not a constraint failure.
14. **Author display** is captured from the principal when the post is made; `AuthorInfo` is what the store loads.
15. **Projection.**
    - Two shared snapshots per seq: one for members (roster, endorsements, types, limit) and one for everyone else
      (S12). **U13/U22:** cache both; pick by `IAccessView` at subscribe.
    - Turning `showAuthorNames` on or off re-sends every card and comment as `retro.card.added` /
      `retro.comment.added`. When voter identities appear or disappear (stage, `stagesEnabled`, archive), every voted
      card is re-sent as `retro.vote`. **U34:** `added` events are upserts by id, and a `retro.vote` without `voters`
      clears them.
    - `retro.readiness.ready` lists every ready principal for the stage, sorted; clients intersect with presence.
    - Members-only events (`retro.endorsement.*`, `team.settings`) project to nothing for others; the seq still advances.
    - `MembersChanged` produces no board event: members' board pages subscribe to the team room and get `team.members`
      there.
    - Cards and comments are ordered by `(createdAt, id)`, votes in card order.

## Golden transcripts

`RetroTranscriptTests` writes `tests/golden/transcripts/retro-<scenario>-<viewer>.json`:

```json
{ "source": "…", "room": "board:<uuid>", "viewer": {"pid", "kind", "member"},
  "frames": [<snap>, <tx>…], "expectedViewerState": {"d": <snapshot>, "o": <overlay>}, "expectedNav": null }
```

Frames are exactly what `WireWriter` sends that viewer. `expectedViewerState` is a fresh snapshot at the last seq; a
reducer folding `frames` must reach it, treating `retro.timer.expired` (and the `endsAt` it carries while idle) as a
one-shot signal rather than state. A stale or missing file is rewritten and the test fails, so the second run passes
(the same flow as U2's generated files). The C# `RetroViewerModel` folds every transcript and 9,000 random commands
(six seeds, quick and team boards, four viewers) and must equal the fresh snapshot each time; removing the vote
re-send on stage change makes it fail.

## Changes from UF3

* **Decision 2:** `Policy` now asks `RetroRoles` for `RetroFacilitate`, `RetroTimer`, `RetroEndorse`,
  `RetroViewRoster`, `RetroReady` and `RetroFocus`. `RetroRoles` gained `TeamId?`-based overloads for that, and an
  `IsMember(…, Principal, …)` that ignores a role reported for a guest; the decider uses it for the caller.
* **Decision 3:** readiness and focus are no longer open to every participant. On team boards (any visibility) only
  members set them (`RetroRoles.MayPace`, `forbidden` otherwise); quick boards keep them open to guests.
* **Revoke** needs the giver to still be a team member (`forbidden` otherwise, checked before `not_found`).
* **`RetroInput.ActionItemCommentAdd(commentId, cardId, body)`** is the HTTP-originated comment from the team page
  (`POST /api/teams/{id}/action-items/{itemId}/comments`, Ask). The viewer is the HTTP caller and must be a member of
  the board's team; the comment is never anonymous, and the stage gate and the archive do not apply. It emits the
  usual `CommentAdded`, so the store, mentions, images and `retro.comment.added` work as for a client comment.
  **U22/U25:** post the team notice (`ActionItemCommentsChanged`) as for any comment on an action-item card.
* **Decision 15, `MembersChanged`:** now projects `retro.members {members}` to team members (nothing to others), so
  a folded member view equals a fresh snapshot. An unchanged roster is a NoOp. **U34:** replace the roster on
  `retro.members`.
