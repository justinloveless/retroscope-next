# U5 decisions: markup (JS)

## Contract: follow U4, not a second design

U4 (C#) and U5 (JS) ran in parallel, and the design does not spell out the DocNode JSON or the edge cases of the grammar. U4 owns `Core/Markup/**` and `tests/fixtures/markup/**`, and its `DocJson.cs` names `web/src/markup` as the mirror. U5 therefore ports U4's in-progress parser and writer rule for rule instead of inventing a second grammar.

- **Wire shape** (from `Core/Markup/DocJson.cs`): every node is `{t, ...}`; children are `c`, scalar content is `v`. Kinds: `doc p h ul ol li quote pre hr island panel table tr th td expand tasks task text b i s u code a mention img attachment status br`. Fields: `h.level`, `ol.start`, `pre.lang` (omitted when absent) and `pre.v`, `island.id`, `panel.kind`, `expand.title`, `task.done`, `a.href`, `mention.id/name`, `img.blob/alt`, `attachment.id/alt`, `status.v/color`. Mention and blob ids are lower-case canonical UUIDs.
- **Dialects:** `retro` (mentions and board images), `jira` (headings and rules, no mentions or images), `jira-description` (`jira` plus top-level `[[island:id]]` lines). An island parsed from markup carries `c: []`; its read-only content comes from the issue DocNode.
- **Grammar, as U4 has it:** the C# sources are the reference until U4's `tests/fixtures/markup/README.md` lands. In short: lines are trimmed in paragraphs; list items take indented continuation lines; quote and list nesting stop at depth 16 and inline nesting at 16; `**`, `~~`, `*`, `_` emphasis with the closer rules of `InlineParser.FindCloser`; emphasis never nests inside emphasis opened with the same delimiter; character classes are ASCII-only and indices are UTF-16 code units. That makes the JS and C# parsers agree on non-ASCII text without Unicode tables.
- **Writer:** `toMarkup` ports `MarkupWriter`/`InlineWriter`, including the italic delimiter choice, the tight paragraph→list join and the `\!` before `[`. ADF-only kinds throw, as in C#.
- **Limits:** `checkMarkup(markup, field)` mirrors `MarkupLimits.Check` (`card` 8,000, `comment` 4,000, `actionItem` 8,000, `jiraText`/`jiraDescription` 32,000 code points; 8 images; C0 controls and lone surrogates rejected). The error names are `empty`, `too_long`, `too_many_images` and `invalid_character`.

**Parity check performed:** U4's uncommitted `Core/Markup/*.cs`, copied as of 22:05 into a scratch console project (not into either worktree), parsed and wrote the U5 corpus plus 34,587 fuzz inputs built from the same pieces as `MarkupFuzzTests`. JS and C# agreed on every DocNode and every canonical string. Inputs with lone surrogates were left out, because C#'s `DocJson.Serialize` cannot encode them (see follow-ups).

## Renderer

- `render(doc, {document, resolveMention, imageSrc, islands})` returns a `DocumentFragment` built with `createElement`, `createTextNode`, `setAttribute` and `append` only. It re-checks every field, because Jira DocNodes come from the server, not from `parse()`. Links need an allowed href (`http`, `https` or `mailto`). Image URLs must be same-origin paths. Enum fields fall back to a neutral value, and unknown kinds keep their text but not their markup. Rendering stops at nesting depth 36, which covers what the parser can produce, and shows "content truncated" below that.
- Element map: `p h1–h6 ul ol li blockquote pre>code[data-lang] hr div.panel.panel-<kind> table>tbody>tr>th/td details.expand>summary ul.tasks>li.task>input[type=checkbox][disabled] strong em s u code a[rel=noopener noreferrer nofollow][target=_blank] span.mention[data-mention-id] img[alt][loading=lazy] span.status.status-<color> br div.island[data-island-id]`.
- **Mention names are never taken from the token** (§g.6). The caller's `resolveMention(id)` supplies the current name. When it returns nothing, the pill reads `@unknown`.
- **Images:** board images default to `/blob/{id}` (§d). Jira attachments get no default URL: the caller passes `imageSrc`, because the proxy path needs the team id and issue key. Without a URL the renderer shows "image (open in Jira)" (§f).

## Tests

`tests/web-unit/markup.test.js` runs on a minimal fake DOM whose HTML sinks throw. It covers:

- an inline corpus of about 75 cases (DocNode plus canonical written form);
- every `tests/fixtures/markup/*.json` file when U4's directory exists (see follow-ups);
- renderer snapshots and a hostile-DocNode test (`on*` attributes, `javascript:` and scheme-relative links, attribute injection through ids, enums and `lang`, unknown kinds);
- a source scan for banned sinks, and the limits;
- 30,000 fuzz iterations (U4's piece list, all three dialects) asserting no throw, dialect-correct kinds, an exact round trip, a writer fixed point and safe DOM;
- a timing bound on pathological inputs.

300,000-iteration runs with three other seeds also passed.

## Follow-ups

- **Merge order with U4.** If U4 changes the grammar or the writer after 22:05, re-port the change into `parse.js`/`doc.js`. The parity harness above takes minutes to rebuild. Once `tests/fixtures/markup/*.json` exists, the test reads it. It accepts an array or `{cases}` with `markup`/`input`, `dialect` (`retro`, `jira`, `jira-description`, any case or punctuation), `doc` and an optional `written`/`canonical`, and fails loudly on any other shape. If U4 settles on a different file shape, adjust `loadSharedFixtures`.
- **For U4:** `DocJson.Serialize` throws on lone surrogates (`Utf8JsonWriter`), and `MarkupParser.Parse` accepts them (the fuzz pieces include `"\ud83d"`). `MarkupLimits.Check` rejects them for stored bodies, so only unchecked callers are exposed.
