# UF11 decisions: app shell polish

UF11 owns the paths listed in `docs/followups/UF11.md`.

## Contracts later units rely on

1. **The app header lives in the entry, not in screens.** `entry.js` splits `#app` into `header.app-header` and
   `div.app-view`, and the router mounts every route into `.app-view`. `screens/frame.js` no longer draws a header;
   `createFrame` is only the centred main column. `setThemePreference` moved from `frame.js` to `app.js`.
   - The header shows on every route. Signed-out visitors get a "Sign in" link that returns to the page, except on
     `/login`, `/auth/*`, `/teams/:id`, `/teams/:id/settings` and `/retro/:code`, which draw their own prompt.
   - A session body without `principal` counts as signed out. Some room specs boot with `{pid, kind, name}`, which is
     not the `/api/me` shape (U29 decision 1).
   - Mentions are a bell link with the unread count (`Mentions (N unread)`), visible at every width, as the
     original's NotificationBell was. Dashboard and Teams are in `nav[aria-label=Main]` on wide screens.
   - The team switcher lists `me.teams`. On `/teams/:id…` and `/teams/:tid/poker/…` it names the current team.
   - **Below 768 px** the header is fixed, `.app-view` is padded by `--header-height`, and the links, teams, theme and
     account items move into a right-hand sheet (`screens/sheet.js`, its own lazy chunk, loaded on the first tap).
   - **Centre slot.** On `/retro/:code` the header mirrors the board's `document.title` (`<title> · Retroscope`,
     which `retro/board.js` already sets) until a screen fills the slot itself with `setHeaderCenter(...nodes)` from
     `app.js`. The slot clears on the next route. **U34:** the board can portal its title, code and guest line there,
     as the original did.
   - **Poker** keeps its Neotro toolbar. The app header hides there and docks its theme and account buttons into
     `.nt-toolbar-extras` (`.app-dock`). On a phone the toolbar wraps them onto a second row.
2. **Router options** (`core/router.js`): `context(route)` returns mount's third argument, or a promise of it that is
   awaited with the chunk. `onShow(route | null, params)` runs after every screen change or update.
3. **`getSocket()` now returns a promise** of the tab's socket. `net/socket.js` loads on first use, so pages without
   a room never download it and the entry chunk stays within budget.
4. **The shared socket goes to retro only.** `entry.js` passes `{socket}` to modules in `SHARED_SOCKET`
   (`retro/index.js`) and starts it as soon as the page loads, before the route chunk arrives. Poker (U31) and the
   team page (U30) still open sockets of their own and take no `{socket}`, so the entry opens no early socket on
   their routes. A second socket in the tab would share the cid and fight with 4409. **U30/U31:** accept
   `app.socket` in `mount()`, then add the module to `SHARED_SOCKET`. Until then, navigating in-app between a team
   or poker page and a board keeps two sockets open, as it did before this unit.
5. **The "Reconnecting…" notice belongs to the room screen.** Poker and the retro board each draw their own banner
   after 10 s offline, so the toast that `app.js` also raised showed the notice twice. `app.js` now shows only the
   terminal 4401/4403 notice. This amends U29 contract 3.
6. **Root files.** `web/assets/public/*` is copied to the root of `dist`, not hashed, and listed in the manifest's new
   `public` map (same `{size, etag, br, gz}` shape as `files`). The web manifest names its icons by logical asset
   name, and the build rewrites them to the hashed URLs. It fails if an icon is missing. `StaticAssets` serves only
   `/favicon.ico`, `/manifest.webmanifest` and `/robots.txt` from that map, so a build cannot publish anything else
   at the root. They are served with `Cache-Control: public, max-age=86400`, ETag revalidation and br/gzip
   negotiation, like `/assets/`. The shell links the favicon, the SVG logo, the manifest and `theme-color`
   (`#111827`, as the original's `index.html` did) only when the build ships them.

## Decisions where the spec was silent or did not fit

1. **`FEATURES` is left to U35 and U36.** U34 decision 4 gives each feature unit its own import and `FEATURES`
   entry in `retro/index.js`. That file is U34's, U35 and U36 run in this wave, and the carried notes say "UF11
   wires {socket} in entry.js". UF11 therefore only passes the socket.
2. **Chunk measurement** (`measureChunks` in `build.mjs`). A lazy chunk is charged for its static closure minus
   what is certainly loaded wherever it can be imported from: the entry, plus the intersection of what each of its
   importers has loaded. A chunk that several lazy chunks add is reported once as `shared:<largest input>` and has
   no baseline. When esbuild moves a lazily imported module's code into a shared chunk (it is also imported
   statically elsewhere), that chunk is charged to the module. With this, `editor` measures 6.8 KB on its own (U34
   decision 1, U10 follow-up), `mentions` is back at its 10 KB budget (1.0 KB), and `card.js`/`composer.js` import
   `markup/editor.js` directly again. The entry is 11.8 KB of 12 KB: the socket code left it (contract 3) and the
   header joined it.
3. **Team uploads** map the HTTP status to the error when the body carries no problem code (409 `board_quota`, 413
   `too_large`, 415 `unsupported_media_type`, 507 `storage_full`), the same table `retro/board.js` uses. A proxy
   answering 413 with HTML is the case this covers.
4. **The two failing pages specs** were test problems:
   - Joining by code answered `{id: 'b1'}`, and the board then subscribed to `board:b1`, which the protocol refuses.
     The fixture now uses a UUID.
   - The reconnecting notice used `toHaveCount(0)`, which counts poker's hidden banner too. The spec now checks
     that the notice is hidden, then visible, and that no second notice (toast) shows, on poker and on a board. The
     fake clock is advanced only after the first socket attempt. Poker connects only after its chunk has resolved
     the code.
   - "Room routes open the socket before the room chunk mounts" now runs on a board, holds the retro chunk until
     the hello has arrived, and a second spec checks the board joins on that one connection.
5. **Fake and demo servers.** The demo serves the three root files the way `StaticAssets` does. The plain fake server
   (`tests/web-fake-server/server.js`, U48's) does not; its shell also omits the icon links. Specs do not depend
   on either.
