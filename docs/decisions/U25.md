U25 owns `Server/Endpoints/{PokerEndpoints,RetroEndpoints,MentionsEndpoints}.cs`,
`Server/Data/Repos/{PokerLists,RetroLists,Mentions,ActionItemComments}Repo.cs`, `Server/Json/RoomHttpJsonContext.cs`

are Unix milliseconds. `nextCursor`/`next` and a parent `key` are written as `null`, not dropped, because the screens
compare with `null` (`topics.js`).

## Decisions where the spec was silent or did not fit

1. **Boot snapshot.** `RoomBootContributor` (an `IBootContributor`) resolves `/poker/:code`, `/teams/:tid/poker/:code`
   and `/retro/:code` through `RoomResolver` and writes `boot.room = {r, access, …the viewer's snap frame}`: the
   poker screen reads `{t, r, e, s, lastQ, d, o}` (U31 decision 4) and the board `{r, access, e, s, d, o}` (U34
   contract 2), so one object serves both. The frame comes from `ActorRegistry.QueryAsync(room, view =>
   view.SnapFrameAsync(viewer))` with a 400 ms budget; the query checks `view.CanSubscribe(viewer)` first, which is false
   for a not-found view (the UF7 follow-up). A password board the caller has not unlocked, a signed-out caller, or a
   query past the budget gets `{r, access}` only; the socket delivers the snapshot. A hidden room adds nothing, and on
   `/teams/:tid/poker/:code` neither does a session of another team. The viewer is the caller with a fresh client and
   connection id: a request has no tab, so `heldByThisTab` is false.
2. **No `signin` access.** `by-code` answers 404 for every hidden room, as U11 decision 8 requires; the board screen then
   says the board does not exist. A sign-in prompt would have to be shown for missing rooms too.
3. **New sessions start with a placeholder round** (number 1, sort key 0, no ticket, `current_round_id` pointing at it,
   `next_round_number = 2`), written in the same statement as the session: the original created round 1 on first open
   (`usePokerSession.ts`), and Core's placeholder fill depends on a current round. Team sessions copy
   `presence_enabled` and `follow_spotlight` from the team's latest session (§d).
4. **Quick boards** are titled "Quick Retro Board" when no title is given, `link` visibility, with the original's
   defaults (Good green, Bad red, Kudos blue, Action Items yellow as the action-items column;
   `create_columns_from_template` in the Supabase dump) and 3 votes per user (parity). Team boards take the chosen
   template, else the team's default template, else the same built-in columns; config comes from the template
   (`sort_chronologically` keeps its column default, since templates have none).
5. **Room codes.** 10 Crockford characters from `RoomCode.NewRandom`. The insert also refuses a code that exists in
   another letter case, because lookups ignore case; a collision is retried up to five times, then 503 `server_busy`.
6. **Session list stats** are one query with two lateral joins. `total` counts rounds that are not pending previews and
   `pointed` the revealed ones among them, the same rule as the room's `PokerChanged` tallies (U21 decision 11).
   `parentKeys` groups rounds with a real ticket by parent key (a null key included) in order of first appearance in
   the strip (`min(sort_key)`), which is the order U30's topic badges break ties by.
7. **Access writes.** `PATCH /api/retro/{id}` writes `visibility`, `password_hash` and `password_set_at` in one
   transaction (U22 decision 4) and deletes every grant whose epoch is not the new `password_set_at` in the same
   transaction. `password_set_at` comes from `now()` and is read back with `returning`, so `AccessSet` carries exactly
   the value later grants and loads compare with (`timestamptz` has microseconds, `DateTimeOffset` ticks). Then it asks
   the board `RetroInput.AccessSet` and calls `ActorRegistry.AccessChanged`, which kicks holders of the old password
   (`access_revoked`). A password implies `password` visibility; `password` visibility needs a password unless the
   board already has one; `team` needs a team board. Board passwords are 4 to 72 UTF-8 bytes (bcrypt reads 72) and are
   hashed through `HashGate`.
8. **Unlock** has no `RetroInput` (U22 decision 4), so the route writes the grant itself, only if the board's
   `password_set_at` still equals the epoch the password was checked against; otherwise 409 `password_changed`. The
   membership cache reads a grant it does not hold (U23 decision 8). A caller who can already subscribe gets 204; a
   board that is missing, deleted, or not a password board answers with the resolver's hidden 404. Every attempt
   is charged to the per-board limit before the board is read, refused ones included.
9. **Board management routes** load the board with the caller's role and grant in one query (as U20 does) and decide
   with `Policy.Can` (`RetroManageAccess`, `RetroArchive`, `RetroDeleteBoard`). A board the caller may neither see nor
   manage is 404; one they see but may not manage is 403. Archive and unarchive are asks (`RetroInput.ArchiveSet`): the
   board's store writes `archived_at` and posts `BoardsChanged` (U22 decision 8).
10. **Team routes** read membership from the rows (`TeamRoles.RoleAsync`), which the team actor commits before announcing
    it. A non-member or a soft-deleted team gets 404 `not_found`.
11. **Action items list and comments live here.** §k gives U25 the comment routes and `ActionItemCommentsRepo`; the list
    route (`GET /api/teams/{id}/action-items`) is listed in §d but in no unit's paths, and it sits next to the comments
    on the same team page, so it is in `RetroEndpoints`/`RetroListsRepo`. **Integrator:** if U24 maps it too, keep one.
    *Integration (wave 5):* U24 mapped it too. The list route stays in `TeamsEndpoints`/`TeamsRepo` (U24 decision 1)
    and now uses this unit's microsecond `ListCursor`, because U24's millisecond cursor could skip rows created within the
    same millisecond as a page's last row; the duplicate route here was removed.
    Comment counts are counted on the source card, as the team room does. Comments are read through the source board's
    actor (`QueryAsync`) and projected with `RetroProjection`, so anonymity, hidden author names and `mine` are exactly
    the board's (R22); the POST is `RetroRoom.AddActionItemCommentAsync` (`RetroInput.ActionItemCommentAdd`), whose store
    posts `ActionItemCommentsChanged`.
12. **Team notices.** Creating a team board posts `BoardsChanged`; creating a team session posts `PokerChanged(0, 1)`,
    deleting one `PokerChanged(0, 0)`: the team page reloads its list when a session is unknown or its total changed
    (U30 decision 3).
13. **Mentions** use the same readability rule as `UsersRepo.UnreadMentionsAsync` (U16), the board's author rule
    (a principal, an imported label as a guest name, otherwise anonymous) and hide the author when the board hides
    author names. Self-mentions are listed, as the unread count counts them.
14. **Cursors** are base64url of `<unix microseconds>.<id>` over `(created_at, id)`, so the next page starts exactly
    after the last row; `limit` defaults to 20 and is clamped to 1–100 (§d). A malformed cursor is 400 `invalid`.
15. **`HashGate`** is registered by `AuthEndpoints.AddServices` (U16); these routes only use it.

16. **Board deletion kicks live subscribers** (verifier fix, outside U25's paths). `RetroInput.Delete` decides
    `BoardDeleted` (a no-op once deleted), which sets `RetroState.Deleted`; `RetroBinding.IsDeleted` returns it, and the
    event is `MemoryOnly` (no wire event, the row is already soft-deleted by the route, as `AccessSet` follows the
    route's write). `DELETE /api/retro/{id}` soft-deletes, asks `Delete` so the actor kicks everyone `deleted`, then
    retires the actor (`TryPurgeAsync`), so a later subscribe loads the board as missing (`not_found`). This touches
    `Core/Retro` (no owner this wave) and `Realtime/Rooms/RetroRoom.cs` (UF9): two lines in `RetroBinding`, in a hunk
    apart from UF9's `IsCreate`/`AddRoom` change. **Integrator:** keep both when merging UF9.

## Verification

`dotnet test tests/Retroscope.Integration.Tests --filter Category=RoomHttp`: 38 tests on the real hosting pipeline,
leader, actors and poker, retro and team rooms against a migrated database. Mutation checks: without the
`AccessChanged` call the password-change kick test fails; without the per-board unlock limit the limit test fails; without the `Delete` ask the board deletion kick test fails.
