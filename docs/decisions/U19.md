## Decisions where the spec was silent or did not fit

1. **Credentials AAD bytes.** `"jira:v1:" ‖ team_id` is the 8 ASCII bytes `jira:v1:` followed by the team uuid's 16 bytes in
   RFC 4122 (big-endian) order, the same layout U3 uses for `AnonTagger`. The importer (U41) must seal imported boxes the same
   way, through `Credentials.AssociatedData`. The plaintext is `{"email":…,"token":…}`, and `key_id` is always
   `Keyring.TryReadKeyId(box)`.
2. **Rotation** is `Credentials.RotateAsync`. In one transaction it re-seals every row whose `key_id` is not the active key
   (`TryReseal`, checked with `IsSealedWithActiveKey`) and updates `key_id`. Rows no key opens are counted and left alone.
   Running it again is a no-op. The invite-box half of DESIGN §e's rotation command belongs to the invites owner.
3. **Config cache.** `Credentials.LoadAsync` caches a team's row for 30 s. Whoever writes `team_jira_config` (U26) calls
   `Credentials.Invalidate(team)`. `MarkStatusAsync` sets `status` and `last_checked_at` together.
4. **Unsaved credentials.** A config save needs Jira before anything is stored, so `ProbeAsync(team, host, email, token,
   projectKey?, boardId?)` runs `myself` + `field` + board resolution with those credentials. It goes through the same
   throttle, breaker and transport and never changes the stored status. Board resolution follows the original's first two
   rules (a numeric id, else the project's first scrum board, else its first board). The original's third rule, the first
   100 boards of the site, is dropped because it could pick an unrelated board (jira.md §2.1).
5. **Field discovery** ports `discoverJiraStoryPointsFieldId`: a schema `custom` containing `story-points` first, then a field
   named like "Story Points". The sprint field is the one whose schema contains `gh-sprint`. Nothing falls back to fixed ids
   (`customfield_10020` is never points). `JiraMap.JqlFieldRef` turns a field id into `cf[NNNNN]` and accepts only
   `customfield_<digits>`. Points are read and written through the configured field only, and `SetPointsAsync` without one is
   `jira_not_configured`. `ReadSprint` ports `createGetSprintMeta`, including legacy `…[id=…,state=…,name=…]` strings. It
   scans every custom field only when no sprint field is known.
6. **Bucket order.** `JiraMap.CompareSprints(name, start, name, start)` ports the comparator of `jiraBrowseSprintBuckets.ts`
   (valid start date first, then unparseable, then none; ties by `NaturalCompare`). It passes all 2,000 cases of
   `tests/golden/sprint-buckets.json`. `GetSprintsAsync` sorts with it, and U26 should use it for browse buckets. Jira's
   `+1000` offsets are normalized before parsing, and only ISO-8601 shapes parse, so `Sprint 5` is not a date (unlike
   V8's legacy parser).
7. **Retry rules.** Retries happen only on 429/503 and connect failures, at most 2. A `Retry-After` of 10 s or less (seconds
   or an HTTP date) is waited out exactly. A longer one is **not** waited out: the call fails at once with
   `jira_rate_limited` and `retryAfter` = Jira's value. Waiting 10 s and retrying before Jira's window reopens would only
   spend quota, and U10's `http.js` treats a long `Retry-After` the same way. Without the header the wait is full jitter
   over `min(2 s, 250 ms·2^attempt)`. POSTs (create, comment, link, transition, sprint/backlog moves) are retried on connect
   failure only. `POST search/jql` is a read and is retried like a GET. A read timeout is not retried, as §f says.
8. **Breaker.** Every attempt counts. A 5xx, an attempt timeout or a connect failure adds one, and any other response resets
   the count. At 5 the breaker opens for 30 s. After that, one more failure re-opens it at once (half-open), and a success
   closes it. An address refused by the SSRF check does not count, because it is our policy and not Jira being down.
9. **Throttle order.** A rate token first, then the team slot (4), then the global slot (16). A request waiting on the rate
   therefore holds no slot. The bucket reserves tokens, so waiters are served in arrival order.
10. **SSRF.** The handler resolves the name itself, and **every** answer must be allowed (one private address refuses the
    host). It connects to the vetted IP. There is no proxy (`UseProxy=false`) and no cookies (`UseCookies=false`, so one
    team's Jira session cannot leak to another), redirects are off, and connects time out after 5 s. Port and scheme are
    always `https:443`. Only tests change `JiraClientOptions.Scheme/Port/IsAllowedAddress/Resolver`.
11. **Redirects.** Any 3xx on an API call is `jira_unavailable`. For attachments, one hop is allowed to an absolute `https`
    URL on the default port, with no userinfo, whose host is the media host or a single-label `*.atlassian.net`. It is
    fetched without Authorization, through the same handler, and a second redirect is refused.
12. **Error codes beyond §f's table.** A non-raster attachment (SVG, HTML, octet-stream…) is `jira_attachment_unsupported`
    (415), and one over 5 MiB is `jira_attachment_too_large` (413). Any 4xx not in the table (409, 405, 410…) maps to
    `jira_validation` (422) with Jira's `errors`, if any. Unexpected 3xx, 5xx, unreadable JSON and a body over 4 MiB
    (counted after decompression) map to `jira_unavailable`. Field messages are cut to 300 UTF-16 units, control characters
    become spaces, and at most 50 fields are kept. Exception messages carry the code only.
13. **Single-flight** covers GETs and `search/jql` keyed by team + method + path + body hash. It runs without any caller's
    cancellation token, so one caller giving up does not fail the others. Writes and attachments are never shared.
    `JiraCache.GetOrCreateAsync` gives the same guarantee for cached values. A value whose key or tags were invalidated
    while it was being fetched is returned but not stored.
14. **JiraCache** is one LRU of 8 MB for every cache §f lists. Callers pass a size estimate (the Jira body length is a good
    proxy) and tags. `JiraCache.IssueTag(team, key)` is the tag a write to that issue invalidates. `GetFieldsAsync` caches
    the field catalogue for 6 h under the team tag.
15. **Path safety.** Issue keys must match `^[A-Z][A-Z0-9_]{0,19}-[1-9][0-9]{0,9}$`, project keys the `team_jira_config`
    regex, and attachment, transition and link ids must be numeric. Anything else throws `ArgumentException` before a request
    is built, so `..` can never reach a Jira path.
16. **`JiraIssueFields` is a class with a settable `Extra`.** The STJ source generator treats `init` properties as
    constructor members, and that cannot be combined with `[JsonExtensionData]`.
17. **DI.** `JiraClient.AddServices` registers `Credentials`, `JiraThrottle`, `JiraCache` and `JiraClient`. It also
    `TryAdd`s `TimeProvider.System`, `Keyring` (from `APP_KEYS`) and `JiraHostPolicy` (from `JIRA_HOST_ALLOWLIST`), each
    lazily, so a host without those settings still starts. Another unit may register its own first.

## FakeJira

`FakeJiraServer.StartAsync()` is an in-process Kestrel on `127.0.0.1:0`, plain HTTP. It serves every endpoint §f lists
with Basic auth, and paging that matches the specifications: Agile `startAt/isLast`, `search/jql` `nextPageToken`. It also
serves the attachment 303 to `api.media.atlassian.com`, plus `Gate` (hold requests in flight), `Script(method, pathPrefix,
replies…)` and a request log with the Host header. It answers for every host name, so the client reaches it through a
resolver that maps names to loopback. Running it as a container for `compose.test.yml` needs an entry point and a
certificate, which are left to the compose owner (U43/U45).

## Follow-ups for other units

- **U26:** call `Credentials.Invalidate` after writing config. Use `JiraCache.IssueTag` for browse/meta/detail entries and
  invalidate it after writes. Sort buckets with `JiraMap.CompareSprints`. Use `JiraMap.JqlFieldRef` for points filters.
  Check the attachment id against the issue's `attachment` field before calling `GetAttachmentAsync`, and set
  `Cache-Control: private, max-age=300` and `Content-Security-Policy: sandbox` on the proxied image. Map `JiraException.Error` to
  problem+json (`Fields` → `fields`, `RetryAfter` → `retryAfter`).
- **U41:** seal imported Jira boxes with `Credentials.AssociatedData(team)` as the AAD.
- **RUNBOOK (U43):** the key-rotation command calls `Credentials.RotateAsync`.
