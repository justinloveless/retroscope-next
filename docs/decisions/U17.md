# U17 decisions: email, magic link, reset, verify

U17 owns `Server/Auth/Tokens.cs`, `Server/Auth/Email/**`, `Server/Jobs/EmailWorker.cs` and its tests in
`tests/Retroscope.Integration.Tests/Email/**` (`Category=Email`).

## Contracts later units rely on

| Type | Use |
|---|---|
| `OutboxMail(to, subject, body)` | One plain-text mail. The constructor throws `ArgumentException` when `to` is not one bare address or `subject` holds a control character (CR/LF header injection) |
| `Outbox.Insert(mail, now)` + `Outbox.Kick()` | The outbox row as a batch command, for a caller's own transaction (U24 invites: the invite row and its mail commit together); `Kick` after the commit wakes the worker |
| `Outbox.EnqueueAsync(mail, with, ct)` | Writes the mail and `with` in one transaction, then kicks |
| `Templates.*` | Every mail body. `TeamInvite(teamName, link)` is there for U24: the team name is quoted on one line with URLs, host names, addresses and quotes removed (S8) |
| `Tokens.Issue / PeekAsync / ConsumeAsync` | `auth_tokens` (magic 15 min, reset 30 min, verify 24 h) |
| `AccountMail` | `IAccountMail` for U16, plus `MagicLinkAsync` and `PasswordResetAsync`; each calls `EmailBudget.TryReserve` first and drops silently over budget. U24 must call `TryReserve(email, ip, sender: inviter)` before its own `Outbox.Insert` |
| `EmailWorker.RunOnceAsync` | One send pass (U27's admin stats or a test can drive it) |

## Decisions where the spec was silent or did not fit

1. **In-house SMTP client instead of `System.Net.Mail.SmtpClient`.** §e allows the fallback "if it warns or fails".
   It fails a stated requirement: the `SmtpClient.EnableSsl` documentation (learn.microsoft.com, net-10.0, fetched
   2026-10-21) says implicit TLS ("SMTP/SSL … port 465") "is not currently supported", and §e asks for 587 STARTTLS
   **or** 465 TLS. Its server-certificate check is also process-wide (`ServicePointManager`), so tests could not trust
   the fake's certificate without trusting every certificate. `SmtpSender.cs` (about 340 lines with option parsing
   and MIME) speaks EHLO, STARTTLS (RFC 3207), implicit TLS, AUTH PLAIN/LOGIN, SMTPUTF8 and DATA with dot-stuffing.
   It refuses a server that does not offer STARTTLS, never sends credentials without TLS, validates the certificate
   against the system store and `SMTP_HOST` unless a callback is injected (tests only), and fails the send when the
   server pipelines bytes after its STARTTLS reply (the CVE-2011-0411 class).
2. **AOT check (DESIGN §12 row "SmtpClient works under AOT with STARTTLS").** The row is answered for the client
   actually used: a scratch AOT console compiled from `SmtpSender.cs`, `Outbox.cs` and the test's `FakeSmtpServer.cs`
   (`PublishAot`, `TreatWarningsAsErrors`, osx-arm64) published with zero warnings and delivered over STARTTLS and
   over implicit TLS with AUTH PLAIN against the fake. The server's own AOT publish is covered by `./build.sh aot-smoke`.
3. **`SMTP_SECURITY`** (new, optional): `starttls`, `tls` or `none`. Unset, it is `tls` on port 465 and `starttls`
   otherwise. `none` exists for a local relay such as mailpit in `compose.test.yml`; credentials are still refused
   on it. Without `SMTP_HOST` the worker logs a warning and mail stays queued, so test hosts and the route inventory
   start without SMTP settings. A malformed `SMTP_PORT`, `SMTP_SECURITY` or `SMTP_FROM`, or only one of
   `SMTP_USER`/`SMTP_PASSWORD`, fails startup. `SMTP_FROM` is `address` or `Name <address>`.
4. **Message format.** `text/plain; charset=utf-8`; `7bit` when the body is ASCII with lines ≤ 998 characters (all
   current templates), else `base64`. A non-ASCII subject or display name is an RFC 2047 encoded word. A non-ASCII
   address needs the server's SMTPUTF8, otherwise the send fails. `Message-ID` uses the sender's domain.
5. **Worker.** Only the leader sends (no `ILeaderEpoch` registered means a test host, which sends). A pass leases up
   to 20 due rows by moving `next_attempt_at` 10 minutes ahead (`for update skip locked`), so a crash mid-send retries
   after 10 minutes and two passes never send one row twice. Failures wait 1 min, 5 min, 30 min, 2 h, 6 h; the 6th
   failure nulls `body_text` and keeps the row with `attempts` and `last_error` (step and reply code only, never the
   address or the server's text) for retention (§b) to remove. Every failure is retried, 5xx included: a 535 from a
   misconfigured relay is fixable, and six tries cost little. The loop wakes on `Outbox.Kick` or every 30 s.
6. **Magic-link preview route.** §e says the masked email "comes from a `preview` POST" but §d has no row for it:
   `POST /api/auth/magic/preview {token}` → `{email: "a•••@example.com"}` or 400 `invalid_token`. It never consumes.
   The web unit owning `screens/auth.js` calls it, then `magic/consume` only on the click.
7. **Responses.** `magic/request` and `reset/request` answer 202 with no body for every well-formed address (400
   `invalid` with `fields.email` for a malformed one, which reveals nothing about accounts). `magic/consume` answers
   200 with the `/api/me` body and sets the session cookie (auth method `magic_link`); `reset/consume` and
   `verify/consume` answer 204. Every unknown, expired, used or malformed token is 400 `invalid_token`.
   `verify/consume` is `RoutePolicy.User` (anonymous: 401, the page shows "Sign in to finish verifying"); a live token
   of another user is 403 `other_account` and is **not** consumed, so its owner can still use it.
8. **Per-address limits** ("3/h/email") are subject buckets checked in the handler, separate for magic and reset.
   Over them the request still answers 202 and nothing is written, like the email budget; the route's per-IP limit
   (20/h) answers 429 as usual. The four token routes share a 30/min/IP limit, verify also 30/min per principal.
9. **Magic links for unknown or disabled addresses.** An unknown address gets a link with `user_id` null, so known
   and unknown addresses do the same work; consuming it creates a verified, password-less account with an empty
   `full_name` (display name "Player") or, if the address registered in between, signs into that account under the
   takeover rule. A disabled account gets no mail, and a link it already holds answers `invalid_token`.
10. **Reset consume** checks the password rule and that the token is live before hashing, hashes behind `HashGate`
    (busy: 503 without consuming the token), then in one transaction consumes the token, sets the hash, sets
    `email_verified_at` if unset, audits `auth.reset` and deletes every session; the sockets are closed after commit
    and this browser's cookie is cleared. The user signs in with the new password next. A reset does not claim: the
    password is replaced, and every session, the squatter's included, is gone.
11. **Login cap.** `LoginCappedAsync` sends a magic link with the `LoginCapped` template (U16 decision 4: there is no
    unlock purpose; signing in is the unlock).
12. **JSON context: one edit outside the owned paths.** U0's scaffold test requires every `JsonSerializerContext` to
    be chained in the frozen `Program.cs`, and no context exists for these routes, so a context of U17's own cannot
    pass it. They are auth routes, so their four DTO types (`Auth/Email/EmailRequests.cs`) are registered in U16's
    `Json/AuthJsonContext.cs`: four `[JsonSerializable]` lines and a `using`, nothing else. Request DTOs carry
    `[JsonUnmappedMemberHandling(Disallow)]` (U16 decision 2).
13. **`IAccountMail` registration** uses `Replace`, so it wins over U16's `TryAdd` of `NoAccountMail` regardless of
    module order.

## Not done here

- The e2e stack's SMTP settings (`compose.test.yml`: mailpit with `SMTP_SECURITY=none`) belong to whoever owns that
  file (U43/U48); this unit only makes the setting exist.
- `/api/admin/stats` reading `EmailBudget.Dropped` and outbox depth is U27's.
- Deleting dead outbox rows and expired tokens is U27's (`RetentionJob`, `TokenSweepJob`).
