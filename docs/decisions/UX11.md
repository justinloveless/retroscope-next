# UX11 decisions: the rich description editor, phases 4 and 5 (dependencies, build gate, editor core)

The owner decided on 2026-10-23 to build the full Jira description editor on ProseMirror, and accepted the five
approvals the design asked for:

1. ProseMirror as the first runtime web dependency, at exact versions, with a pin test.
2. A build-time rewrite of `prosemirror-view`'s `readHTML`, pinned by sha256, so no `innerHTML` ships.
3. A budget of about 90 KiB brotli for a lazily loaded `rich-editor` chunk.
4. Projected ADF sent to users with `JiraEditIssues`, only when they open the editor.
5. Whole-document `descriptionAdf` saves, which will replace the markup-and-islands description path.

The owner also asked for the editor chunk to be prefetched when the issue drawer opens for a user who can edit.
Mention search and image upload are in scope for later phases. The emoji picker is out for now. The real-Jira gates
G1–G3 are pending the owner's manual run.

This unit is phases 4 and 5 of the delivery plan: the dependency and its build gate, then the editor core with no UI.
It changes `web/package.json`, `package-lock.json`, `web/build.mjs`, `web/budgets.json`, `web/src/rich/` (new),
`web/styles/rich-editor.css` (new), one export in `web/src/poker/issue-drawer.js`, `THIRD_PARTY.md`,
`tools/quick.mjs` and the web unit tests. Approvals 4 and 5 are server work (phases 2 and 3) and are not here.

   - **Skipped as too new:** prosemirror-view 1.42.7 and prosemirror-transform 1.12.3 and 1.12.4, all published on
     2026-10-22.
   - **The three transitive packages are direct dependencies.** That pins them in `web/package.json` too, not only in
     the lockfile. The lockfile holds each package once, at the pinned version, from registry.npmjs.org, with a
     sha512 integrity hash.
   - **The image needs no change.** The Dockerfile's web stage already runs
     `npm ci --workspace web --include-workspace-root=false`, which installs a workspace's `dependencies` as well as
     its `devDependencies`. That step was reproduced against the new lockfile in an empty directory, and it installed
     all 15 packages and esbuild. `web/build.mjs`'s header comment no longer claims esbuild is all the stage installs.
2. **A pin test fails on any package change** (`tests/web-unit/core/deps.test.js`, the npm side of
   `DependencyRuleTests`). It checks four things:
   - **`web/package.json`:** `dependencies` and `devDependencies` equal explicit maps.
   - **The root `package.json`:** it holds the test tooling only.
   - **Versions:** every one is exact.
   - **The lockfile:** every non-dev package equals the runtime map, and every dev package is a listed one. The
     listed dev packages are esbuild and its platform packages, Playwright and axe-core.

   An added, removed or bumped package therefore fails `quick` and CI until the test's lists change, which is the
   owner's call (tenet 2).
3. **`readHTML` is rewritten at build time, and nothing that names a sink ships.**
   - **Where.** `VENDOR_REWRITES` in `web/build.mjs`, applied by `rewriteVendor` inside the `banned-sinks` plugin's
     `onLoad`, before the scan. `BANNED_SINKS` still scans every loaded file, after the rewrite. It has no exemption.
   - **The pin.** It applies to `prosemirror-view/dist/index.js` when the file's sha256 is
     `3cc9270e7b27a3b5a1bfc9ce3d63a8d7bf9c65eb2a811152d1a7ea478d2751e3` (1.42.6, the same file the prototype measured).
     Any other bytes fail the build with both hashes in the message. Each edit must match exactly once, or the build
     fails. A version bump therefore stops the build until someone reviews the new file and updates the pin.
   - **The six edits:**
     - `readHTML` becomes a function that throws `HTML clipboard parsing is disabled`. Its old body was the only
       `innerHTML` assignment.
     - The copy handler no longer writes `text/html`.
     - The drag handler writes `text/plain`, not `dom.innerHTML`.
     - The `capturePaste` fallback passes `null` for HTML, so it takes the plain-text branch.
     - The two comments that name `innerHTML` are removed.

     After these edits the scanned source has no sink match at all, reads included.
   - **The output is checked too.** After bundling, `buildWeb` scans every emitted `.js` file with the same regex and
     fails on a match. The inputs were already scanned; this check covers whatever a plugin or esbuild might produce.
   - **At run time** the rewrite is a second line of defence. The editor's `handleDOMEvents` own copy, cut, paste and
     external drop, and ProseMirror runs those handlers before its own. An internal drag-move uses the slice stored at
     dragstart and parses no HTML.
   - **Tests** (`build.test.js`):
     - the reviewed file loses every sink and keeps no call to the Trusted Types wrapper;
     - a planted, modified copy fails a bundle with the "not the reviewed file" error, and the reviewed copy passes;
     - an edit that matches zero or two times fails;
     - only `node_modules` files are rewritten;
     - no built chunk contains `innerHTML`, and exactly one chunk carries the rewritten view;
     - `scanBuiltScripts`, the output check, fails on a sink planted in an emitted script, and `buildWeb` calls it.

   - **Why nothing else moves.** A first version imported `isAllowedHref` from `markup/doc.js`. esbuild splits at
     module boundaries, so `doc.js` became a shared chunk of its own (2,168 B), and `/retro/:code` (17 → 18 chunks)
     and `/mentions` (9 → 10) gained a request on their boot path. A leaf module for the rule would not help: any
     module both the routes and the editor import becomes a chunk of its own. So `rules.js` carries a copy of the
     rule, plus the control-character check the server adds, and `tests/web-unit/rich/rules.test.js` pins the copy to
     `isAllowedHref` over a corpus that includes every character from U+0000 to U+00FF. The drawer grew by about
     33 bytes for the `loadRichEditor` seam. Chunk file names carry content hashes and chunks import each other by
     those names, so an edit to the editor alone moves other chunks by tens of bytes.
   - **The editor chunk.** It is almost all ProseMirror: the prototype measured the full package set at 71–73 KB
     before tree shaking. Toolbars, node views and menus come in phases 6–8, against about 19 KB of headroom.
5. **The schema mirrors the server's allow-list through one data file.** `web/src/rich/adf-schema.json` holds the
   allow-list of `Core/Adf/AdfSchema.cs` as data: nodes, marks, attributes with their value rules, content groups and
   block marks by parent. The rules are int, number, enum, bool, string with pattern and length, strict hex colour,
   href with schemes, timestamp and number list.
   - **One for one with the server table** (`rich/server`, commit `0f34862` read on 2026-10-23):
     - the groups are AdfSchema's contexts under the same names (`expand`, `blockquote`, `cell`, …), less the
       preserve-only types, which reach the editor as `rsOpaque` or `rsOpaqueInline`;
     - `contextMarks` is the contexts' `ParagraphMarks` and `HeadingMarks`, keyed by parent node: both marks in the
       document and a layout column, only `alignment` on a paragraph in a cell, none anywhere else;
     - a node's `marks` is its `AdfNodeSpec.Marks` (a link on `mediaSingle` and `media`);
     - string lengths count code points, and every string refuses control characters (`char.IsControl`), as
       `AdfSchema.ValidString` does; text follows `ValidText` (tab anywhere, CR and LF only in a code block);
     - tokens sit only where the context allows opaque children: never directly in `bulletList`, `orderedList`,
       `decisionList`, `mediaSingle`, `mediaGroup`, a table, a row or a layout section;
     - `listItem` and `taskList` have no first-child rule, because `AdfWrite` has none; `mediaSingle` keeps `media`
       first, as `AdfWrite.Structure` requires; `tableRow` may be empty, as the server's context allows.
   - **Client-only data.** Three entries have no field in `AdfSchema` and come from `AdfWrite`: `colwidth`'s length
     must equal `colspan`; `code` combines only with `link` (plus `rsMark`); `doc.version` is 1.
   - **What is built from it.** `schema.js` builds the ProseMirror schema from that file, and `adf.js` validates
     against the same compiled rules. Node and mark names are the ADF type names, and every allow-listed attribute is a
     ProseMirror attribute whose `validate` is its rule. Content expressions come from the file's child lists. Only the
     ProseMirror roles (`tableRole`, `defining`, `isolating`, `code`) and `toDOM` are written in code.
   - **Attributes the editor owns.** These are never sent as such:
     - `rsKeep`, the server's stash ref;
     - `blockMarks`, the ADF marks of a non-text node, such as an `rsMark` or a link on media;
     - `align` and `indent`, a paragraph's or heading's `alignment` and `indentation` marks;
     - `adfShape`, the attribute keys a node arrived with.
   - **Block marks by parent.** ProseMirror cannot make an attribute depend on the parent, so `block-marks.js` adds a
     guard plugin: after any document change it clears `align` or `indent` from a block whose parent does not allow
     it, so a wrap into a list, a paste or a drag never leaves a mark the save refuses. The walk skips inline content.
     `contextMarks(parent, node)` in `rules.js` is the helper phase 6 uses to enable the align and indent commands.
   - **Tokens.** `rsOpaque` and `rsOpaqueInline` are atom nodes whose only attribute is `ref`. `rsMark` is a mark with
     `excludes: ''`, so several can cover one text.
   - **Required attributes default to null.** ProseMirror refuses a schema in which a required content position holds
     only nodes it cannot create without attributes, such as `layoutColumn{2,3}` or a task list's first item.
     `isComplete(node)` reports a node that still lacks one, and the paste path drops anything that filling left
     incomplete. ProseMirror does not validate defaults, so the reader checks required attributes itself, also on a
     node that arrives with no `attrs` member. Phase 7 fills ids and widths when it creates such nodes.
   - **Keeping it in sync: a cross-check test, not a generated file.** A generated export was the first plan, but
     the file carries data the C# table does not model (the `AdfWrite` rules above, group membership with tokens) and
     the editor-only shape (shared rules, `@group` references) would have to move into C#. A test that reads both
     sides keeps each in its natural form:
     - **Server side (follow-up 1).** A Core test (`Category=Adf`) loads `web/src/rich/adf-schema.json` with
       `JsonDocument`, no new package, and asserts for every editable node and mark: the same attribute names, type,
       required flag, min and max (lengths in code points), enum values and check (pattern, colour, href, card URL,
       timestamp); each context's child set less preserve-only types, plus `rsOpaque` where `OpaqueChildren` is true;
       `Min` and `Max`; `ParagraphMarks` and `HeadingMarks` against `contextMarks`; and `CodeTextMarks`. Its
       `tools/quick.mjs` row maps both files to it. It cannot land on this branch: `AdfSchema.cs` exists only on
       `rich/server`, which is not in this branch's base, so the test belongs to whichever branch first holds both.
     - **Client side (here).** `tests/web-unit/rich/schema.test.js` pins the ProseMirror schema to the file: the same
       nodes and marks, exactly the allow-listed attributes plus the editor's own, each node accepting exactly the
       listed children (by walking ProseMirror's content automaton), inline-ness, `code` combining only with `link`
       and `rsMark`, and the value rules. `adf.test.js` checks the reader against the server's limits on both sides of
       each value reconciled in this unit.
     - **Why JSON.** A C# test can read a JSON file with `JsonDocument` and no new package, and esbuild bundles it.
       Node imports it with `with { type: 'json' }` (checked on Node 20.19; CI runs Node 22).
6. **ADF conversion (`adf.js`).** Three entry points cover two directions:
   - **`adfToPm(adf)`** is strict. The projection must never send anything outside the allow-list, so an unknown
     node, member, attribute or mark, a refused value, a bad nesting, a bad text or a cap throws `AdfError {code,
     path}`. Paths and codes follow the server's (`content.3.content.0.attrs.href`). The editor would not open on
     such input.
   - **`adfFragmentToPm(list, {session})`** is the paste mode. It drops what fails instead of throwing; see
     decision 8.
   - **`pmToAdf(doc)`** rebuilds the document from attributes.
     - It writes an attribute when its value differs from the default, or when the node arrived with that key.
       `"language": null` and `colspan: 1` therefore survive.
     - It writes `attrs: {}` and `content` when the node arrived with them.
     - On an inline atom it writes only `rsMark` marks: a bold range over a status leaves the status alone.
   - **Canonical equality** (`canonicalAdf`). ProseMirror introduces exactly three differences:
     - key order;
     - mark order (it sorts marks by schema rank);
     - joined adjacent text nodes with the same marks.

     None has a meaning in ADF. `canonicalAdf` sorts keys and `marks` arrays and joins such text nodes. The client
     will compare documents before saving, so a no-op edit skips the PUT, as the design asks.
   - **Round-trip test.** `tests/web-unit/rich/_project.js` stands in for the server's projection, driven by the strict
     reader's own errors:
     - an unknown attribute moves into `rsKeep`;
     - a refused mark becomes `rsMark`;
     - any other refused node becomes `rsOpaque` or `rsOpaqueInline`, with the server's 16-character ref form.

     Every doc case in `tests/fixtures/adf/*.json` is projected first: 80 documents. Then `pmToAdf(adfToPm(p))` is
     canonical-equal to `p`, and every token ref keeps its count. Because the projection follows the reader's own
     errors, a reader that started refusing an allowed node would still round-trip, so the test also names the 25
     fixtures allowed to need a token (hostile values, unknown nodes, `blockTaskItem`, a heading in a quote, images
     without the required `layout`) and requires every other fixture to open unchanged.
7. **Tokens are never cloned (`tokens.js`).**
   - **The guard.** `tokenGuard(base)` refuses any transaction that raises a token ref's count above the count in the
     document the editor opened with. So a move (delete and insert in one transaction) and re-inserting a deleted
     token both pass, and inserting a copy fails.
   - **Cost.** Only steps whose slice carries a token, stash or node mark trigger a count, so typing never walks the
     document.
   - **Splits and copies.** A split or a copy repeats a node's attributes, so `appendTransaction` keeps an `rsKeep` or
     node-level `rsMark` ref on the node that held it before the transaction (its old position mapped forward) and
     clears it from the others. A copy inserted before the original therefore does not take its stash. When the
     original was deleted in the same transaction (a move), the first carrier keeps it.
   - **Not guarded.** Text `rsMark` marks are left alone: one mark spans several text nodes legitimately.
8. **The clipboard (`clipboard.js`).** A copy writes `text/plain` and `application/x-retroscope-adf+json`, which
   holds ADF and the slice's open depths. A paste reads that type through the paste-mode reader, and otherwise plain
   text. Chromium hands that type to any origin, so it is parsed as hostile. The paste rules:
   - **Tokens never enter.** `rsOpaque`, `rsOpaqueInline`, `rsMark` and `rsKeep` are dropped.
   - **Unknown nodes and marks are dropped.** Extensions are among them, and so are names inherited from
     `Object.prototype` (`constructor`, `__proto__`): only that mark or attribute goes, not the whole paste.
   - **One mark of each type.** A text with two links or two `strong` marks keeps the first of each.
   - **Links and colours.** A link whose href fails the read view's rule loses the link mark and keeps its text. A
     colour that is not a strict `#rrggbb` is dropped. A card with a refused URL is dropped. A status with a hex colour
     is dropped: hex statuses are accepted only from the base.
   - **Mentions.** One whose id is not in `session.mentions` becomes its display text. The session holds the ids
     picked in this editing session, and the editor will add the base document's ids, which the server accepts too.
   - **Media.** A media node is kept only for `type: "file"` with an id in `session.media`, the base's media and this
     session's uploads. Otherwise it is dropped, and so is an image left without its media.
   - **Local ids.** Optional `localId`s are dropped. Required ones (tasks, decisions) are regenerated, because a pasted
     copy would otherwise repeat an id (`duplicate_local_id`).
   - **Caps.** A payload over 1 MiB, nested deeper than 32 or larger than 5,000 nodes pastes nothing. Open depths are
     clamped to what the content can open. The strict reader's caps are 48 levels and 20,000 nodes.
   - **Code blocks.** A paste into a code block takes `text/plain` only.
   - **Drops.** An external drop is refused until media upload lands in phase 11.
9. **The chunk seam and the prefetch.** `issue-drawer.js` exports `loadRichEditor()`, a dynamic `import()` of
   `web/src/rich/rich-editor.js`. Nothing calls it yet. It makes the chunk build and be measured while no UI uses it.
   - **The entry module.** `createRichEditor({host, adf, session})` is the seam that phase 6 fills. It wires the
     schema, history, the base keymap, list and table keys, a few input rules, the table, gap-cursor and drop-cursor
     plugins, the token guard and the clipboard handlers. Wiring them now keeps the measured size honest.
   - **The prefetch.** The owner's request belongs to phase 6, when the drawer has a user who can edit and a reason to
     load the chunk. It will call `loadRichEditor()` when the drawer opens for such a user.
10. **`rich-editor.css` is its own stylesheet and is not in `ROUTE_STYLES` yet.** It adapts ProseMirror's three
    stylesheets (whitespace, selection, gap cursor, table selection) to the app's tokens, plus a token placeholder
    style. It is built and budgeted as `css:rich-editor`. Phase 6 decides whether the drawer links it on open or
    whether it joins the poker route.

## Coordination with the server phases (`rich/server`)

These are assumptions this client makes. The server's projection and validator should match them:

0. **Where the client follows the server and Jira may disagree.** `AdfWrite` enforces no first-child rule on
   `listItem` or `taskList`, and allows an empty `tableRow`; the client follows. If the real-Jira gates (G1–G3) show
   Jira refusing such a document, both sides should add the rule together.

1. **`rsMark` and `opaque_duplicated`.** One mark object spans several text nodes once other marks split the text, and
   editing splits it further. The duplicate count must not count `rsMark` per text node.
2. **`rsKeep` placement.** Text nodes never carry `rsKeep`: ProseMirror text has no attributes. A stash for a text
   node's unknown members would have to make it `rsOpaqueInline`.
3. **Unrepresentable parents go opaque.** A refused node must become a token in a parent that lists `rsOpaque` in
   `adf-schema.json`. A refused cell, row or column cannot stand alone, so the projection must make the nearest
   ancestor that can hold a token opaque. That means the table or the layout section, not the cell.
4. **Null attributes.** The client writes back a `null` attribute only when the node arrived with that key, as with
   `codeBlock.language: null` from Jira. The validator should accept it where the base holds it.
