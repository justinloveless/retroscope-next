# U6 decisions: ADF

U6 owns `src/Retroscope.Core/Adf/**`, `tests/fixtures/adf/**` and `tests/Retroscope.Core.Tests/Adf/**`.

## Public surface (for U19, U26, U36)

| Member | Use |
|---|---|
| `AdfToDoc.Render(adf, attachments) → Doc` | Read-only rendering (comments). Never throws on Jira content |
| `AdfToDoc.Description(adf, attachments) → AdfDescription` | Editor view of a description: `Doc` (editable blocks plus `island` nodes), `Islands` (island id → original top-level ADF block text, verbatim), `Editable` |
| `MarkupToAdf.TryWrite(doc, islands, out adf, out missingIsland)` | Edited description back to ADF; false (with the id) when the Doc names an island the caller does not hold, which U26 answers with `stale` |
| `MarkupToAdf.Write(doc)` | Comments, new issues and retro "Create in Jira": no islands |
| `AdfAttachment(Id, FileName, MimeType, Created)` | One entry of the issue's `attachment` field; `IsImage` is the proxy's content-type list |
| `AdfToDoc.MaxDepth` (32), `MaxNodes` (5,000), `TruncatedText`, `MissingImageText` | The §f caps and placeholders |

Input is a `JsonElement` (U19's DTO can keep `description` and comment `body` as `JsonElement`; that is AOT-safe and keeps the
original bytes). Output ADF is a JSON string for U26 to embed with `Utf8JsonWriter.WriteRawValue`.

## Decisions where the spec was silent or did not fit

1. **What is editable is decided by a round trip, not only by a type list.** A top-level block stays editable when (a) it uses
   only the §f subset (paragraph, heading, bulletList, orderedList, listItem, codeBlock, blockquote, rule, text, hardBreak;
   marks strong, em, strike, code, link with only `href`; attributes `localId`, `level`, `order`, `language`), nested the way
   both the ADF schema and the markup grammar allow, with no C0 control characters or lone surrogates in text, and (b) its
   rendering, written as markup, parsed again and converted back by `MarkupToAdf`, has the same *visible content*
   (`AdfLossiness.Project`). Everything else becomes an island. This is the "no lossy write ever" guard: a link with a `title`,
   a code block with `wrap`, an aligned paragraph, a heading with a line break, emphasis around code, a heading inside a
   quote, a nested list deeper than markup allows and similar cases are islands instead of being simplified on save.
2. **What "same visible content" ignores.** `localId`s, empty paragraphs (and empty headings), spaces and tabs at the edges of a
   line (markup trims them), bold/italic/strike on whitespace, trailing hard breaks, and `( ) < >` and space in a link href
   versus their percent-encoded form (markup cannot hold the raw characters; the URLs are equivalent). Saving an edited
   description therefore drops empty paragraphs used as spacing and Jira-side `localId`s on editable blocks. Islands keep
   everything.
3. **Mention paragraphs are islands** (carried follow-up, U4 decision 2). Mentions render as their display text (`@Name`),
   emoji as their text or short name, dates as `yyyy-MM-dd` (UTC), inline/block/embed cards as links when the URL is
   http/https/mailto, otherwise text. Each of these makes its paragraph an island in a description.
4. **Island ids** are `base64url(sha256(canonical subtree)[0..12])`: 16 characters, a valid markup island id. Canonical form:
   object members sorted by ordinal name, no whitespace, strings re-encoded by `Utf8JsonWriter`'s default encoder, numbers as
   written. §f's `[0..12]` is read as 12 bytes (96 bits) rather than 12 hex characters, so a collision cannot splice the
   wrong block. Identical blocks share an id and one `Islands` entry (the first one's text).
5. **Splice-back is byte for byte**: `Islands` holds `JsonElement.GetRawText()` of the original block and `MarkupToAdf`
   writes it with `WriteRawValue`. Formatting, member order and escapes survive (tested).
6. **Media mapping (F20).** Media nodes are matched to attachments by `attrs.alt` (the filename, ordinal comparison). When
   several attachments share a name they are ordered by `Created`, then by numeric id; the n-th distinct media id with that
   name takes the n-th upload. The same media id twice maps to the same attachment. A media node with no `alt`, or more media
   ids than uploads, renders "image (open in Jira)". A resolved attachment that is not PNG, JPEG, GIF or WebP (including SVG)
   renders as "`name` (open in Jira)" text, because the proxy refuses those types. External media renders as a link (the CSP
   does not allow remote images). `mediaSingle` captions render as a paragraph after the image.
7. **Truncation.** Every visited node counts against the 5,000 cap, and nodes deeper than 32 are skipped. `Render` appends one
   italic "content truncated, open in Jira" paragraph. In `Description`, a truncated block is always an island (its raw text
   is complete, so a save stays lossless); a run of consecutive truncated islands shows the notice once, and islands past the
   size cap render empty. Recursion depth in the island-id hash is bounded by the caller's `JsonDocument` depth limit
   (64 by default).
8. **Rendering choices for ADF-only nodes.** `panelType` `tip` maps to `success`, `custom` and unknown types to `info`. Status
   colours outside the six names (including `#rrggbb`) are `neutral`. Nested task lists are flattened into their parent
   (`DocTaskItem` has no depth); `blockTaskItem` paragraphs become lines of one task. `decisionList` renders as a bullet list.
   Table `colspan`/`rowspan` are ignored (`DocTableCell` has no span), which is how §f's "no colspan > 10" is met.
   `layoutSection`, extensions and any other container flatten to their children; unknown leaves to their `text` or
   `attrs.text`. Heading levels are clamped to 1–6; an `orderedList` `order` outside 0–999,999,999 or not an integer starts
   at 1. A code block language markup cannot hold is dropped from the rendering (and makes the block an island).
9. **Marks become nested nodes by longest run.** At each position the mark covering the longest run of text becomes the outer
   node; ties go to link, then bold, italic, strike, underline. Emphasis runs continue over line breaks and whitespace (which
   carry no visible emphasis) but never open or close on them, and whitespace at the edges of an emphasis node moves outside
   it, because markup emphasis cannot open or close on whitespace. A link run never crosses a line break (a markup link label
   cannot). Code with other marks keeps them in the rendering; in a description that makes the paragraph an island.
10. **`MarkupToAdf` follows the ADF schema** (`@atlaskit/adf-schema` 57.7.20 `json-schema/v1/full.json`, read from unpkg on
    2026-10-20 for this decision; nothing is pinned): list items and quotes hold only paragraphs, lists and code blocks, at
    least one, and a list item that opens with a list gets an empty paragraph first. So a heading inside a list item or quote
    becomes a paragraph, a rule there is dropped, and a quote inside either is flattened into it. The `code` mark is combined
    with `link` only, so emphasis around inline code is dropped. Retro mentions become `@Name` text (the token's name; the
    author wrote it) and board images become their alt text or "image", since board blobs cannot be attached to Jira from
    here. `MarkupToAdf` throws for ADF-only Doc kinds (panel, table, status, attachment…), as `MarkupWriter` does.
11. **`Editable` is false only when the description is not an ADF `doc`** (for example an array or a bare paragraph). A null
    or missing description is an empty, editable Doc.
12. **Lone surrogates.** An escaped lone surrogate makes `JsonElement.GetString()` throw; such a string is read as a single
    U+FFFD rather than failing the whole issue, and the block holding it is an island.

## Verification

`dotnet test tests/Retroscope.Core.Tests --filter Category=Adf`:

- `tests/fixtures/adf/*.json` (blocks, inline, islands, media, hostile): one fixture per node type and mark (a test fails if a
  node type or mark in its list appears in no fixture), each converted and compared with its expected Doc. Every description
  fixture is also saved through markup and `MarkupToAdf`: islands must come back byte for byte and editable blocks with the
  same content. Island ids in the fixtures were computed independently in Python (`json.dumps(sort_keys=True,
  separators=(',', ':'))`), and two vectors are asserted directly.
- Island classification for table, mediaSingle, panel, expand, status, date and coloured text (plus mention, emoji, inline
  card, underline, task and decision lists, link titles, code options, alignment, cards, layouts); moving and deleting islands
  around edited text; an unknown island id is reported, not written.
- Hostile input: `javascript:`, `vbscript:`, `data:`, protocol-relative, control characters and non-string hrefs are dropped;
  mistyped members and junk nodes are ignored; depth and node caps, and a 20,000-node wide document converts in well under 2 s.
- markup → ADF → markup over the whole shared markup corpus (exact unless the case needs lowering) and 20,000 fuzz inputs
  (no island, same content, fixed point after one pass). During development the fuzzer also ran 200,000 inputs on each of
  12 further seeds.

## Follow-ups for other units

- **U19/U26:** keep the description and comment bodies as `JsonElement` and pass the issue's `attachment` list. U26's
  `IslandStore` keeps `AdfDescription.Islands` for the 60 s detail cache; `GET issues/{key}` returns `Islands.Keys` as
  `islandIds`. A description write must check `MarkupLimits.Check(text, MarkupField.JiraDescription)` first, then
  `TryWrite`; a false return is `stale`. When `Editable` is false the drawer must not offer description editing.
- **U26:** the 32,000-code-point `JiraDescription` limit applies to the markup, where islands are short refs; a very long
  editable description could exceed it. Nothing here truncates.
