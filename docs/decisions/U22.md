# U22 decisions: retro room

U22 owns `src/Retroscope.Server/Realtime/Rooms/RetroRoom.cs`, `src/Retroscope.Server/Realtime/Stores/RetroStore.cs` and
`Server/Json/RetroRoomJsonContext.cs` (U0 decision 3; the store passes no JSON, so the placeholder stays). §k names no test
path; the `Category=RetroRoom` tests live in `tests/Retroscope.Integration.Tests/RetroRooms/**`, following U13 and U14.
The folder is plural so its namespace does not hide the `RetroRoom` class.

## Decisions where the spec was silent or did not fit

1. **Registration without `AddRoom`.** `ActorsModule.AddRoom` resolves `IAccessView` with `GetRequiredService`, and the
   only implementation is U23's membership cache, which is not merged. Every test that boots the real host (the U11
   route inventory) would fail to start. `RetroRoom.AddServices` registers the same `RoomType.Of(binding, store, access)`
   itself and takes the access view with `GetService`, falling back to one where every role and grant is absent (the
   precedent is U11's `PolicyRoomAccess`). The factory runs after every module registered, so U23's view wins whatever
   order or `TryAdd` style it uses. **Integrator:** once U23 is merged this can become `services.AddRoom(...)`.
   `ITeamNotices` (also U23) is optional in the same way; without it no notices are sent.
2. **`ANON_TAG_KEY` is read on first use** (`ConfiguredAnonTagger`), like U1's lazy `Db`: the health probe, the route
   inventory and `aot-smoke` start without it, and the first anonymous post or ownership check throws when it is missing.
3. **Durability.** `MembersReplaced` and `MaxEndorsementsChanged` are written by the team actor and `AccessChanged` by
   its HTTP route, so the board sequences them as `Ephemeral` (no transaction, still on the wire). Everything else is
   `Committed`.
4. **Visibility and password are written by U25, not by the board.** `AccessSet` carries the visibility and
   `PasswordSetAt` but not the bcrypt hash, and §b ties all three together with CHECKs, so the board cannot write them
   from its event. **U25:** update `visibility`, `password_hash` and `password_set_at` in one transaction, then
   `AskAsync(AccessSet)` so the live board shows the change, then `registry.AccessChanged(room)` to kick subscribers who
   lost access. Unlock grants (`board_access_grants`) have no `RetroInput` either and are written by the unlock route.
   If U8 later adds the hash to `AccessSet`, the store can take the write over.
5. **Images.** One statement per post marks the referenced board images attached (`coalesce`, so the first time
   stays) and, for an anonymous card, comment or edit, sets `created_by = null` (S6). It is scoped to the board and
   `purpose = 'board_image'` and divides by `count(*) = cardinality(ids)`: an id that is missing, on another board, or
   an avatar fails the whole transaction (SQLSTATE 22012), so the command is nacked `internal` and nothing is written.
   The decider cannot see `blobs` (U8 decision 10), and the actor maps every refused transaction to `internal`; a
   client only sends such an id if it was tampered with.
6. **Mentions** follow the body: an edit deletes the rows of users no longer mentioned and inserts new ones (rows that
   survive keep their time); deleting a card, comment or column deletes the rows of every card and comment that
   cascades.
7. **Action items.** `CardAdded.ActionItem` is inserted into `team_action_items` in the card's transaction (create in
   place, §c.2), with `created_by = null` for an anonymous card. The board never updates that table afterwards: card
   deletes reach it through `ON DELETE SET NULL` and text sync goes through the team actor.
8. **Team notices are posted after the commit.** `RetroStore` implements `IRoomStore.CommitAsync` again so the notices
   follow the base commit; a notice that fails is logged and never surfaces as a commit failure (that would poison the
   actor although the commit stood). On team boards:
   * `ActionItemCreated` for `CardAdded.ActionItem`;
   * `ActionItemTextChanged(card, body, version)` for **every** card edit, and `SourceCardDeleted` for every deleted
     card (also those cascading with a column). The board does not know which cards are sources (imported items, a
     moved action-items flag), and the team actor ignores cards it does not hold (U9 decision 5);
   * `ActionItemCommentsChanged(item, count)` when a comment is added or deleted on a card that is an item's source.
     The item id is looked up by `source_card_id` after the commit (imported items do not use U8's derived id); the
     count comes from the board's state;
   * `BoardsChanged` on rename, stage change and archive.
9. **`last_activity_at`.** Every commit carries `update retro_boards set last_activity_at = now() where id = $1 and
   last_activity_at < now() - interval '1 minute'`: no state to track, and the row is written at most once a minute
   (§c.8). Board-level changes also bump `updated_at`.
10. **Load.** A board with `deleted_at`, or of a soft-deleted team, loads as missing (`not_found`). Authors are read
    from `principals`/`users` with the §b display rule (nickname, full name, `User`; never the email). A
    `legacy_author` label without a principal loads as a guest-badged author with no `pid`; a row with neither author
    nor tag is anonymous. Team members come from `team_members` in `TeamProjection.Roster` order, so a later
    `MembersChanged` with the same roster stays a no-op. Only the readiness rows of the current stage are loaded.
11. **The retro timer** needs nothing extra: the runtime arms `RetroDecider.Timers` after the loading message, so a
    timer that ended while the process was down is due at once and expires exactly once (tested across two restarts).
12. **Order of the action-items swap.** `retro_columns_one_action_uq` is not deferrable, so `ActionItemsColumnSet`
    clears the old flag in one statement and sets the new one in a second. Column reorders rely on the deferred
    `retro_columns_sort_uq`.

## Follow-ups for other units

- **U13 / UF7:** nothing implements `IRoomGateway` yet (`UnavailableRoomGateway` is still registered), so a real socket
  cannot reach a board. The tests drive boards through `ActorRegistry` with `TestPeer`, as U13's do.
- **U8 / U25:** deleting a board has no `RetroInput` and `RetroBinding.IsDeleted` cannot see a deletion. U25 can soft
  delete the row and use `ActorRegistry.TryPurgeAsync`, or U8 can add a deletion input that the binding reports through
  `IsDeleted` (subscribers are then kicked with `deleted`).
- **U23:** register `IAccessView`, `IMembershipLookup` and `ITeamNotices`; post `RetroInput.MembersChanged` and
  `TeamSettingsChanged` to live boards of the team.
- **Integrator (UF6):** the idempotent-create rule for retro cards, comments and columns lands in `Core/Retro`; nothing
  in the store depends on it.

## Verification

- `dotnet test tests/Retroscope.Integration.Tests --filter Category=RetroRoom`: 13 tests pass. They cover every client
  command plus archive/unarchive through the real store, compared with a fresh load after a restart (both snapshot
  variants and three overlays); anonymous cards, comments, images and action items with no principal in any column,
  and the author's edit and delete after a restart; attached images and refused foreign, avatar and missing ones;
  mentions on add, edit, comment and cascade; stale preconditions writing nothing; a timer expiring once after a
  restart; the action item created in place and every team notice; action-item comments from the team page;
  subscribe access and deleted boards or teams.
- Mutation checks: keeping `created_by` on anonymous images, dropping the attach count check, and dropping the mention
  cleanup on edit each fail a test.
- `./build.sh test`: see the unit report.

1. `RetroRoom.AddServices` uses `services.AddRoom`; the `NoAccess` fallback is gone (U23 registers `IAccessView`).
2. `ActionItemCommentsChanged` is computed from a card → action item map loaded with the board and kept from its own
   events, so the commit path makes no extra query.

   names nobody.
