# U34a decisions: the shared markup editor

## Decision gate: the contenteditable editor ships

The primary design (§g.6) passes every U34a check on Chromium, Firefox, WebKit and mobile WebKit (iPhone 13
profile). Repeated runs (`--repeat-each 3`, and `--repeat-each 2` after the last spec was added) passed with no
retries and no flakes. The textarea + preview fallback is
therefore **not** built. If a later browser regression forces the fallback, it goes behind the same
`createEditor` API.

## Public API (for U34, U35, U36 and U33)

`createEditor(options)` in `web/src/markup/editor.js` returns `{el, input, getValue, setValue, focus,
selection, select, update, destroy}`.

| Option | Meaning |
|---|---|
| `value` | initial markup, canonicalised on the way in |
| `dialect` | `retro` (default), `jira` or `jira-description` (U4 decision 1) |
| `mentions` | `[{id, name}]` or a function returning it: the `@` listbox and the current names of pills |
| `islands` | `Map<id, island DocNode>` for Jira descriptions; islands are read-only atoms |
| `onSubmit(markup)` | when set, Enter submits and Shift+Enter adds a line; without it Enter adds a line |
| `onChange(markup)` | every change of the canonical value (typing, undo, paste, transforms) |
| `uploadImage(file) → Promise<blobId>` | pasted or dropped PNG/JPEG/GIF/WebP (retro dialect only); the caller posts to `/api/retro/{id}/images` |
| `imageSrc`, `placeholder`, `label` | passed to `render()`; `aria-placeholder`/`data-placeholder`; `aria-label` |

`setValue` resets the undo history and does not call `onChange`. Drafts in `sessionStorage` and restoring a
nacked create are the caller's job (`composer.js`, U34): both are `setValue` plus `onChange`.

## Decisions where the spec was silent or did not fit

1. **Caret offsets are linear-text offsets, not markup offsets.** §g.6 says `caret.js` maps markup offsets to
   DOM positions. Markup offsets move whenever the canonical writer escapes or re-delimits text, so they do
   not survive a normalise. `caret.js` instead counts visible content: one per character, one per atom (any
   `contenteditable=false` element: mention pill, image, island, rule), one per line break and one between
   blocks. A trailing filler `<br>` counts nothing. `render(parse(markup))` produces the same linear text as
   the DOM it replaces, so `(markup, caret)` snapshots restore exactly.
2. **The value is canonical.** `domToDoc` serialises the DOM through the allow-list, then the value is
   `toMarkup(parse(toMarkup(doc)))`. Marks never nest inside the same mark, adjacent equal marks merge, and
   whitespace at the edge of a mark moves outside it, because the writer cannot open `** a**`. The DOM is
   re-rendered only when it holds something `render()` would not produce, or when the visible text (ignoring
   whitespace) would change. So a trailing space or an open last line stays on screen while the value is
   already trimmed.
3. **Typing is native, structure is not.** The browser handles plain text input, IME and block merges. The
   editor handles Enter and Shift+Enter (`<br>`, plus a filler `<br>` at the end of a block), atom deletion,
   paste, drop, undo/redo and formatting. Formatting uses DOM Range operations, never `execCommand`.
   `beforeinput` `format*` intents (Safari menus) are cancelled. Bold, italic and strike are mapped to the
   markup; the others have no markup form. `insertParagraph` from soft keyboards counts as Enter.
4. **IME.** The editor never serialises or re-renders between `compositionstart` and `compositionend`, and
   it ignores Enter with `isComposing` or keyCode 229. CDP `Input.imeSetComposition` exists only in
   Chromium, so the Korean, Japanese and Chinese specs run there. Firefox and WebKit get a test that replays
   the event sequence an IME produces (`compositionstart`, `insertCompositionText` inputs with
   `isComposing`, `compositionend`). Playwright cannot drive a real IME in those browsers.
5. **Collapsed Ctrl/Cmd+B/I/E** arm a pending mark for the next typed text. Moving the caret clears it.
   A selection is trimmed of outer whitespace before a mark is applied.
6. **Ctrl/Cmd+K** opens a one-field link form under the editor. Inside a link it removes the whole link.
   The address is normalised by `normalizeHref`. It adds `https://` to a bare host and percent-encodes
   spaces, `(`, `)`, `<` and `>`, because the U4 grammar refuses them in an href (carried follow-up).
   Schemes other than http, https and mailto are refused, and the field is marked `aria-invalid`.
7. **One Backspace/Delete removes an atom** next to the caret. For block atoms (islands, rules) that also
   holds across the paragraph break. For an inline pill at the end of the previous paragraph, Backspace
   merges the paragraphs as usual.
8. **Mentions.** `@` followed by up to 32 non-space characters, at the start or after whitespace or `(`,
   opens the listbox. It shows up to 8 people, prefix matches first. ↑/↓ move, Enter/Tab choose, and Esc
   closes it without letting the event reach an enclosing dialog. A chosen person becomes a pill plus a
   space. Pills show the current name from `mentions`. A pill whose person is not in `mentions` shows
   `@unknown` (U5 renderer) but keeps the token's name in the value.
9. **Styling.** The only inline style is `white-space: pre-wrap` on the input, set through CSSOM (allowed
   under the CSP). Without it browsers type `&nbsp;` runs and the linear model drifts. Everything else is
   class-based (`rs-editor`, `rs-editor-input[data-empty]`, `rs-editor-mentions`, `rs-editor-link`).
10. **Size.** Minified and brotli-compressed, `editor.js` + `caret.js` + `undo.js` come to 6.6 KB (budget
    8 KB, §g.7). `parse.js`/`render.js`/`doc.js` add 3.3 KB more, but retro and the Jira drawer load them for
    read-only rendering anyway.

## How the browser specs run

`tests/e2e/fake/editor/*.spec.js` serve their own page through `page.route('https://editor.test/**')`: an
esbuild bundle of `_harness-entry.js` under the production CSP (`script-src 'self'`,
`require-trusted-types-for 'script'; trusted-types 'none'`). Every test also asserts that no
`securitypolicyviolation` fired. They need neither `web/dist` nor the fake server, so they run under
whatever `tests/e2e/playwright.config.js` U48 provides.

That config is U48's and was not on main when this unit ran, so `./build.sh fake-e2e "editor/*.spec.js"`
stops with "config not found". Two runs passed instead:

- `npx playwright test --config tests/e2e/fake/editor/playwright.config.js`, the committed standalone
  config with the four target projects: 79 passed, 9 skipped (the CDP IME tests outside Chromium).
- `./build.sh fake-e2e "editor/*.spec.js"` with a temporary, uncommitted stand-in for U48's config (same
  four projects): 79 passed, 9 skipped.

Firefox empties the `DataTransfer` of a constructed `ClipboardEvent`, so the paste specs dispatch a plain
`paste` event that carries `clipboardData`. That is a test-harness detail; real pastes are unaffected.

## Follow-ups for other units

- **U48:** `tests/e2e/playwright.config.js` needs the projects chromium, firefox, webkit and mobile-webkit
  (`devices['iPhone 13']`), and must not treat `_*.js` helpers as specs. The editor specs need no `baseURL`
  or `webServer`.
- **U0:** add `test-results/` (Playwright output) to `.gitignore`. Local runs also needed
  `npx playwright install chromium firefox webkit`: the cached Chromium was the wrong build for 1.64.1.
- **U10 (`kit.css`):** style `.rs-editor-input` (focus ring, min/max height, scroll), the placeholder
  (`.rs-editor-input[data-empty]::before { content: attr(data-placeholder) }`), `.rs-editor-mentions`
  (absolute, under the caret; `[aria-selected=true]` highlight), `.rs-editor-link`, `.mention` pills and
  read-only `.island` blocks.
- **U34/U33:** import the editor lazily (`import('../markup/editor.js')`) so it lands in its own `editor`
  chunk, as §g.7 budgets it.
