# U35 decisions: retro stages, timer, focus, settings and share

U35 owns `web/src/retro/{stages,readiness,timer,focus,config,share}.js` and `tests/e2e/fake/retro-stages/**`.
Each module exports one board feature (`stagesFeature`, `focusFeature`, `timerFeature`, `configFeature`,
`shareFeature`) in the shape of U34 decision 4.

## Edits outside the owned paths

1. **`web/src/retro/index.js` (U34)**: five imports and five `FEATURES` entries, as U34 decision 4 asks of U35.
   U36 adds its own entries to the same array, so expect a trivial merge there.
2. **`web/styles/retro.css` (U34)**: a U35 section is appended, and the column palette selectors also match
   `.retro-focus[data-color]` so the banner takes its column's colours. U35 owns no stylesheet, and the CSP
   refuses style attributes, so the styles cannot live in the modules. Both edits are in one commit
   (`feat(retro): mount the stage, focus, timer, share and settings features`) for the integrator to review.

## Decisions where the spec was silent or did not fit

1. **Readiness counts present people only.** The count is `ready ∩ presence` over the people present, and marks
   for another stage than the current one count as nobody (`readinessOf`). "Mark ready" is offered to people who
   may pace the board (`RetroRoles.MayPace`: everyone on a quick board, members on a team board) while they are
   present. It is hidden on a closed or archived board.
2. **Stage moves wait one round trip** (§g.4). The advance button is disabled only when readiness is enforced and
   someone present is not ready, which is the server's rule. The original disabled it whenever anyone was not
   ready. That rule is not kept, because without enforcement the stage pills jump anywhere anyway. With
   enforcement the pills are display only, and Reset, Restart and Reopen stay available (`StageRules`). A `stale`
   nack (another facilitator moved first) is toasted with the stage now shown. Other people's moves are announced
   in the polite live region rather than toasted.
3. **The timer is for facilitators.** `RetroDecider.RunTimer` checks `IsFacilitator`: signed in, and a member on
   team boards. §c.4 says "signed-in", so the page follows the decider. Guests see "Sign in to use the timer"
   (parity). Timer commands wait one round trip and carry `from: timer.state`. A `stale` nack is toasted.
4. **Clock.** The display is `endsAt − ctx.now()`, where `ctx.now()` is `socket.clock.serverNow()`. The display
   element carries `data-deadline` (the local-clock instant of `endsAt`), which the skew specs read. **Wake
   detection:** while a timer runs, each tick compares the wall-clock delta with the `performance.now()` delta.
   On a step of more than 1 s the timer dispatches `online` on `window`. That runs the socket's own wake path:
   `clock.checkStep()` drops the samples and a ping goes out. The socket exposes no resample call, and
   `net/socket.js` is not U35's.
5. **Alarm.** It rings when this page saw the remaining time go from above zero to zero or below while running.
   It also rings when `state.expiredAt` changes (U34 decision 3) and the server time is within 5 s of it. It rings
   at most once per `endsAt` (a set of rung end times), and only when the timer's `alarm` flag is on. "Time is up"
   is also announced in the assertive live region, so the end is noticed even with audio locked or muted.
6. **Music is generated.** No licensed track exists (U37: `music.mp3` absent). The music is a 32-step arpeggio
   of 250 ms steps, generated with WebAudio. Notes are scheduled 1.5 s ahead from the position
   `durationMs − remainingMs`. A jump (pause, resume, a clock correction) restarts the schedule. So every tab
   plays the same step, and a resume carries on from where the timer is. `data-music-position` on `.retro-timer`
   shows the position while music plays.
7. **Audio unlocks on the first pointer or key event** (capture listeners on `document`). Until then the sound
   button shows a warning icon. Volume and mute are per browser: `localStorage['rs.timer.volume']` and
   `['rs.timer.muted']`. Volume is a menu of four levels, not a range input, and the duration fields are text
   inputs with `inputmode=numeric`. Both avoid form controls whose WebKit shadow trees may trip the CSP
   (U34 decision 2).
   **Superseded by UX15:** volume is now a level slider (`rs.timer.level`), a native range that was tested
   against the CSP in WebKit.
8. **Focus banner.** It shows only while focusing is allowed: discussing, or stages off, and not archived. Its
   previous and next buttons step through the column in the viewer's own sort. That sort lives inside
   `column.js` (U34 decision 9), so the banner reads the column's card order from the DOM, and falls back to
   the default sort. The banner lists the card's comments read-only. Its thread button triggers the board's
   `comments` action, so no second composer is opened on the same draft key. Focus is optimistic. A `stale`
   nack is dropped silently (`room.js`), and the confirmed focus shows again.
9. **Settings dialog.** It sends only the fields that changed, each with the value the dialog saw (`maxVotes: 0`
   means unlimited). It stays open, busy, until the change lands. A `stale` nack never reaches the page
   (`STALE['retro.config.update'] = 'silent'`), so the dialog infers the outcome from the config it observes:
   - The config shows the patched values: the save landed and the dialog closes.
   - A patched field moved to some other value: the server refuses, so the dialog shows the fresh value, names
     the field, and keeps the facilitator's other edits.
   - Neither within 8 s: the dialog shows the latest values and says nothing was saved.

   While the dialog is open, untouched fields follow other people's changes.
10. **Share.** The link and a copy button are for everyone. If the clipboard is refused, the field is selected
    and the button says "Press Ctrl+C". Who may open the board is offered to people who may manage it
    (BoardManage). On a team board that is the admins and the owner, from `members[].role`. A quick board does
    not tell the page who created it, so every signed-in user is offered the controls, and a 403 is explained
    ("Only the board's creator or a team admin…"). The choices are radios, with no `<select>`. "Team members
    only" is offered on team boards only. A password is 4 to 72 characters, as in U30's create-board dialog,
    and is checked in script (`noValidate`). The server keeps only a bcrypt hash, so the password is shown once,
    with a copy button, right after it is set. Leaving the field blank on a password board keeps the current
    password.

## Size

The retro chunk grew from 20,629 to 27,827 bytes brotli (budget 32,768). U36 shares the remaining room. If it
needs more, the settings and share dialogs could become lazy chunks behind tiny toolbar stubs. That needs new
file paths outside U35's.

## Verification

- `./build.sh fake-e2e "retro-stages/*.spec.js"`: 112 passed (28 tests × chromium, firefox, webkit and
  mobile-webkit), 0 failed. The specs cover:
  - stage compare-and-set with two facilitators in two browser contexts;
  - readiness counting present people only;
  - timer agreement within 100 ms between tabs whose clocks are +30 s and −30 s off, with server skew;
  - the wake-detection resample;
  - the alarm once per `endsAt`, whether the tab or the server sees the end first;
  - the music offset after a resume;
  - focus from the snapshot for a late joiner;
  - the settings `stale` refresh;
  - the password share flow, ending with a second person unlocking the board.
- `./build.sh fake-e2e "retro-board/*.spec.js"` (U34's specs, after the `index.js` and CSS changes): the only
  failure is `cards.spec.js` "the boot snapshot paints the board before the socket answers". It fails the same
  way on a clean checkout of `main`: the entry's shared socket sends its own `hello` with no subs, and the spec
  reads the first hello. UF11 wires the shared socket into the retro mount.
- `./build.sh test`: exit 0. .NET 2,892 of 2,892 passed; the simulation passed 2,000 of 2,000 seeds; web unit
  tests 337 of 337 passed; golden vectors passed.
- Checked by eye on the demo (port 5207): every stage board in light and dark, the iPhone width, and the
  settings and share dialogs.

## Follow-ups

- **U28:** expose a `resync()` on the socket (drop the clock samples, ping) so the timer need not dispatch
  `online`.
- **U25:** a per-viewer `canManage` (in the board overlay or the by-code answer) would let quick boards show the
  share controls only to their creator.
- **UP1 (demo):** `retro.config.update` with `maxVotes: 0` should store unlimited (null). Its stale check should
  also compare `expected.maxVotes` (0) against an unlimited config. Today the demo stores 0, and treats an
  unlimited board as stale.
- **UF11 / integrator:** resolve the `FEATURES` merge in `retro/index.js` with U36's entries. When the shared
  socket reaches `mount()`, re-run `retro-board/cards.spec.js`.

## Amendment (UF14)

- **Decision 4:** on a wall-clock step the timer calls `ctx.socket.resync()` (drop the clock samples, ping)
  instead of dispatching `online` (UF14 contract 2). The U28 follow-up is done.
- **Decision 9:** the settings dialog no longer sends an update it knows will be refused (not a facilitator, an
  archived board, invalid values, a field someone else changed since the dialog read it); it shows the reason
  instead (UF14 decision 7).
- `focus.js` escapes ids with `CSS.escape`.
