# UF10: auth edge cases (from wave 4)

UF10 owns `src/Retroscope.Server/Auth/**`, `src/Retroscope.Server/Endpoints/{AuthEndpoints,MeEndpoints,OidcEndpoints}.cs`, `src/Retroscope.Server/Data/Repos/{Users,Sessions}Repo.cs`, their tests under `tests/Retroscope.Integration.Tests/{AuthCore,Email,Oidc}/**`, and `docs/decisions/{U16,U17,U18}.md` (append-only).

1. `MagicConsumeAsync` skips the account claim when the caller is already that principal.
2. Reset consume refuses disabled accounts.
3. Move the `external_identities` unlink into the `UsersRepo.Claim` transaction.
4. Move `SignupSql` into `UsersRepo`, so signup and `CreateAsync` share one column list.
5. Keep `OperationCanceledException` out of the `RecheckAccessAsync`-style catch-alls in auth code.
6. Map `POST /api/auth/magic/preview` as `docs/decisions/U29.md` expects.
7. Record the exp leeway in `docs/decisions/U18.md`.
8. `PUT /api/me/avatar` uses `SniffedImage.TryCreate` and `BlobsRepo.InsertAvatarAsync` (256 KiB cap), sets `users.avatar_blob_id`, and returns 415 `unsupported_media_type` for refused images, if it does not already.

**Check:** `dotnet test tests/Retroscope.Integration.Tests --filter "Category=AuthCore|Category=Email|Category=Oidc"` and `./build.sh test` green, with a test for each item.
