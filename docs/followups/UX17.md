# UX17 follow-ups: the sprint report

1. **Move the poker browse off the deprecated Agile issue lists.** The current Jira Software OpenAPI spec marks
   `GET /rest/agile/1.0/sprint/{id}/issue` and `GET /rest/agile/1.0/board/{id}/backlog` as deprecated, with
   `GET /rest/software/1.0/sprint/{id}/issue` as the replacement. Community posts give 2026-11-01 as the removal
   date; the official changelog entry was not found, so the date is unverified. The ranked browse
   (`BrowseService.RankedAsync`, through `JiraClient.GetSprintIssuesAsync` and `GetBacklogAsync`) calls both. The
   sprint report does not.
2. **Regenerate the rendered docs.** UX17 changed `docs/DESIGN.md` (§f endpoints and proxy routes, §g.1 layout,
   §g.7 budgets). `docs/DESIGN.html` does not have those changes yet.
3. **Check against a real Jira site.** Whether `search/jql` returns `statuscategorychangedate`, whether the board
   sprint list sends `total` for closed sprints, and whether it lists sprints of other boards.
4. **A real-stack e2e spec** for the report, once a closed sprint can be seeded without leaking into every
   playground board of `tests/Fakes.Host`.
5. **Decide poker's points field.** The sprint report reads points from the board's estimation field unless an admin
   chose one (UX17 decision 12). Poker's browse, points filter and submit still use the stored field. For a team whose
   stored field is not the board's, submitted points may not show on the Jira board. Check with the owner whether
   poker should follow the same rule.
